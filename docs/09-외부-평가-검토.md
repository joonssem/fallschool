# 09. 외부 LLM 평가 검토

- 작성일: 2026-10-01
- 사용자 제공 평가를 현행 코드와 대조했다. 붙여넣기에 누락이 있는 문장은 복원하지 않았다.
- 문서 검토만 수행. 게임 코드 수정·새 시뮬레이션·실기 플레이는 아직 하지 않았다.
- 관련: [전원 참여 모드](08-전원-참여-모드.md)

## 1. 코드로 확인한 지적

| 지적 | 확인 결과 | 대응 방향 |
|---|---|---|
| 새 중력을 체험한 뒤 예측 문에 도착 | `solar.js`: 달 경계 -28/문 -47, 화성 -110/문 -118, 토성 -247/문 -255. 목성은 경계·문 -206이며 구역 판정은 `<`. 외부 평가의 일부 좌표는 현행 코드와 다르지만 세 곳의 순서 문제는 맞음 | 문 이동만 하지 말고 착지·입구 발판·중력 경계·별 거리를 함께 검토. 체험 후 질문은 관찰 문제로 표시하는 방법도 있음 |
| 힌트가 정답을 미리 알려줌 | `choiceGate()`는 질문과 힌트를 상시 표시. 화성 힌트가 대표적 | 첫 화면의 필요 정보와 정답 힌트를 구분하고 오답 후 단계적 힌트 제공 |
| 판막을 혼자 열 가능성 | 발판 중심 간 12m, 각 유효 범위 1.35m, 다인 방 유지 2.5초. 중심 간 이동 개산 12/7≈1.7초라 유지 시간만으로 두 사람을 보장하지 않음. 현재 시험은 다인 방에서 혼자 순서대로 밟는 경우를 검증하지 않음 | 단독 통과를 시험하고, 필수 협동인지 선택 협동인지 먼저 결정. 혼자 통과 가능하다는 것 자체를 무조건 결함으로 보지 않음 |
| 직렬 문에서 마지막 학생이 막힘 | 방 전체가 3명 이상이면 유지 1.5초. 열린 문은 약 4초에 걸쳐 닫힘. 근처 인원은 보지 않음 | 도움 역할·교사 지원·구제 장치를 함께 설계. 실제 회로 조건을 만족하지 않는데 전구를 켜는 구제는 피함 |
| 개념 오답 낙하가 도움 점프에 섞임 | `respawnAtCheckpoint()`는 낙하 원인을 구분하지 않고 셈. `cp.noHelp`는 예외 지정 | 개념 판단 실패와 조작 실패를 구분. 첫 시도 O/X만으로 이해를 평가하지 않음 |
| 산·염기에 계속 넣는 설명이 불완전 | 질문은 계속 넣기, 답과 해설은 산성이 약해짐에서 끝남 | 질문 범위를 '아직 산성인 동안 조금씩 넣기'로 한정하거나 중성 이후 충분히 더 넣으면 염기성이 되는 설명까지 포함 |
| 전구 밝기 비교가 실제 체험과 분리됨 | 현재 장치는 스위치 연결 조건을 보여줌. 전구 직렬·병렬 밝기 비교 장치는 아님 | 스위치 논리 체험과 전구 확장 문제를 구분. 비교 장치를 추가하면 같은 전지·같은 전구 조건 유지 |

## 2. 과학 표현 검토

- 우주 정거장: HUD에 표시되는 중력 ×1은 조작용 설정이라고 명시해야 한다. 실제 미소중력은 중력이 없어 생기는 것이 아니라 우주선과 내용물이 함께 자유낙하하면서 나타난다. [NASA](https://www.nasa.gov/learning-resources/for-kids-and-students/what-is-microgravity-grades-5-8/)
- 화성 폭풍: 학생을 세게 밀어내는 힘은 게임적 과장. 실제로는 대기가 얇아 같은 풍속에서 밀어내는 힘이 작다. '화성의 바람 속도가 약하다'로 일반화하지 않는다. [NASA](https://www.nasa.gov/solar-system/the-fact-and-fiction-of-martian-dust-storms/)
- 목성·토성: 발판 위 걷기는 게임 장치로 설명한다. 목성에는 진짜 지표면이 없다. 중력 수치의 기준 높이는 문구 확정 전 별도 확인한다. [NASA 목성 설명](https://science.nasa.gov/jupiter/jupiter-facts/)
- 소행성대: 안내판은 이미 '게임 중력 0.5배'라고 쓰지만 HUD는 단순히 중력으로 표시한다. 띠 전체에 일정한 지표 중력이 있다는 오해를 피하도록 표시를 통일한다. '작으니 중력이 없다'는 설명은 채택하지 않는다.

## 3. 그대로 채택하지 않을 제안

- 판막의 '심방→심실 스위치 순서'를 강제하는 안: 놀이 장치와 실제 판막 작동을 혼동할 수 있다. 협동 강화를 위해 새로운 오개념을 만들지 않는다.
- 학생별 정답 위치 변경: 다른 화면의 학생이 바닥 없는 곳을 걷는 등 공유 공간의 일관성이 깨질 수 있다. 답 공유는 협동 학습일 수도 있으므로 이유 설명과 새로운 상황 질문으로 이해를 확인한다.
- 모든 힌트 제거: 초보자의 부담이 커진다. 필요한 정보와 정답을 직접 말하는 힌트를 구분해 단계화한다.
- 직렬 스위치에 전지·전구 역할 부여: 위치 이름으로 쓰되 스위치가 전지·전구 자체라고 오해하지 않도록 한다.
- 모든 질문을 예측으로 통일: 예측→체험과 체험→관찰→비교 모두 가능하다. 의도와 질문 이름을 일치시킨다.
- 시소를 '무게와 무관'으로 단정: 동일한 무게를 가정한 위치 합은 무게가 작용하는 위치의 효과를 단순화한 것으로 볼 수 있다. 실제 힘·회전 운동을 계산하는 시뮬레이션은 아니므로 설명 범위를 제한한다.

## 4. 다음 작업 추천 세 가지

1. **과학 문구·지원 기록 정리**: 조작용 중력·화성 바람의 과장·산성 질문의 범위를 명시하고, 개념 오답과 조작 낙하를 분리한다.
2. **협동 구간의 전원 통과 지원**: 직렬 문 마지막 학생 지원을 우선 설계한다. 판막은 단독·늦은 도착·재접속을 시험하고 필수 협동 여부를 결정한다. 전원 참여를 위해 탈락·막힘을 새로 만들지 않는다.
3. **태양계 질문과 체험 순서 개선**: 달·화성·토성 입구를 재설계하고 문 전후 중력·안전 발판·경로를 시험한다. 힌트 단계화와 짧은 설명 질문을 함께 적용한다.

새 맵 추가 전에 위 세 가지를 기존 맵에서 검증하는 것을 추천한다. 교실에서는 대기 시간, 자발적 도움, 오답 후 재고, 다른 상황에 적용하는 설명을 관찰한다. 재미·학습 효과는 코드만으로 단정하지 않는다.

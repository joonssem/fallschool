# 64. 자유 탐험·협력 맵 인터뷰 및 설계 지시서

- 작성일: 2026-10-19
- 근거: 사용자와 진행한 객관식 인터뷰 및 최종 지시서 정리.
- 상태: 인터뷰·추가 조건 확정, 설계안 3개 별도 작성·사용자 선택 대기, 미구현·미등록. 맵 이름과 id 미정.
- 읽는 조건: 이 자유 탐험·협력 맵의 설계안을 제안하거나 선택 이후 구현할 때 읽는다.
- 현재 범위: 8절의 추가 결정을 반영하여 설계안 3개를 제안한다. 사용자가 안을 선택하기 전에는 구현하거나 맵을 등록하지 않는다.

## 1. 인터뷰에서 확정한 조건

| 항목 | 확정 내용 |
|---|---|
| 대상·기기 | 초등학교 5학년 21명, iPad 10세대, 같은 맵에 동시 등장 |
| 운영 | 한 차시 플레이 약 20~25분, 여러 수업에 걸쳐 이어하기. 학생 자율 진행 중심, 교사는 필요할 때 도움 |
| 핵심 재미 | 자유 탐험·발견·점프·협력. 여러 방향으로 이동하고 이전 지역으로 돌아갈 수 있음 |
| 교육 방향 | 탐험과 점프 중심으로 여러 교과를 자연스럽게 연결. 지역 배경과 구체적인 학습 개념은 문서 조사 후 조합 3안을 제안 |
| 첫 제작 규모 | 핵심 지역 3곳과 중앙 산. 서로 다른 환경이 하나의 세계로 연결 |
| 큰 목표 | 중앙 정상 도달. 기본 정상은 점프 실력이 낮은 학생도 탐험과 협력으로 도달하도록 설계 |
| 선택 목표 | 지역 복원과 숨은 발견. 더 높은 첨탑·특별 경로는 어려운 선택 등반 |
| 추락 | 기본 탐험은 가까운 쉼터에서 재시도. 선택 등반은 아래 지형으로 크게 떨어져 상당 구간을 다시 올라가도 됨. 탈락 없음 |
| 협력 필요성 | 일부 주요 구역은 3명 이상이 협력해야 진입. 모든 관문을 혼자 해결할 수 있게 바꾸지 않음 |
| 모둠 구성 | 고정 모둠 없이 현장에서 자유 합류 |
| 협력 방식 | 서로 다른 장소의 역할 수행 중심에 정보 공유 결합. 각자 역할을 수행하면 참여 인정. 정확한 동시 조작은 요구하지 않음 |
| 통과 자격 | 해결에 참여한 학생에게 각각 저장. 이후 혼자 재통과 가능. 처음 온 학생은 직접 협력 해결하며 경험자는 다시 도움 가능 |
| 친구 모집 | 도움 요청을 지도에 표시. 요청자는 주변을 탐험하다 인원이 모이면 복귀. 관문이 잠겨 있어도 다른 활동 가능 |
| 저장 | 개인 쉼터·발견·수집·관문 통과 자격과 반 전체 공동 발견·지역 복원 진행 모두 유지 |

사용자가 참고한 로블록스 경험은 올라가다 떨어지면 다시 오르는 코스와 숫자 바닥을 따라 전진·좌우 이동·점프하는 코스다. 정확한 게임명과 당시 순위는 미확인이다. 특정 게임을 확인했다고 전제하지 말고, 높이 도달의 성취·다음 발판 도전·경로 선택·친구 관찰·실패 후 재도전을 참고한다.

인터뷰에서 확정한 조건은 1절이다. 이후 절의 운영·검증 상세는 그 조건을 구체화하는 설계 요구이며, 아직 선택하지 않은 해결 방법을 사용자 확정 사항으로 표시하지 않는다. 프로젝트 공통 규칙을 바꾸지 않고 이번 맵의 요구를 충족하는 방법부터 검토한다.

## 3. 설계안에 지킬 요구

### 자유 탐험과 교육

- 학생이 탐험 순서와 당장의 목표를 선택하게 한다. 개념을 이해하면 지형·단서·장치를 더 잘 활용하도록 연결한다.
- 여러 교과를 연결하되 지역마다 중심 개념과 관찰 가능한 학습 목표를 좁혀 제안한다. 교과별 문항 수나 설명판 수를 늘리는 것을 교육 내용의 충실함으로 판단하지 않는다. 5학년이 이해할 수 있는 수준과 특정 학년·학기 단원 일치는 구분하며, 단원 일치를 주장하면 별도 근거를 확인한다.
- 퀴즈 정답 문이나 `발판 조작 → 결과판 확인 → 문 열기` 반복으로 교육을 붙이지 않는다. 선택 결과는 공간·물체·이동에서 보이고 다음 행동에 쓰여야 한다.
- 기본 정상과 어려운 선택 등반을 구분한다. 학생 간 밀치기·잡기는 사용하지 않는다.
- 기본 정상의 접근 가능성은 조작 난도에 대한 설계 목표다. 미통과 협력 관문은 혼자 접속했을 때 열리지 않을 수 있다. 혼자 가능한 탐험과 협력 이후 가능한 진입을 이동망에 구분하고, 정상까지 필요한 협력의 범위도 명시한다. 모든 학생의 실제 도달을 검증된 사실로 표현하지 않는다.
- iPad 터치 입력, 점프 중 좌우 조작, 카메라 시야, 작은 화면의 단서 가독성을 고려한다.
- 기본 탐험 실패는 빠르게 수정하게 한다. 선택 등반 추락의 부담은 허용하되 발견·수집·관문 자격은 잃지 않는다.
- 선택 등반의 진입 전에 추락 위험을 알아볼 수 있게 한다. 아래 지형 착지·맵 밖 낙하·수동 복귀·다음 차시 재접속 각각의 위치를 정하고, 기본 쉼터 자동 복귀가 선택 등반의 재등반 경험을 지워 버리지 않는지 검토한다. 재접속으로 높은 도전 위치를 복원할지는 미정이다.
- 정상 도달은 개인 성취로 기록하고, 이후에도 선택 등반·복원·친구 도움을 계속할 수 있는 흐름을 제안한다. 수업 종료는 정상 도달과 별개로 저장 후 중단할 수 있게 설계한다.
- 기존 약 150~250m 길이 기준을 자유 이동·수직 등반에 어떻게 적용할지 검토한다. 전체 범위·주요 동선·반복 등반·복귀 거리를 나누고, 기준에서 벗어나는 제안에는 이유를 밝힌다. 길이 예외가 이미 승인됐다고 간주하지 않는다.

### 실제 협력과 개인 진행

- 협력 완료·개인 자격은 위치 파생 판정이 아니라 공유 경로에 명시적으로 기록하는 방식을 포함한다.
- 3명 이상의 실제 참여가 필요하고 한 학생이 모든 역할을 대신할 수 없게 한다. 단순히 근처에 서 있는 학생에게 자격을 주지 않는다.
- 서로 다른 참여 학생의 역할 수행을 구분한다. 재방문 경험자가 참여해도 각자 역할이 필요하다. 세 번째 참여 이전의 완료 판정, 2인 통과, 미참여자의 뒤따라 진입을 막는 방안을 제안한다. 역할 완료를 얼마나 오래 유지하고 어떤 시점에 함께 참여해야 하는지는 설계안에서 정한다.
- 역할마다 왜 필요한지와 행동들이 하나의 결과로 연결되는 원리를 설명한다. 세 발판에 서 있는 것만으로 협력을 대신하지 않는다.
- 정확한 동시 입력은 요구하지 않는다. 관문이 열릴 때까지 역할 진행을 유지하는 방안을 기본으로 검토하되, 초기화·이탈 처리 방식은 설계안에 명시한다.
- 반 전체 기록과 개인 통과 자격을 구분한다. 먼저 온 학생의 진행 때문에 나중에 온 학생이 관문 해결·복원 참여 기회를 잃지 않게 한다.
- 협력 도중 이탈, 인원 초과, 여러 모둠의 동시 도전, 경험자의 재참여, 재접속을 검토한다.
- 자유 합류는 정확히 3명으로 고정한다는 뜻이 아니다. 4명 이상이 모였을 때의 역할·대기·통과 자격을 설명한다. 21명이 세 지역으로 흩어졌을 때 남은 1~2명의 모집과 경험자의 복귀 동선을 검토하되, 시간 경과에 따른 자동 개방으로 필수 협력을 없애지 않는다.
- 반 전체 복원과 개인별 반복 해결을 함께 보여 줄 때 무엇이 공유되고 무엇이 개인 상태인지 설명한다. 이미 복원된 풍경에서 새 학생이 무엇을 바꾸고 어떤 결과를 확인하는지도 제시한다. 서로 다른 모둠의 장치 조작·충돌 지형이 다른 학생을 떨어뜨리거나 미참여자를 통과시키지 않는지 검토한다.

## 4. 설계안 3개의 산출물

세 안은 외형만 바꾸지 말고 핵심 이동 방식·발견 방식·협력 원리가 달라야 한다. 각 안에서 다음을 설명한다.

1. **세계와 핵심 재미:** 반복해서 즐길 행동 한 문장, 세 지역의 환경과 중앙 산의 관계.
2. **이동망과 목표:** 자유 이동 구역, 협력으로 개방하는 주요 구역, 기본 정상, 선택 등반, 우회·복귀 경로.
3. **교과 연결:** 지역별 5학년 수준 개념과 이를 활용하는 행동. 기존 맵과 중복, 오개념 위험, 현실과 게임 모형의 차이.
4. **구체적인 장면:** 혼자 탐험하는 장면과 3명 이상 협력하는 장면을 각각 `단서 → 선택·역할 수행 → 보이는 변화 → 다음 행동`으로 제시.
5. **의미 있는 선택:** 서로 다른 두 방법이나 경로의 이점과 부담, 결과가 다음 이동에 쓰이는 방식.
6. **장기 도전:** 여러 차시에 걸쳐 생기는 목표, 처음 온 학생과 숙련자가 할 일, 완료 뒤 자발적 활동.
7. **실패·저장·합류:** 판단 실패와 점프 실패를 구분. 낙하·재접속·협력 중 이탈 때 유지·복구되는 상태.
8. **위험과 최소 시험:** 반복 왕복, 대기, 역할 독점, 길 잃기, 터치 부담 중 큰 위험과 이를 확인할 짧은 시험 구간. 현재 기능과 새 기능의 구분.

각 안은 독립된 맵 후보 3개이며, 세 지역을 하나씩 나눠 세 안으로 세지 않는다. 각 후보 안에 세 지역과 중앙 산을 모두 포함하되, 같은 구조의 관문을 세 번 반복하는 안은 차별성이 부족한 것으로 평가한다.

각 안은 전체 설계와 함께 첫 구현 조각(가장 불확실한 행동을 확인할 짧은 구간)을 제시할 수 있다.

마지막에 세 안의 장단점·구현 불확실성을 비교하고 추천안 하나와 이유를 제시한다. 재미·학습 효과는 가설로 표시하고 관찰할 학생 행동과 수정 징후를 적는다. **사용자의 안 선택을 기다린다.**

## 5. 선택 이후 구현·검증 기준

- 가장 불확실한 핵심 행동과 iPad 조작을 짧은 구간에서 먼저 확인하고 전체 맵으로 확장한다.
- 프로젝트의 맵 시험 규칙에 따라 봇이 `run(...)`으로 실제 걸어서 기본 정상 도달, 주요 선택별 결과, 잘못된 선택 후 복귀, 선택 도전 우회, 모든 별 도달을 확인한다.
- 협력은 3명 이상 역할 수행, 1인 대체 방지, 참여자별 자격, 경험자의 재참여, 동시 모둠 간 상태 분리를 검증한다.
- 협력 시험은 세 참여자의 이동·역할 수행으로 개방한 뒤 참여자 화면의 통과·자격 기록을 확인한다. 1인·2인, 미참여자 동행, 4명 이상 합류, 역할 중 이탈·재접속도 확인한다. 단일 클라이언트에 다른 학생 위치만 주입하는 시험은 실제 네트워크 합류·자격 저장 검증과 구분한다.
- 다중 클라이언트 시험 도구를 새로 만드는 일이 범위에 포함된다. 오래된 존재, 탭마다 다른 uid, 규칙 미게시 상태, 새로고침 시 덮어쓰기, 방 정리 후 복원을 시나리오에 포함한다.
- 개인·반 기록 저장, 재접속·중도 이탈을 검증한다. 기본 탐험 경로 시험이 어려운 선택 등반을 강제하지 않는지도 확인한다.
- 저장은 새로고침뿐 아니라 탭 종료 후 다음 차시 재입장, 방 재생성·정리 후 복원, 중복 합류·완료 요청에서도 확인한다. 학생·반의 식별 방법, 저장 완료 표시, 통신 실패 시 복구, 의도적인 새 탐험 시작과 초기화 범위를 설계한다. 기기 변경 시 기록 이전 여부는 별도 미정 사항이다.
- 자유 이동은 여러 방문 순서·이전 구역 복귀와 재접속 쉼터를 검증한다. 선택 등반은 허용된 아래 지형 착지와 재등반, 기본 기록 보존을 확인한다. 정상 도달 후에도 탐험·도움이 계속되는지 확인한다.
- `prototype`에서 `npm test`와 화면 확인을 수행한다. 실제 iPad·21명 동시 접속을 실행하지 못했다면 미확인으로 기록한다.
- 공통 파일을 바꿀 때는 AGENTS.md의 영향 범위 점검을 먼저 수행하고 변경 범위·호환 영향을 기록한다.
- 맵 기준 문서에 현재 동작·변경 이력·발전 방향, docs/19 점검표와 교실 관찰 항목을 기록한다. 새 맵 등록 시 색인과 두 README 맵 표를 함께 갱신하고, 커밋한다면 같은 커밋에 포함한다.
- 자동 시험·코드 확인·교사 보고·실제 학생 관찰을 구분한다. 자동 시험 통과는 규칙·이동 검증이며 재미나 학습 효과의 증거가 아니다.

## 6. 미정·미검증 사항

- 맵 id는 소문자 1~16자. 신규 기능 필요 항목(개인 쉼터, 도움 요청 지도 표시)을 표시한다.
- 지역 배경·교과 개념·학습 목표의 구체적인 문장, 맵 이름·id는 설계안 비교 후 결정한다.
- 관문별 역할·참여 판정·초기화 조건, 모둠 분리 방법, 저장 구조와 재접속 위치는 설계·기술 검토 대상이다.
- 반 전체 복원 기록과 새 학생의 반복 참여를 양립하는 구체적인 방식은 제안이 필요하다.
- 지도 모집·다중 모둠·장기 저장·자유 이동의 전체 실현 가능성은 미검증이다. 일부 기존 코드의 정적 확인 결과는 7절에 기록한다.
- 최초 단독 접속자가 탐험할 수 있는 범위, 미완료 역할의 유지 시간, 4명 이상 참여 처리, 저장 경로·복원 방식, 재접속 시 선택 등반 위치는 설계안에서 제안한다. 정상 경로의 관문 수와 학생 식별에 대한 사용자 결정은 8절을 따른다.
- 문서화만 완료했다. 맵 제작·자동 시험·실제 기기 시험·교실 관찰은 수행하지 않았다.

## 7. 지시서 재검토 (2026-10-19)

검토 범위는 인터뷰 답변, 프로젝트 규칙·교육·관찰 문서 및 아래 코드의 정적 확인이다. 실행 시험이나 전체 구현 감사는 아니다. 아래 사실은 작업 중인 파일을 읽은 시점의 내용이며 구현 단계에서 다시 확인한다.

| 확인한 사실 | 설계에 미치는 영향 | 근거 |
|---|---|---|
| 학생 uid는 `sessionStorage`에 보관된다 | 다음 수업에도 같은 학생으로 식별되는 방식을 별도로 정해야 한다. 현재 방식이 장기 식별을 보장한다고 가정하지 않는다 | `prototype/src/net/backend-firebase.js`의 `makeUid` |
| 방은 생성 시각 기준 6시간이 지나면 새 방 생성 시 정리 대상이 된다 | 장기 기록을 단기 방 데이터에만 의존할 수 없다. 기존 방 정리 정책 전체를 무조건 없애는 해법은 피한다 | `prototype/src/net/room.js`의 `ROOM_TTL`, `cleanupOld` |
| 입장 시 `players/{uid}` 진행 필드를 설정하고 새 경기에서는 진행·시드를 초기화한다 | 이어하기와 새 탐험 시작을 구분하고, 기존 경기 모드의 초기화와 장기 저장을 분리할 필요가 있다 | `Room.enter`, `main.js`의 `onStudentMeta`, `resetRun` |
| Firebase 규칙의 현재 학생 기록은 cp·별 수·짧은 문항 기록 등이며 미정의 필드는 거부된다 | 장기 기록·협력 역할·모집 상태를 기존 경로에 임의로 추가하면 저장된다고 가정할 수 없다. 저장 경로·규칙 변경의 영향 검토가 필요하다 | `firebase/database.rules.json`의 `fallschool/rooms` |
| 기존 체크포인트 선택은 인덱스 증가 방식이고, 혼자 모드 완주 시 입력을 중지한다 | 자유 순서의 쉼터·개인 정상 성취·정상 이후 탐험 흐름을 확인해야 한다 | `prototype/src/main.js`의 `onCheckpoint`, `onFinish` |
| 기존 협력 시험은 위치 주입을 사용하고 일부 장치의 단독 통과를 기대한다 | 새 맵의 필수 3인 협력은 별도 검증이 필요하다. 기존 맵의 선택 협력을 바꾸지 않는다 | `prototype/tests/coop.mjs` |

### 이번 재검토에서 보완한 점

- 확정 조건과 후속 설계 상세의 지위를 구분하고, 필수 협력을 유지하면서 기본 정상의 조작 접근성을 설명했다.
- 정상 이후 활동, 자유 방문 순서, 선택 등반의 추락·재접속 처리를 검토 항목에 추가했다.
- 반 전체 복원과 개인 관문 자격의 충돌, 초과 인원·늦은 합류·다중 모둠의 처리 조건을 구체화했다.
- 장기 저장을 기존 경기 기록과 구분하고, 현재 코드에서 확인한 제약을 근거와 함께 남겼다.
- 교육 개념의 범위를 좁히도록 하고, 설계안 3개 각각이 하나의 완결된 세계 후보임을 명시했다.

### 설계안 단계의 완료 판정

각 후보에서 혼자 첫 접속 → 도움 모집 → 3인 이상 역할 수행 → 개인 자격 획득 → 다음 차시 복귀 → 정상 도달 → 선택 도전·도움 계속하기의 흐름을 추적할 수 있어야 한다. 자유 이동망·교과 목표·저장 및 협력의 미정 해결안과 가장 먼저 시험할 위험이 제시되면 사용자 선택을 요청한다. 실제 제작 가능성·재미·학습 효과를 확인 완료로 표시하지 않는다.

## 8. Claude 검토 이후 추가 결정 (2026-10-19)

1절의 확정 조건은 유지한다. [65. 검토](65-자유탐험협력맵-지시서-검토.md)의 지적 1·2에 대해 사용자가 다음과 같이 결정했다.

| 항목 | 사용자 결정 |
|---|---|
| 정상 경로 | 필수 3인 이상 협력 관문 1개 |
| 마지막 1~2명 | 교사가 필요할 때 수동으로 통과를 도울 수 있음. 시간 경과 자동 개방은 사용하지 않음 |
| 학생 식별 | 교사 발급 이어하기 코드. 6자 안팎, 헷갈리는 글자 제외, 앞 두 글자는 학급 표시 |
| 기기 기억 | 처음 입력한 코드를 localStorage에 기억해 다음부터 자동으로 불러옴. localStorage 자체는 학생 정체성이 아니며 코드 재입력으로 다른 기기에서도 복원 |
| 복원 확인 | 불러올 때 저장된 정상 도달 여부·별 수 요약 표시 |
| 이름 | 실명 저장 안 함. 게임 속 별명 8자 이하만 사용 |
| 보관 | 한 학기 단위의 구체적인 기간·만료 처리는 설계안에서 제안. 교사 일괄 삭제 기능 포함 |
| 반드시 제시할 위험 | 같은 코드의 동시 접속, 코드 추측, Firebase 규칙 변경이 교실 대소동에 미치는 영향 |

이 결정으로 설계안 제안에 필요한 사용자 응답은 갖춰졌다. 설계안은 4절 형식과 함께 지적 3~11의 해결안·첫 구현 조각을 포함하고, 정적 확인·실행 확인·추정을 구분한다. 실제 구현·등록은 선택 전까지 진행하지 않는다.

설계안 비교와 한 학기 보관 정책의 구체적인 제안은 [67. 설계안 비교](67-자유탐험-협력맵-설계안-비교.md)를 참조한다. 아직 안 선택·실행 검증 전이다.

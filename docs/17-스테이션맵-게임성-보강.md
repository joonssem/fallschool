# 17. 스테이션 맵 게임성 보강 (연결 코스 + 매 판 다른 문제)

2026-10-01, Claude. 브랜치 `claude/gameplay`(워크트리 `D:\Projects\fallschool-claude2`), **미커밋**. 대상: 분수 피자, 색과 빛의 미술 공방, 도형 건축 연구소.

## 왜

새 맵은 "발판에 서기"만 하는 스테이션(방)을 이어 붙인 구조였다. 코드에서 확인한 사실: 세 맵이 같은 틀(24칸 방 + 선택 발판 + 문 열림)이고, 방 사이는 이어진 바닥이라 달리기·점프·타이밍이 쓰이지 않았으며, 정답이 매 판 같았다. 교사는 미술 공방이 좋은 반응이었다고 보고했고 같은 반이 다시 하면 지루할 것 같다고 예상했다(재진행 결과는 아님). 이번 변경은 퍼즐은 그대로 두고 (1) 방 사이를 움직임 구간으로 채우고 (2) 판마다 문제를 바꾼다. 재미와 학습 효과는 교실에서만 판단할 수 있다.

## 1. 방 사이 연결 코스 (`src/levels/course.js`, 신규)

- 방과 방 사이 27m를 채운다(`CONNECTOR_LENGTH = 26`, 방 간격 `ROOM_STEP = 59`). 세 종류:
  - **회전 막대**: 넓은 판 위에서 맞아도 밀릴 뿐, 뛰어넘거나 때를 기다린다. 가운데 기둥이 있어 가운데 선으로는 못 간다.
  - **움직이는 발판**: 폭 5m, 좌우 ±2.6m로 오가고 틈은 1.5~2.5m. 떨어질 수 있다.
  - **가로 범퍼**: 사이로 지나가거나 뛰어넘는다. 맞아도 밀릴 뿐이다.
- 연결 코스 입구에 **체크포인트**를 두고 **도움 점프를 허용**한다(`noHelp` 없음). 퍼즐 방 체크포인트는 그대로 `noHelp`(개념 오답 보호). 떨어지면 방 뒤쪽이 아니라 연결 코스 입구로 돌아온다.
- 모든 움직임은 시간 `t`(방에서는 서버 시계)로 계산해 화면 간에 같다.
- 맵별 배치: 분수 피자 막대 → 움직이는 발판, 미술 공방 움직이는 발판 → 범퍼 → 막대, 도형 건축 범퍼 → 움직이는 발판 → 막대. HUD 구간 이름은 "연결 코스".
- 각 맵은 `level.course = { rooms, connectors, tail, goalZ }`를 내보내 시험이 경로를 만든다.

## 2. 매 판 다른 문제 (`src/levels/variants.js`, 신규)

문제는 **시드**로 정한다. 시드는 방의 모든 학생이 같고 새 경기마다 바뀌므로, 같은 판에서는 같은 문제이고 다음 판에서는 다른 문제가 나온다. 퍼즐 상태는 학생별이라 목표를 바꿔도 화면 간 모순이 없다. **학생마다 다른 문제는 만들지 않았다**(같은 방 안의 답 공유는 줄지 않는다).

| 맵 | 바뀌는 것 | 후보 | 조합 수 |
|---|---|---|---|
| 분수 피자 | 주문량 | 주문 1: 1/4·1/2, 주문 2: 1/2·3/4, 주문 3: 3/4·한 판 | 8 |
| 미술 공방 | 목표 색 | 물감 두 방은 서로 다른 두 색 섞기(파랑·초록·빨강 중), 빛 첫 무대는 두 색(노랑·자홍·청록 중), 마지막 빛은 흰색 고정 | 18 |
| 도형 건축 | 전개도 보기·대칭 문제 | 전개도: 정육면체가 되는 5개와 되지 않는 6개 풀에서 방마다 정답 1·오답 2, 두 방이 다른 전개도, 자리 섞임. 대칭: 출발점과 기준선 반사, 오답 둘(한 칸 어긋난 점, 두 기준선을 거친 점 등) | 매우 많음 |

- 제목·목표 견본·HUD 구간 이름이 문제에 맞게 바뀐다(`dynamicSign`). 도형 건축은 전개도 모델을 새 경기마다 다시 만들고 이전 모델을 치운다(장면이 불어나지 않음을 시험).
- 과학·수학 정확성: 전개도의 유효 여부는 기존 `analyzeCubeNet`이 판정한다. 35개 헥소미노 중 11개가 정육면체 전개도라는 독립 기준과 맞는다(기존 시험). 새 후보도 모두 시험으로 유효·무효를 확인했다. 분수 주문량은 8분의 몇 판이며 조각(1/2·1/4·1/8)으로 모두 만들 수 있다. 미술 공방의 색 혼합은 기존과 같은 가상 모형이다(실제 물감과 다를 수 있음).

## 확인하지 못한 것

- **재미와 난이도**: 연결 코스가 실제로 재미있는지, 숙련 학생에게 쉬운지·초보에게 막히는지는 교실에서만 알 수 있다. 시험의 봇은 단순하다(회전 막대는 가운데를 비껴 걷고, 움직이는 발판은 일부 시각에서 한 번 떨어진다).
- **PC 화면**: 분수 피자에서 회전 막대·움직이는 발판 연결 코스를 PC 브라우저로 확인했다(구간 이름 "연결 코스", 장애물 배치, 다음 방 제목에 주문량 표시). 안내판이 카메라에 가까워 화면 가장자리에서 잘려 위치를 두 번 옮겼고(마지막 위치 `x -7.4`, `zA - 6`)는 다시 캡처하지 못했다. 미술 공방·도형 건축의 화면은 확인하지 못했다. iPad 가독성·FPS, 실제 Firebase 21명에서의 움직임 동기화(`t`는 서버 시계 기준)는 미확인.
- **같은 방 안의 답 공유**: 시드가 방 단위라 같은 방 학생끼리는 같은 문제다. 학생별 문제는 `uid`가 필요해 하지 않았다.
- **개념 접근**: 연결 코스는 개념을 담지 않는다(휴식·움직임 구간). 개념이 움직임에 들어가는 변경(문서 14의 방향)은 이번 범위가 아니다.
- **병합**: `pizza.js`, `colorstudio.js`, `geometrylab.js`와 세 테스트, `package.json`을 수정했고 Codex의 새 맵 작업과 겹칠 수 있다. 공통 파일 `kit.js`·`main.js`는 건드리지 않았다.

## 2. 수정 내용

### 우선 작업 1: 과학 표현·힌트·지원 기록
- **태양계 HUD**: `달 · 게임 중력 ×0.33 (실제 ×0.17)`, 소행성대·우주 정거장은 `(조작용)`. 정거장 안내판 추가: 실제로는 중력이 있고 함께 자유낙하해 떠다니며, ×1은 걷기 위한 조작용.
- **소행성대 안내판**: 작은 천체들이 띄엄띄엄 있고 띠 전체의 중력은 없다. 0.5는 조작용.
- **화성 모래 폭풍**: "게임을 위한 과장". 실제는 대기가 얇아 같은 속도의 바람도 미는 힘이 작다고만 쓰고 풍속이 느리다고는 쓰지 않았다.
- **목성·토성**: 실제 값은 구름 꼭대기(딛는 땅 없음) 기준이며 발판은 게임 장치.
- **산과 염기 "섞으면?"**: "아직 산성인 동안 점점 약해져요"로 범위를 한정하고, 해설에 중성→염기성까지 덧붙임.
- **힌트 단계화**: `choiceGate()`의 `wrong`을 배열로 받을 수 있다 (문자열도 그대로 동작). 첫 오답은 생각할 거리, 같은 문을 다시 틀리면 정답 설명. 태양계 4개 문과 산·염기 "섞으면?"에 적용. 문 위 힌트에서는 정답에 가까운 문장을 뺐다. 시도 횟수는 문마다 기록하며 새 경기·진행 초기화 때 0으로 돌아간다.
- **도움 점프**: 예측 문을 틀려 떨어진 낙하는 `stuckFalls`(도움 점프 계산)에 세지 않는다. `falls`와 `gates` 기록은 그대로라 Firebase 필드·규칙 변경 없음.

### 우선 작업 2: 협동 구간
- **직렬 문**: 방이 3명 이상이어도 (가) 아직 문을 지나지 않은 학생(나 포함)이 3명 미만이거나 (나) 문 앞 28m 안에서 30초 넘게 기다렸다면 7초 유지(`LATCH_SOLO`). 세 스위치를 모두 밟아야 전구가 켜지는 조건은 그대로다. 먼저 온 학생은 뒤에 친구가 남아 있어 짧은 유지를 쓰므로 협동이 유지된다. 도움이 켜지면 안내가 나온다. 협동자가 접속을 끊으면 사람 수가 줄어 (가)로 자동 완화된다.
- **현황판과 이름**: 문 위 "이어진 스위치 N / M"(발판 상태. 참여 학생 수가 아님), 스위치 ①②③, 필요 조건 문장. 참여 학생 수는 표시하지 않았다.
- **배선**: 전구 쪽 기둥·가로대, 전구→전지 되돌아오는 선을 추가해 닫힌 고리로 그림 (화면 확인 항목 참고).
- **판막**: 단독 통과 가능을 사실로 확인하고 **선택 협동으로 유지**. 필수로 바꾸지 않았다(구제 장치까지 만들어야 하므로 교실 관찰 후 결정). 완료 메시지·안내판에서 "게임 장치이며 실제 판막은 혈액의 압력 차이로 열린다"고 구분. 심방→심실 순서 요구는 채택하지 않음.
- 전구 직렬·병렬 밝기 비교는 확장 도전 문 그대로이며 스위치 논리 체험과 구분된다. 밝기를 보여 주는 장치는 추가하지 않았다.

### 우선 작업 3: 태양계 질문과 체험 순서
결정: **달·화성·토성은 체험 뒤 관찰·비교 질문, 목성만 진짜 예측.** 이유: 달은 로켓 착지(`z=-31~-47`)가 이미 달 구역이라 문만 앞으로 옮길 수 없고, 화성·토성도 입구 발판·체크포인트·도전 별이 구역 안에 있다. 좌표를 옮기면 별 거리(중력 기준)·착지·안전 발판 전부를 다시 맞춰야 한다. 지형은 건드리지 않았으므로 경로 시험을 다시 하지 않았다.
- 질문 앞에 `[관찰]` `[비교]` `[예측]`을 붙이고, `tests/solar-gates.mjs`가 이름과 문 앞뒤 중력이 맞는지 확인한다.
- 학생별 정답 위치 변경은 적용하지 않았다.

## 4. 남은 불확실성 (코드·시뮬레이션으로 확인할 수 없음)

- **실제 Firebase·iPad**: 학생 화면마다 `until`, 유지 시간, 판막 `activated`가 각자 계산된다. 늦게 도착·재접속 화면의 상태 일치는 모의 위치 입력으로만 시험했다. 실제 지연(위치 0.1~0.3초 늦음)에서 직렬 문 마지막 무리 판정(문 앞뒤 경계 근처)이 깜박이는지 확인 필요.
- 마지막 무리 규칙이 **접속만 하고 움직이지 않는 학생**을 "아직 지나지 않음"으로 센다. 이 경우 30초 기다림으로 해소된다. 30초가 적절한지 교실에서 확인.
- 도움이 켜지면 협동 없이 열 수 있다. 먼저 온 학생이 30초 기다린 뒤 혼자 여는 것이 괜찮은지(협동이 줄어드는지) 관찰.
- 안내판 글자 크기·가독성, 현황판 표시, 닫힌 고리 배선이 실제 iPad 화면에서 읽히는지 (아래 5절).
- 학습 효과: [관찰]/[비교]로 이름을 바꾼 것이 학생의 설명을 늘리는지, 단계별 힌트가 소거를 줄이는지는 교실 시험으로만 판단할 수 있다.

## 5. 화면 확인

헤드리스 Edge로 페이지 로드(체크포인트 시작, 구간 HUD "직렬 스위치 문")까지는 확인했으나, 직렬 문 현황판·배선·새 안내판의 캡처는 얻지 못했다. **글자 크기·가독성·닫힌 고리 배선은 화면으로 확인하지 못했으므로 iPad 실기에서 확인해야 한다.**

### 안내판 글자 폭 점검 (재확인에서 발견·수정)
안내판은 512px 캔버스에 글자를 줄여 넣고(최소 20px) 더는 줄지 않아 넘치면 잘린다. 모든 맵의 안내판 291줄을 Edge(맑은 고딕)로 실측했더니, 새로 쓴 문장 일부(화성·토성 비교 질문, 목성 힌트, 중화 질문)와 기존 물의 순환 응결 질문이 넘쳐 잘렸다. 문장을 줄여 **20px에서도 490px를 넘는 줄은 0개**가 되었다. 단, 실측은 Windows 글꼴 기준이며 iPad(Apple SD Gothic Neo)는 폭이 조금 다를 수 있고, 20~24px로 줄어든 안내판(기존 맵 다수 포함)이 iPad에서 읽히는지는 실기 확인이 필요하다. 기존 문장 중 20~24px로 작게 그려지는 줄은 수정하지 않았다.

## 7. 시작 화면·맵 선택 정리 (맵이 늘어나는 것에 대비)

2026-10-01 점검(Edge 캡처 1024×768, 1024×690)에서 확인한 문제와 수정:

| 문제 | 수정 |
|---|---|
| 제목이 첫 맵 이름("점프 연구소 시험장")으로 고정 | 게임 이름 "점프 연구소"로 변경 (이름은 임시, 바꿔도 됨) |
| 반 참가 화면에 맵 고르기가 섞여 학생이 고른 맵을 하는 줄 오해 | 시작 화면은 방 번호·이름·색·참가만. 맵 고르기는 `혼자 연습하기` 뒤 별도 화면으로 이동 |
| 맵 칩이 줄바꿈되어 맵이 늘면 참가 버튼이 밀림 (690px에서 이미 "조작 방법"이 화면 밖) | 분류 탭 + 카드(이름·한 줄 설명·분류·"함께 하기"), 목록만 스크롤, 연습 시작 버튼 고정 |
| 교사 패널 맵 격자가 출발 버튼·학생 목록을 밀어냄 | 현재 맵 이름 + `바꾸기`로 접어 두고, 펼치면 분류별 목록(최대 높이 36vh 스크롤) |
| 이름 입력칸이 패널 오른쪽으로 삐져나옴 | `width: 100%` |
| 배경 HUD가 비쳐 어수선 | 오버레이를 더 어둡게 + 흐림 |

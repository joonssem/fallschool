# 62. 미끄럼 협곡 탐험대 — 제작 기록

## 현재 동작 요약 (2026-10-19 기준)

- 상태: **사용자 요청으로 보관·활성 목록에서 제외·추가 개발 중단**. 기존 id `slidecanyon`. 사용자 평가는 "재미도 의미도 게임성도 떨어짐", "그냥 이동하면 끝나는 맵"이다. 아래 동작은 보관한 버전의 설명이며 추천·재개 계획이 아니다.
- 코스·이동 모형·시험 구간·자동 시험·계획서를 파일 위치 그대로 남겨 추후 구성요소를 재사용할 수 있게 했다. 활성 목록에서 import와 등록 행만 제거했다.
- 바닥 느끼기 → 두 내리막 → 감속 굽이 → 관성 언덕/완만한 우회 → 전망길의 5구간이다. 기본 길은 점프·다이브·별 없이 완주한다.
- 선택 결과는 캐릭터 속도·정지 위치·언덕 도달 위치에 나타난다. 문 열기나 숨은 정답 속도 판정은 없다.
- 느린 진입으로 언덕을 못 넘어도 같은 플레이어가 옆길로 이동해 시험 결승에 도착한다. 순간이동·자동 속도 주입은 없다.
- 기본 길 실측 약 230.1m, 바깥 갈래 약 240.2~242.9m, 관성 연결길 약 229.4m. 봇이 실제 걸은 거리이며 학생의 플레이 시간·체감 길이와 다르다.
- 체크포인트 7곳, 선택 별 3개(감속 전망대·바깥 굽이·언덕 전망대). 별은 모두 건너뛸 수 있고 관성 길 통과만으로 자동 획득하지 않는다.
- 시드에 따라 굽이와 마지막 길의 감속 표면이 두 배치 중 하나로 바뀐다. 핵심 지형·표면의 규칙은 유지한다. 같은 접근의 속도 차이를 봇으로 확인했으며 새로운 판단의 재미는 교실 확인 전이다.
- 다시 타기는 길 옆의 명시된 선택 발판을 밟으면 가속 전 평지로 돌아오는 방식이다. 실패한 학생은 발판을 사용하지 않고 걸어서 우회 완주할 수 있다.
- 약 6m/s로 실제 이동 후 입력을 놓은 정지 거리: 매끈한 바닥 약 12.84m(첫 버전 11.98m), 거친 바닥 약 0.79m, 기존 보통 바닥 약 0.38m. 게임 모형의 봇 측정이며 실제 재료 값이나 iPad 체감이 아니다.
- 언덕 진입 약 11.66m/s는 통과, 더 일찍 감속한 약 7.19m/s는 미통과 후 옆길 완주를 확인했다. 1/120초·1/60초 간격에서 진입 후 무입력·동일 전진 입력을 각각 비교했다.
- 정지·부활·횡방향 벽 충돌·점프/다이브 후 착지·다른 바닥 복귀 시험을 통과했다. 전체 기존 시험 결과는 아래 검증 기록에 구분한다.
- 정식 게임의 Chrome 맵 카드·연습 시작·출발 화면을 확인했다. 실제 iPad·Firebase 방 동기화·교실 재미와 학습 효과는 미확인이다.

## 1. 실행과 파일

`prototype`에서 HTTP 서버를 열어 `tests/slidecanyon-trial.html`을 연다. 기존 실행 방법은 [README](../prototype/README.md#실행)를 따른다. 평지 비교·굽이·언덕 버튼은 제작 확인을 위한 시작점 선택이며 학생용 제품 화면은 아니다.

활성 등록을 해제했으므로 혼자 연습·교사 맵 목록에는 나타나지 않는다. `/?map=slidecanyon`은 보관 코스를 여는 주소가 아니며 기존 기본 맵으로 처리된다. 전체 코스 소스는 아래 빌더로 보관하고, 표면 이동 시험은 기존 `tests/slidecanyon-trial.html`로 볼 수 있다.

| 파일 | 역할 |
|---|---|
| `prototype/src/slide-motion.js` | 매끈한·거친 표면의 감속·추진·조향 모형 |
| `prototype/src/levels/slidecanyon-trial.js` | 동일 조건 비교 평지, 굽이, 내리막·언덕·안전 우회길 |
| `prototype/tests/slidecanyon-trial.mjs` | 실제 Player와 충돌체를 이용하는 봇 이동 시험 |
| `prototype/tests/slidecanyon-trial.html` | 같은 시험 구간과 기존 Input을 사용하는 독립 미리보기 |
| `prototype/src/levels/slidecanyon.js` | 정식 코스·개인 별·선택 재도전·두 표면 배치 |
| `prototype/tests/slidecanyon.mjs` | 정식 맵 출발~결승, 길이, 실패 복귀, 별·선택 재도전·재시드 시험 |
| `prototype/tests/slidecanyon-freeze.mjs` | 실제 main.js의 simulate 함수를 실행하는 학생 모드 정지·재개 시험 |

시험 명령: `node tests/slidecanyon-trial.mjs`, `node tests/slidecanyon.mjs`, `node tests/slidecanyon-freeze.mjs`. 재사용 시 회귀 확인을 위해 `npm test`에도 남겼다. 보관 뒤 `MAPS`에서 제외되어 공통 규칙의 등록 맵 자동 수집 대상은 아니며, 위 시험이 보관한 빌더를 직접 불러 검증한다.

## 2. 변경 범위와 호환 영향

### 안전한 이유가 되는 사실

`BoxCollider`의 새 `slideSurface` 옵션 기본값은 `null`이다. Player의 새 분기는 **접지 중·normal 상태·해당 표면 옵션 존재**일 때만 실행된다. 기존 맵에서 이 옵션을 사용하지 않음을 확인했다. 전역 `TUNING`, `icy`, 기존 경사 `slippery`의 값과 생성 규칙은 바꾸지 않았다.

별도 지속 상태를 Player에 추가하지 않는다. 접촉한 바닥이 다음 스텝의 표면을 결정하고, 기존 부활 처리가 ground·속도를 초기화한다. 새 바닥을 벗어난 일반 바닥에서는 기존 감속으로 돌아간다.

### 수정한 공통 파일

- `player.js`: 새 표면일 때만 속도 모형 사용. 새 표면과 기존 `slippery`가 동시에 지정되면 경사 외부 이동을 중복 적용하지 않는다. 실제 경사에서 중력·충돌 법선이 속도에 작용한다.
- `physics.js`: `slideSurface` 옵션 전달만 추가. 기존 충돌 계산·충돌체 크기·기본 옵션은 유지한다.
- `package.json`: 기존 시험 명령 끝에 시험 구간 명령 추가. `kit.js`·`variants.js`·네트워크·DB 규칙은 수정하지 않았다.
- 정식 제작에서는 `main.js`의 `simulate`에 새 맵의 `pauseOnFreeze` 옵션을 연결했다. 학생 모드·옵션 사용 맵·교사 frozen 상태일 때 Player 갱신과 플레이어를 사용하는 레벨 진행을 멈춘다. 공유 시각은 계속 갱신해 정지 해제 때 과거 물리를 몰아서 실행하지 않는다. 옵션 없는 기존 맵의 호출 분기는 유지한다.
- `levels/index.js` 끝에 새 항목을 추가해 기존 기본 맵·기존 맵 순서·같은 시드의 난수 사용을 유지한다. 새 맵의 재시드는 자체 두 표면 배치만 바꾼다.

### 실행으로 확인한 호환 범위

변경 직전 Player 복사본과 새 Player를 등록 22항목에서 같은 시드(71)·출발점·240스텝의 이동/점프/다이브 입력으로 비교했다. 매 스텝 위치·속도·접지·상태가 일치했다. 별도로 보통·기존 icy·기존 slippery 경사를 비교했다.

비교 전 기준선을 두 번 실행해 재현성을 확인했다. 변경 전 코드의 가속 값을 일시적으로 바꾸자 비교 결과가 달라지는 것도 확인해 검사가 이동 변경을 볼 수 있음을 확인했다. 비교용 복사본·임시 스크립트는 확인 후 제거한다. 이는 해당 입력 추적의 실행 근거(영향 범위 점검 4단계)이며 모든 가능한 입력과 실기기에서의 동일성을 보장하지 않는다.

### 남은 위험

- 높은 속도에서의 모든 코너·임의 조이스틱 방향·새 표면에서의 모든 점프 조합은 아직 검증하지 않았다. 현재 경계 시험은 최대 속도에 가까운 실제 내리막 진입 뒤 횡방향 이동이다.
- 전진을 유지한 느린 진입은 언덕 꼭대기 가까이 도달한다. 전체 제작 전에 지형과 입력의 성공 범위를 더 넓혀, 작은 조작 오차가 성공을 좌우하지 않는지 확인한다.
- 본체 정지 시험은 공유 시각이 흐르는 학생 모드에서 실제 고속 Player의 위치·속도가 보존되고 해제 후 이동을 잇는지 확인한다. 실제 Firebase 방·네트워크 지연·교사 화면 버튼까지 이어지는 기기 확인은 남아 있다.
- 출발 화면을 가리던 안내판은 옆으로 옮겨 Chrome에서 확인했다. 이동 중 카메라 시야와 강한 감속 구역·벽 접촉의 체감은 실제 조작·iPad에서 추가 확인해야 한다.

## 4. 검증 기록

### Chrome 시험 피드백 반영

사용자가 Chrome에서 시험 후 미끄럼을 조금 더 늘리도록 요청했다. 매끈한 표면의 감속 값만 1.5에서 1.4로 낮춰 약 6m/s 정지 거리를 11.98m에서 12.84m로 약 7% 늘렸다. 거친 바닥과 일반 바닥의 정지 거리는 앞선 측정과 일치한다. 새 수치의 실제 체감은 사용자 재시험 전이다.

초기 조정안 1.2는 정지 거리를 약 15m로 늘렸지만 기존 감속 진입도 언덕을 넘는 등 변화가 커서 최종값으로 채택하지 않았다. 최종 1.4에서는 느린 진입 비교의 역입력 시작을 평지 z=-27에서 -26으로 앞당겼다. 미끄러움 증가에 따른 같은 입력의 결과 변화를 숨기지 않고, 분명히 감속한 진입과 속도 보존 진입을 비교한다. 시험은 최초 오르막 시도와 미끄러져 돌아온 후 재시도를 구분하도록 보완했다.

- `node tests/slidecanyon-trial.mjs`: 통과. 평지 정지, 우회 완주, 감속 굽이, 고속/저속 언덕, 실패 후 복귀, 경계, 부활, 점프·다이브 착지 확인.
- `npm test`: 미끄럼 조정 뒤 새 시험 구간을 포함한 전체 시험 통과(종료 코드 0).
- 정식 등록 뒤 `npm test`: 정식 코스·교사 정지 시험과 모든 기존 시험 통과(종료 코드 0). 이후 추가한 선택 재도전·관성 연결 전체 길이·공유 시각 정지 조건도 각각 대상 시험으로 통과 확인했다.
- Chrome에서 미리보기 로딩·출발 화면·캐릭터 표시 확인. 실제 iPad·교사 보고·교실 관찰은 이번 작업에서 확인하지 않음.

교실에서는 [61의 관찰 질문](61-미끄럼협곡-제작-계획.md#8-교실-관찰-질문)에 따라, 감속 위치를 보고 스스로 바꾸는지와 미끄럼을 통제하기 어렵다고 느끼는 장면을 우선 기록한다.

## 5. 정식 코스와 계획의 차이

- 200m는 초기 목표였다. 실제 측정은 기본 약 230m, 바깥 갈래 약 240~243m로 150~250m 기준 안이다. 선택 전망대를 모두 방문한 동선은 기본 길 측정에 포함하지 않는다.
- 관성 연결은 길이가 약 229.4m라 기본 길과 차이가 작다. 봇 소요는 약 31.7초 대 기본 약 33.4초로, 거리 절감보다 속도를 잇는 이동과 언덕 전망대 접근이 주 이득이다. 학생 기록 경쟁이나 큰 시간 절감으로 홍보하지 않는다.
- 걷는 재도전 고리는 경사 출발점까지 왕복이 길어져, 길 옆의 **명시된 선택 재도전 발판** 두 곳으로 변경했다. 실패 뒤 기본 우회는 걷기로 해결한다. 재도전 발판은 별·기본 완주에 필수가 아니며, 안전 길/전망대에서 실제 접근 거리는 20m 이내다. 별과 진행은 보존하고 속도만 기존 부활 처리로 초기화한다.
- 새 맵의 교사 정지에만 물리 중단을 적용했다. 모든 기존 맵의 정지 동작을 일괄 바꾸는 작업은 이번 범위에 넣지 않았다.
- 사용자에게 시험 완료·정식 제작 요청을 받아 전체 코스를 구현했다. iPad 확인을 완료했다고 해석한 것은 아니며 정식 코스·iPad·실제 방의 검증 항목은 남겨 두었다.

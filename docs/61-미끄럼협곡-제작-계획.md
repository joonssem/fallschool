## 2. 코스 구성

기본 경로의 실제 보행 거리 목표는 **약 200m, 허용 설계 범위 150~250m**다. 모든 기본 갈래를 시험해 범위와 복귀 부담을 확인한다. 선택 별의 왕복 거리는 별도로 기록한다.

| 구간 | 목표 길이 | 핵심 행동 | 보이는 결과 → 다음 행동 |
|---|---|---|---|
| 1. 바닥을 느끼는 입구 | 30m | 나란한 보통·미끄럼 바닥에서 이동하고 입력을 놓아 본다 | 멈추는 위치가 달라짐 → 앞의 넓은 감속 구역으로 진입 |
| 2. 넓은 내리막 | 40m | 직선 미끄럼 길과 완만한 보통 길 중 선택 | 도착 속도와 위치가 달라짐 → 다음 굽이에 맞는 진입 위치 선택 |
| 3. 굽은 협곡 | 45m | 굽이 전의 거친 안쪽 바닥으로 옮기거나 넓은 바깥 곡선을 따른다 | 안쪽은 방향 전환이 쉽고 바깥쪽은 이동이 계속됨 → 합류 후 다음 길 준비 |
| 4. 관성 언덕 | 45m | 짧은 관성 연결길 또는 넓은 완만한 기본 길 선택 | 연결길의 진입 속도가 오르막 도달 위치에 쓰임 → 부족하면 아래 기본 길로 합류 |
| 5. 마지막 전망길 | 40m | 앞서 익힌 감속·곡선·직선 중 자기 경로 선택 | 고른 길로 전망 광장에 도착, 선택 경로 표식으로 자기 해결을 확인 |

길이 합 200m는 설계 배분이다. 메시 배치나 waypoint 합을 실제 보행 거리로 보고하지 않는다.

### 선택의 이득과 대가

- 미끄럼 직선: 진행을 이어가기 좋지만 뒤늦은 방향 수정이 어렵다.
- 거친 안쪽길: 감속으로 굽이를 쉽게 돌지만 이동 속도가 줄어든다. 올바른 감속 판단이 가장 조작하기 쉬운 길로 이어진다.
- 넓은 바깥길: 감속을 놓쳐도 완주하지만 동선이 길어진다. 실패 판정이나 강제 재출발을 주지 않는다.
- 관성 연결길: 속도를 보존하면 짧은 언덕길을 이용한다. 속도를 잃으면 안전한 아래길로 연결되며, 기본 완주에 재도전이 필요하지 않다.

관성 연결길은 **선택 지름길**이다. 넓은 기본 길은 속도 준비 없이 걸어서 오른다. 별 전망대는 지름길 위의 별도 옆길에 두어, 지름길을 이용해도 별을 자동 획득하지 않게 한다.

관성 언덕이 시험 구간에서 성립하지 않으면 해당 구간을 구현 완료로 표시하지 않는다. 장거리 도약·자동 발사로 대체해 다른 핵심 행동을 만들기보다 이동 규칙을 먼저 보완하고 계획과 결과를 기록한다.

## 3. 조작·가독성·안전

- 기존 이동 입력을 기본으로 사용한다. 새 브레이크 버튼, 다이브 타이밍, 필수 점프를 추가하지 않는다. 기본 코스는 점프·다이브 없이 완주 가능하게 한다.
- 바닥은 색뿐 아니라 매끈한 반사 무늬·굵은 홈 무늬로 구분한다. 홈 무늬는 충돌 없는 자식 장식으로 만들어 턱을 늘리지 않는다.
- 진입 전에 굽이와 감속 바닥이 보이게 한다. 위험을 화면 밖에 숨기거나 속도 숫자로 정답을 안내하지 않는다. 이동 흔적은 상태 피드백이며 실제 물리 측정 도구가 아니다.
- 기본 길은 폭 6m 이상을 초기 목표로 하고 굽이와 합류는 더 넓게 잡는다. 실제 폭은 iPad 이동 확인으로 조정한다.
- 바깥 경계는 캐릭터가 멈추거나 길 안쪽으로 진행할 수 있는 고정 벽으로 만든다. 벽에 닿았다고 반대쪽으로 강하게 튕기거나 넘어지게 하지 않는다.
- 체크포인트는 각 구간 전의 평평한 보통 바닥에 둔다. 경사·미끄럼·가속 효과와 분리한다. 복귀 직후 입력 없이 2초 서 있을 수 있어야 한다.
- 감속을 놓쳐도 앞쪽 안전 합류로 간다. 반복 낙하·긴 역주행·20m 이상 강제 왕복으로 비용을 만들지 않는다.
- 정지한 학생을 강제로 계속 미는 구간은 짧게 제한하고, 가까운 보통 바닥으로 벗어날 수 있게 한다. 교사 일시정지 뒤에도 임의 이동이 생기지 않아야 한다.

### 이동을 끊지 않는 체크포인트와 복귀

- 체크포인트는 구간 옆의 평평한 합류 공간에서 활성화한다. 기본 경로가 그 공간을 지나되 관성 내리막과 다음 언덕 사이에는 정지 구역·체크포인트·필수 안내를 두지 않는다.
- 관성 길 도전 시작점은 **가속 내리막 전**이다. 부활 시 속도를 주입하지 않고 여기서 기존 이동 입력으로 다시 출발할 수 있게 한다. 보통 길로 먼저 진행하는 선택도 가능하다.
- 별을 놓친 학생은 선택 재도전 고리로 시작점까지 돌아간다. 고리는 점프 없이 역경사를 걸어 갈 수 있는 보통 바닥이고, 강제 속도 구간과 교차하지 않는다. 고리의 실제 왕복 길이는 목표 20m 이내로 측정한다. 만들 수 없으면 별 위치·고도·진입 길이를 줄인다.
- 단순히 checkpoint 좌표만 더하는 것으로 복귀를 해결했다고 보지 않는다. 실제 부활→재출발→선택 길 진입까지 걸어서 확인한다.

## 4. 선택 도전과 재체험

선택 별은 우선 **3개**로 설계한다. 모든 별을 건너뛰어도 결승에 도착한다.

| 별 | 추가 행동 | 복구 |
|---|---|---|
| 감속 전망대 | 거친 바닥을 이용해 넓은 옆 전망대에 멈춤 | 지나치면 기본 길 합류, 가까운 재도전 고리 이용 |
| 바깥 곡선 | 넓은 곡선의 바깥 탐험길을 선택 | 평평한 합류길로 귀환 |
| 관성 언덕 | 속도를 이어가 높은 옆 전망대 도달 | 아래 안전 길 합류, 도전 시작점으로 짧게 복귀 가능 |

첫 체험은 바닥을 읽는 적응이 중심이다. 재체험은 안쪽 감속길·바깥 곡선·선택 전망대 중 다른 이동 방법을 고르는 데 둔다. 시간 단축은 개인 선택이며 기본 목표가 아니다.

시드는 굽이 방향·거친 바닥의 위치·관성 연결길의 진입 배치를 안전한 검증된 조합 안에서 바꾸는 데 쓴다. 단순 좌우 반전만으로 새 판단이 생겼다고 주장하지 않는다. 각 변형에서 미리 보이는 단서를 읽어 경로를 선택할 수 있어야 한다. 표면별 규칙 자체는 시드로 뒤집지 않는다.

첫 버전은 자유 난수 지형 대신 최소 두 개의 고정 설계 배치를 검증한다. 한 배치는 굽이 전 감속이 짧은 안쪽길에 유리하고, 다른 배치는 긴 직선 뒤 관성 연결을 이용하기 위해 거친 바닥을 피하는 선택에 이점이 있게 한다. 두 배치 모두 완만한 기본 길을 유지한다. 실제 판단이 달라지지 않으면 시드 다양성은 미달로 기록하고 첫 체험용으로 범위를 명시한다.

## 5. 현재 코드에서 확인한 범위와 공통 변경 후보

2026-10-19 정적 코드 확인 기준:

- `prototype/src/player.js`: `ground.icy`는 입력 시 가속과 입력을 놓았을 때 감속을 줄인다. 기존 보통 바닥보다 빨리 달리게 하는 장치가 아니다.
- 같은 파일의 `ground.slippery`는 접촉면 법선에 따른 수평 이동을 더한다. 이 추가 이동과 속도 상태를 동일한 관성으로 취급할 수 없다.
- 수평 제어는 목표 속도 쪽으로 현재 속도를 바꾸므로 내리막에서 얻은 속도가 다음 바닥·오르막으로 보존된다고 단정할 수 없다. 관성 언덕은 별도 구현·실행 확인 대상이다.

공통 변경은 새 맵에서 명시적으로 사용하는 표면 옵션에 한정하는 방향을 검토한다. `TUNING`의 전역 기본값이나 기존 `icy`·`slippery` 의미를 바꾸어 다른 맵에 영향을 주지 않는다. 실제 인터페이스는 시험 구간 구현 전에 정한다.

### 새 표면 이동의 필수 조건

- 미끄러운 **평지 자체가 추진력을 만들지는 않는다**. 내리막에서 중력의 경사 방향 효과로 속도를 얻고, 평지에서는 속도를 덜 잃으며, 오르막에서는 속도를 잃는 단순 모형으로 한다. `windAt`의 강제 이동이나 `onStand`에서 속도를 반복 주입하는 방식은 사용하지 않는다.
- 이동 입력은 추진·조향을 돕되 현재처럼 매번 목표 속도로 끌어당겨 관성을 즉시 지우지 않게 한다. 반대로 모든 바닥에서 조향을 어렵게 만드는 변경도 피한다. 거친 바닥은 작은 방향 전환과 정지를 돕는 구역이다.
- **표면 경계에서는 감속하고, 강제 초기화는 부활·맵 교체·라운드 재시작에서 한다.** 새 표면에서 보통 바닥으로 나올 때 속도가 한 프레임에 사라지지 않게 한다. 관성 구간 중간에는 짧은 보통 바닥 이음새를 끼우지 않는다.
- 이전 맵의 옵션 없는 바닥 및 기존 `icy`·`slippery` 동작은 그대로 유지한다. 새 이동 상태를 플레이어에 추가하면 새 맵의 표면 이탈, 점프·착지, 부활, 맵 교체 시 수명을 명확히 한다. 새 맵 이탈 뒤 남은 효과가 다른 맵에 적용되지 않아야 한다.
- 기본 길의 굽이·감속 구역은 구현 때 정할 최대 설계 속도로 진입해도 안전하게 통과하게 만든다. 속도 상한은 충돌 안정성과 iPad 조작으로 정하는 게임 값이며 과학 상수로 표시하지 않는다. 상한에서 얇은 벽을 관통하거나 코너에 끼면 전체 코스로 확장하지 않는다.
- 같은 높이·같은 내리막·같은 초기 이동으로 표면 차이를 비교할 수 있는 입구를 만든다. 미끄럼 길은 가파르고 거친 길은 완만한 배치만으로 마찰의 효과를 설명하지 않는다. 바닥뿐 아니라 신발과의 접촉 조건을 고정한 게임 모형이라고 짧게 안내한다.

변경 후보는 `player.js`의 표면 이동 처리, `physics.js`의 표면 정보 전달, `levels/kit.js`의 생성 옵션이다. 필요한 파일만 바꾸고, 각 변경 전 [영향 범위 점검](../.claude/skills/blast-radius/SKILL.md)을 적용한다. 이번 계획 작성에서는 공통 파일을 수정하지 않았다.

표면 상태는 개인 플레이어에 적용하고, 다른 학생과의 물리 충돌·공유 가속 조작은 추가하지 않는다. 맵 등록 후보 id는 `slidecanyon`이며 현재 미등록이다. 등록할 때 두 README의 맵 표와 [55 색인](55-맵-문서-색인.md)을 같은 변경에 포함한다.

## 7. 구현 순서와 완료 기준

1. **짧은 시험 구간:** 직선 미끄럼 바닥·거친 바닥·넓은 굽이·안전 합류를 먼저 만든다. 전진·정지·역방향·횡방향 입력과 바닥 경계를 실제 플레이어로 확인한다. 얼음 위 체류만으로 안내가 반복되지 않게 한다.
2. **관성 확인:** 속도를 유지한 진입과 감속한 진입의 다음 구간 도달 결과를 비교한다. 버튼을 누른 횟수나 임의 속도 문턱으로 길을 여는 방식으로 대신하지 않는다. 공통 변경의 기존 맵 호환 영향을 기록한다.
3. **전체 코스:** 기본 갈래·별·체크포인트를 추가한다. 실제 보행 거리와 놓친 굽이 뒤 복귀 거리를 측정한다.
4. **등록·기록:** `index.js`, 루트·prototype README 맵 표, 55 색인, 제작 기록을 함께 갱신한다. 계획과 구현의 차이를 제작 기록 머리말에 적는다.
5. **봇·전체 시험:** 맵 파일을 불러 실제 `run(...)`으로 기본 길 출발~결승, 각 갈래의 다른 결과, 감속 실패 뒤 복귀, 별 3개 도달과 건너뛰기를 확인한다. 같은 초기 속도·입력에서 표면별 차이와 관성 연결을 비교하고 여러 시드를 확인한다. `prototype`에서 `npm test`를 실행한다.
6. **화면·기기 확인:** iPad에서 바닥 경계·방향 전환·카메라 진행 방향·정지 부담을 확인한다. 실제 방에서 교사 일시정지·재시작과 개인 상태를 확인한다. 자동 시험 완료와 기기·교실 확인을 따로 기록한다.

### 시험 구간에서 전체 제작으로 넘어갈 조건

| 확인할 장면 | 규칙·이동 판정 | 실패할 때 조치 |
|---|---|---|
| 표면 비교 | 같은 초기 조건에서 미끄럼 평지의 정지 거리가 보통 바닥보다 길고, 평지에 정지해 있으면 저절로 가속하지 않음 | 표면 모형 수정 |
| 감속과 조향 | 같은 굽이에서 미리 감속한 경로는 적은 방향 수정으로 안쪽길 통과. 놓친 경로도 벽 끼임 없이 바깥길로 완주 | 속도·굴곡·감속 바닥 길이 조정 |
| 관성 연결 | 도전 시작점부터 실제로 걸어 얻은 높은 진입 속도와 낮은 진입 속도를 비교. 무입력 비교와 동일 전진 입력 비교를 각각 수행하며, 기존 속도가 다음 도달 위치에 영향을 줌 | 기본 이동으로 누구나 같은 결과가 되면 언덕·추진 규칙 재설계 |
| 관성 성공·실패 | 준비한 진입으로 짧은 길을 넘어가고, 속도를 잃은 진입은 안전 아래길로 합류. 둘 다 점프 없이 결승 연결 | 오르막에서 멈춰 고립되면 기본 길과 합류 구조 수정 |
| 부활·재도전 | 모든 부활 위치에서 2초 정지 후 기본 길 출발 가능. 관성 도전은 가속 전부터 재출발 가능, 별 복귀 고리 실제 길이 기록 | 체크포인트·도전 시작점 이동 |

규칙·이동 판정 통과 뒤에도 iPad에서 통제감이 확인되지 않으면 전체 코스의 폭·속도를 확정하지 않는다. 점프·다이브는 기본 완주 조건에서 제외하지만 사용 가능한 기존 입력이므로 해당 입력으로 상태가 깨지지 않는지는 확인한다.

## 8. 교실 관찰 질문

- 학생이 굽이에서 지나친 뒤, 다음 시도에 감속 바닥을 더 일찍 선택하는가?
- 바깥길을 스스로 고르는가, 안내를 못 읽어 밀려간 것으로 느끼는가?
- 입력을 놓거나 반대로 움직였을 때 예상대로 멈출 수 있는가? 조작을 포기한 학생은 어디에서 멈추는가?
- 친구가 정답 위치만 알려 주는가, 이동 모습을 보여 주며 이유를 설명하는가?
- 별을 생략하고도 완주하는가? 다른 경로·별에 자발적으로 다시 도전하는가?
- 끝난 뒤 다시 해 보고 싶은 구간과 불편했던 구간을 각각 묻는다. 빠른 완주·적은 낙하만으로 재미를 판정하지 않는다.

학년별 성취기준은 아직 선정하지 않았다. 제작 중 교육 자료와 수업 계획을 대조하기 전에는 특정 학년·단원에 맞는다고 표시하지 않는다.

## 2. 세 안에 공통으로 적용할 제안

### 2.1 사용자 결정과 자유 이동

- 핵심 지역 3곳과 중앙 산. 시작 본부와 세 지역의 바깥 탐험길은 처음부터 서로 연결한다. 모든 지역을 차례대로 방문해야 하는 체크리스트는 없다.
- 정상 경로의 필수 협력 관문은 **논리적으로 1개**다. 지역의 추가 협력 구역은 정상 도달에 요구하지 않는다. 미해결 학생은 관문 앞까지 혼자 탐험하며 친구를 모집할 수 있다.
- 정상 관문에서 참여 자격을 얻으면 이후 혼자 통과한다. 기존 자격이 없는 학생이 따라 점프해 통과하지 못하도록 진입면·다른 접근로까지 검사한다. 교사의 수동 도움은 예외 자격으로 기록하고 3인 공동 성공·복원 기여로 세지 않는다.
- 별은 안마다 총 **6개 제안**: 지역별 1개, 중앙 산 선택 등반 3개. 발견 도감은 별과 별도이며 모든 별·복원은 기본 정상 조건에서 제외한다.
- 한 차시 안에 완주할 것을 요구하지 않는다. 처음에는 지역·쉼터 발견, 이후 정상 관문·새 경로, 그다음 고난도 등반·다른 역할·복원을 목표로 스스로 선택한다. 특정 차시 수는 보장하지 않는다.

**코드 위험과 제안:** 학급 표시가 알려지면 무작위 부분은 4자뿐이다. 짧은 코드는 비밀번호 수준의 보호를 제공하지 않는다. 유효 코드 전체 목록·해시 목록을 클라이언트나 공개 DB에 내려주지 않는다. 코드 검증은 새 서버 기능으로 처리하고, 실패 빈도 제한·수업 중 교사 개방·코드 재발급을 결합한다. 단순 프런트엔드 횟수 제한이나 짧은 코드의 해시만으로 추측을 막았다고 말하지 않는다. 구체적 시도 제한은 학교 공용 IP 사용을 고려해 정하고 첫 시험에서 정상 학생까지 막지 않는지 확인한다.

**중복 접속 제안:** 같은 코드로 제어 가능한 세션은 1개. 서버에서 원자적으로 세션 임대를 획득하고 두 번째 접속은 이동·기여 없이 사용 중 안내만 제공한다. 기존 세션을 자동으로 쫓아내지 않고 기기 변경은 교사의 세션 해제·재발급으로 처리한다. 오래된 세션은 하트비트 만료 후 재획득한다. 3인 판정은 탭 uid가 아니라 서로 다른 코드에 연결된 학생 식별자 기준이다. 서로 다른 코드를 한 학생이 알아내 사용하는 문제까지 실제 사람 수로 완전히 증명할 수는 없다.

### 2.3 저장 경계·다른 앱과의 호환

- 제안 경로는 `fallschool/explorations/{worldId}` 아래 학기 메타·개인 기록·반 기여, `fallschool/explorationSessions/{sessionId}` 아래 모집·역할·일시 위치다. 기존 4자리 경기 방과 별개다. 실제 스키마는 선택 후 영향 범위 점검으로 확정한다.
- 기존 클라이언트는 인증 없이 동작한다. 새 코드 교환·중복 접속·교사 권한·만료 삭제를 **공개 DB 쓰기만으로 안전하게 제공할 수 있다고 가정하지 않는다**. 서버 측 코드 검증·권한 있는 기록 처리와 새 맵용 세션 인증이 필요한 안으로 제안한다. 서비스 운영·배포 비용과 가능성은 미검증이며 첫 공통 기술 조각에서 확인한다.
- 원문 코드는 장기 진행 DB의 공개 키로 쓰지 않고 서버 비공개 매핑으로 다룬다. 단기 토큰·교사 관리 권한을 코드와 구분하고, 교사 권한을 현재 페이지 소스의 교사 문자열로 대체하지 않는다. 한 학기 코드와 단기 토큰은 URL·공개 지도·실패 로그에 남기지 않는다.
- 새 경로만 제한적으로 허용하는 규칙을 설계한다. 교실 대소동의 루트 `rooms/`, `presence/`와 기존 `fallschool/rooms/`, `index/` 정책은 그대로 유지하는 것을 목표로 한다. Firebase 프로젝트 전체 인증 설정·규칙 게시에는 교실 대소동 영향이 있을 수 있으며, 경로 이름만 분리했다고 호환을 증명하지 않는다.
- 선택 후 공통 파일 영향 범위 점검, 규칙 에뮬레이터 또는 동등한 권한 시험, 두 앱의 방 생성→참가→진행→결과·강퇴·정리 회귀 확인을 수행한다. 새 규칙이 게시되지 않은 상태에서는 저장 실패를 표시하고 기존 기록을 초기화하지 않는다. 현재는 어느 규칙도 수정·게시하지 않았다.

### 2.4 협력·도움·복원

- 정상 관문은 최대 7개의 동등한 작업 자리에서 같은 논리 자격을 얻는 방식 제안. 작업 자리는 서로 떨어진 작은 공간으로 구성해 모둠별 조작이 다른 모둠의 발밑을 바꾸지 않게 한다. 처음에는 1자리만 만들어 확인하고 필요 수만큼 확장한다.
- 한 시도에 3~6명. 핵심 역할 3개 외 추가 학생은 분리된 관찰·검증·연결 작업을 맡고, 수행 기록이 있어야 자격을 얻는다. 7명 이상이면 다음 작업 자리로 나누거나 다음 시도를 선택한다. 3명만 일하고 나머지가 구경해도 자격을 얻는 방식은 사용하지 않는다.
- 제안 상태는 모집→3인 이상 역할 배정→관찰·상호 전달→조정→공동 결과 확정→개인 자격 저장이다. 위치는 접근 조건의 단서이고 완료·역할·참여자는 공유 기록에 남긴다. 역할 간 정보와 결과를 주고받게 하며 정확한 동시 버튼 입력은 없다.
- 역할 결과는 활동 중 최대 3분 유지하는 것을 시작값으로 제안한다. 오답 조정은 즉시 가능하고, 틀린 판단 때문에 역할 전체를 초기화하지 않는다. 하트비트 10초 미갱신은 해당 역할을 일시 중지하고 30초 재합류 유예 후 빈 역할로 돌리는 출발값이다. 지연·슬립 실측으로 조정하며 실제 단절 감지 시간이라고 주장하지 않는다. 유예 동안 완료 판정은 중지한다.
- 도움 요청은 관문 id·필요 인원·작업 자리만 표시하고 코드는 공개하지 않는다. 모집 중 자리 예약은 없으며, 활동이 시작되면 참여 의사를 확인한다. 요청자는 다른 활동을 계속하다 합류 안내를 받을 수 있다. 관문 입구로 돌아오는 열린 하산길·본부 연결을 두어 경험자의 도움 왕복을 줄인다.
- 반 복원은 완료/미완료 하나로 끝내지 않고 개인별 새 기여를 누적한다. 개인은 미수행 작업 조각을 언제나 완료할 수 있다. 반 풍경은 개인 수가 늘수록 불빛·식생·완성 부품이 추가되는 방식이며 마지막 학생이 만든 조각도 별도로 보인다. 무한 파밍은 막고 같은 작업의 반복 도움은 별도 도움 기록만 갱신한다. 구체적 표시는 각 안의 제안이다.

### 2.5 쉼터·추락·수업 운영

- 지역별 마지막 안전 쉼터를 따로 저장한다. 기본 길에서 맵 밖으로 떨어지면 현재 지역 쉼터, 선택 등반은 아래의 실제 착지 지형에 남아 재등반한다. 전역 최고 인덱스 체크포인트와 높이 −10m 규칙을 그대로 적용하지 않는다.
- 선택 등반의 수동 복귀는 도전 입구로, 탭을 닫고 재접속하면 마지막 **정적 안전 쉼터**로 돌아오는 방식을 제안한다. 공중·움직이는 발판·고난도 첨탑 중간은 저장하지 않는다. 높은 도전 위치를 로그아웃으로 복구하지 않으며 수집한 기록은 유지한다.
- 교사의 수업 열기·일시 정지·닫기는 저장 세션만 제어하고 장기 기록·배치를 초기화하지 않는다. 새 탐험·새 학기는 별도 명시적 동작이다. 정상 도달은 입력을 중지하는 경기 결승이 아니라 기록과 축하 후 계속 움직이는 개인 성취다.
- 첫 성능 확인은 실제 iPad 10세대에서 원격 아바타 20개·세 지역 외형·정상 시야를 함께 두고 한 차시 길이로 진행한다. [03]의 최소 30fps 목표와 프레임 급락·발열·입력 반응·통신 지연을 기록한다. 멀리 있는 이름표·장식·아바타 세부 묘사는 줄이되 같은 세계의 존재·모집 신호를 잃지 않게 한다. 실제 21대 네트워크와 한 기기의 모의 20아바타 시험은 구분한다.

## 3. A안 — 하늘 능선 탐험대 (id 후보 `ridgeworld`)

### 3.1 세계와 핵심 재미

**높은 관찰점에서 다음 착지 장소와 숨은 길을 발견하고, 자기 수준에 맞는 능선을 이어 오른다.** 정밀 물리 장치보다 걷기·점프·주변 바라보기가 중심이다.

지역은 층층 절벽, 숲 수관, 옛 전망 유적이며 중앙은 세 능선이 만나는 산이다. 수평 순환길과 세 높이대의 연결을 만들어 같은 장소도 아래·옆·위에서 다시 발견한다.

### 3.2 이동망과 목표

본부↔세 지역 외곽↔이웃 지역의 낮은 능선이 처음부터 열린다. 어느 지역에서든 중턱 합류점으로 갈 수 있다. 정상의 필수 관문은 **세 시야 다리** 1개. 이후 넓은 계단형 능선으로 기본 정상까지 오른다. 숲 안쪽 전망원은 별도 3인 협력으로 여는 선택 주요 구역이며 정상에는 필요 없다.

전체 최초 탐험을 강제하지 않는 대표 기본 동선은 수평 이동·완만한 상승을 합쳐 약 180~230m 목표다. 모든 선택 능선 누적 길이는 별도다. 고난도 첨탑의 큰 추락은 아래 수관·절벽 선반에 착지하게 한다. 거리·높이·시간은 아직 설계 추정이며 봇 실측 전이다.

### 3.3 교과 연결

| 지역 | 중심 개념·목표 | 실제 행동 |
|---|---|---|
| 층층 절벽 | 수학: 길이 비교. 짧은 거리와 적은 점프가 항상 같은 경로가 아님을 설명 | 같은 목적지의 짧고 좁은 능선과 길고 넓은 길 비교 |
| 숲 수관 | 과학: 빛과 가림. 보이지 않던 장소가 관찰 위치를 바꾸면 보이는 이유 설명 | 나뭇잎 틈·빛든 착지면을 다른 높이에서 찾아 탐색 |
| 전망 유적 | 국어: 위치를 분명하게 전달. 기준물·방향·순서를 넣어 친구에게 경로 안내 | 서로 다른 시야의 학생끼리 보이는 특징 전달 |

공통 개념은 **부분적인 관찰을 연결해 전체 경로를 판단하기**다. 중앙 산에서는 세 관찰점의 정보를 이어 다리를 배치하고 직접 오른다. 빛은 조망 단서로 쓰며 “밝으면 언제나 안전” 같은 과학 법칙으로 만들지 않는다. 지도는 가상 모형이고 국어 설명의 질은 자동 채점하지 않는다.

### 3.4 혼자·협력 장면

- 혼자: 위쪽 틈에 별 모양 깃발 발견 → 넓은 우회 능선 또는 가까운 좁은 선반 선택 → 높이가 바뀌며 가려졌던 동굴 입구가 보임 → 동굴로 하산해 다른 지역으로 연결. 별 없이 넓은 길로 정상 가능.
- 협력: 관찰자가 가까운 발판의 모양을 확인 → 연결자가 그에 맞는 첫 다리를 배치 → 시험자가 실제 건너 다음 가려진 착지면을 확인하고 결과를 전달 → 연결자가 두 번째 연결을 조정 → 세 학생이 확인한 연속 경로가 실제 중앙 진입로가 됨. 관찰자는 새 연결 후 바뀐 시야를 다시 확인해야 하므로 먼저 누르고 떠나는 역할이 아님.
- 잘못 연결하면 안전 선반에서 “끊긴 연결”이 보이고 즉시 다른 끝점을 고를 수 있다. 이동 담당이 떨어져도 쉼터는 작업 자리 안이다. 경로가 맞고 세 역할의 상호 확인이 기록되면 참가자별 자격 저장. 익숙한 학생도 새로운 연결 배치에서 관찰 역할을 할 수 있다.

### 3.5 선택과 구간 변화

넓은 능선은 안전하지만 관찰 시야가 제한되어 숨은 가지를 놓치기 쉽다. 높은 좁은 선반은 추락 부담이 크지만 새 동굴·별을 먼저 발견한다. 초반은 눈에 보이는 착지, 중반은 우회해 얻는 시야, 후반 선택 첨탑은 여러 착지점을 연속 판단한다. 같은 점프 횟수만 늘리지 않는다.

### 3.6 장기 도전·복원

먼저 기본 정상을 밟은 학생도 다른 지역의 진입 순서·첨탑 경로를 고르거나 관찰자로 도움을 준다. 개인 발견은 고정 장소 id로, 반 복원은 각 학생의 전망 깃발·안내 표식 기여로 누적한다. 지도에서 아직 찾지 않은 고도대가 남아 다음 차시 목표가 된다. 위치 기억 자체가 의미 있는 장기 세계이므로 세계 전체를 매 차시 섞지 않고 협력 다리의 작업 배치만 바꾼다.

### 3.7 실패·저장·합류

기본 능선은 지역 쉼터로, 첨탑 추락은 아래 착지 지형으로 간다. 협력 다리 상태는 모둠 작업 자리에만 적용하고 얻은 중앙 진입 자격은 개인에게 유지한다. 재접속은 마지막 안전 쉼터다. 복원 깃발을 다른 학생이 추가해도 기존 발판은 움직이지 않는다.

### 3.8 위험·첫 구현 조각

가장 큰 위험은 iPad 카메라에서 단서가 보이지 않거나 협력이 한 학생의 구두 정답 지시로 끝나는 것이다. 첫 조각은 **두 높이대·세 관찰 자리·연결 다리 2개·안전 우회·추락 선반 1개**로 제한한다. 세 클라이언트가 역할을 나누어 두 번째 시야를 얻는지, 연결자가 다른 사람의 정보를 실제로 사용하는지 본다. 20~25분은 동일 구간 반복을 강요하지 않고 자유 재방문·관찰을 포함해 성능을 본다. 학생이 결과를 보지 않고 끝점만 외워 고르면 단서 배치를 바꾸거나 역할을 재설계한다.

기존 지형 탐험대의 답사 표식 수집과 달리 **어디까지 올라가 무엇을 볼지**가 이동의 다음 선택을 만든다. 다만 실제 시야 재미가 약하면 넓은 지도에 기존 점프를 붙인 수준이 될 수 있다. 신규 기능은 코드·장기 저장·개인 쉼터·모집 지도 외에 관찰점 정보와 모둠 다리 기록이다.

## 4. B안 — 물길을 깨우는 계곡 (id 후보 `waterworld`)

### 4.1 세계와 핵심 재미

**물의 통로를 바꾸어 건널 곳과 올라갈 곳을 만들고, 바뀐 풍경 속을 돌아다닌다.** 직접 환경을 바꾸어 다음 탐험을 여는 재미다.

지역은 상류 폭포 숲, 수로 마을, 메마른 유적이며 중앙은 저수지 위의 산이다. 지역 사이 낮은 둑길은 항상 열고 물길 변화는 개인 선택 통로·분리된 협력 작업 자리에서만 충돌에 반영한다.

### 4.2 이동망과 목표

본부↔폭포·마을·유적의 외곽길이 순환한다. 정상 관문은 **세 갈래 수로 연결** 1개이며 참여 자격을 얻으면 중앙의 고정 수문 통로를 지나 넓은 산길로 오른다. 유적 내부 정원은 추가 협력으로 여는 선택 구역. 기본 정상은 모든 정원 복원을 요구하지 않는다.

대표 기본 동선 약 170~220m 목표, 선택 배수로·폭포 뒤길은 별도. 폭포 옆 첨탑은 떨어지면 아래 바위 선반에 착지한다. 물은 학생을 소실시키거나 자동 유속으로 계속 밀어내지 않는다. 수위 변화는 장시간 기다리는 대신 짧은 전환으로 보여 주되 게임 시간 모형임을 밝힌다.

### 4.3 교과 연결

| 지역 | 중심 개념·목표 | 실제 행동 |
|---|---|---|
| 폭포 숲 | 과학: 높은 곳에서 낮은 곳으로 흐르는 물. 경사와 연결에 따라 도착 지점이 달라짐을 설명 | 작은 분기 수로를 바꿔 물이 도달하는 쪽을 관찰 |
| 수로 마을 | 수학: 같은 단위로 양 비교. 제한된 물을 나눌 때 한쪽 증가가 다른 쪽에 미치는 영향 설명 | 두 물통의 같은 눈금을 보고 부유 발판과 마른 길 중 선택 |
| 메마른 유적 | 국어: 원인·결과 설명. 관찰한 상류 변화와 하류 결과를 연결 | 친구에게 “어디를 열었더니 어디에 닿았다”로 전달 |

공통 개념은 **연결된 곳에 변화가 전달됨**이다. 중앙 산의 협력 수로도 이 원리로 작동한다. 실제 유체 시뮬레이션·수압·정확한 유량 계산을 가르친다고 주장하지 않으며 임의 수치로 실제 시설 안전을 판단하게 하지 않는다.

### 4.4 혼자·협력 장면

- 혼자: 물에 잠긴 낮은 길과 떠 있는 발판을 발견 → 배수해 넓은 길을 걷거나 물을 남겨 높은 발판으로 점프 → 물높이와 이동 경로가 함께 바뀜 → 높은 길의 폭포 뒤 동굴 또는 낮은 길의 마을 입구로 이동.
- 협력: 상류 담당이 물을 보낼 분기를 선택 → 중류 담당에게 실제 흐름이 나타남 → 중류가 물을 나누어 보낼 통로를 연결 → 하류 담당이 도달·누수 위치를 보고 전해 줌 → 상류·중류가 수정 → 세 사람이 본 연결 결과로 중앙 수로 발판이 연결됨. 정확한 동시 입력이나 발판을 계속 누르는 일은 없음.
- 누수는 옆의 안전 배수로로 빠져 학생을 떨어뜨리지 않고 어느 연결이 빠졌는지 보인다. 담당자는 결과를 보고 즉시 조정한다. 하류 담당도 첫 결과 확인 뒤 피드백과 두 번째 검증이 필요하다.

### 4.5 선택과 구간 변화

마른 길은 넓고 조작이 쉽지만 낮은 동선만 제공한다. 물을 남기는 길은 높은 발견에 닿지만 발판 사이 점프가 있다. 초반은 한 분기, 중반은 두 목적지에 나누기, 후반 선택 도전은 기존 물길을 역으로 추적해 폭포 뒤에 접근한다. 수위를 정답 숫자로 제시하거나 자동 충전을 기다리는 것을 놀이로 삼지 않는다.

### 4.6 장기 도전·복원

반 복원은 각 학생이 찾아 연결한 물길 조각과 작은 수변 정원을 누적한다. 복원된 정원에 새 학생도 자기 물길·식재 조각을 더할 수 있다. 완성 풍경은 모두 공유하지만 다른 학생의 새로운 연결은 기존 학생의 충돌 지형을 바꾸지 않는다. 다음 방문에는 다른 물 배분으로 높은 동굴과 낮은 길을 비교하거나 다른 수로 역할을 맡는다.

### 4.7 실패·저장·합류

개인 선택 수위는 개인 통로에서 복원하고 아바타에는 해당 탐험 상태 표식을 붙인다. 협력 구간은 모둠별 물통·수로·발판을 분리해 같은 모둠의 화면만 동일 상태로 유지한다. 반 풍경 수위는 장식으로 한정한다. 기본 쉼터는 물에 잠기지 않는 고정 둑 위에 둔다. 선택 첨탑 추락은 실제 아래 지형, 맵 밖은 해당 지역 쉼터다.

### 4.8 위험·첫 구현 조각

가장 큰 위험은 **같은 공간인데 친구마다 물과 길이 달라 혼란스러운 것**이다. 첫 조각은 **한 분기·두 통로·3역할 수로 1자리·고정 둑 쉼터**다. 서로 다른 화면에서 물·발판·다른 학생의 위치가 이해되는지, 비참여자가 새 발판을 타지 않는지 확인한다. 혼란이 크면 개인 통로를 공간적으로 분리하는 방향으로 바꾸며 전체 수로망 제작은 보류한다.

물의 순환 맵의 정해진 여행과 자석 항구의 한 방향 장치 이동과 달리 물길 **연결망을 수정하고 이전 구역을 다른 상태로 재방문**한다. 다만 점프보다 수문 조작 비중이 커질 위험이 있어 세 안 중 사용자 선호와의 적합성은 중간으로 판단한다. 신규 기능은 공통 기능 외에 상태별 수로 렌더링·충돌·모둠 동기화다.

## 5. C안 — 길을 짓는 원정대 (id 후보 `trailworld`)

### 5.1 세계와 핵심 재미

**점프로 탐험하며 발견한 부품의 쓰임을 판단하고, 직접 만든 연결 길로 더 높은 곳을 연다.** 기존 길을 잘 타는 것에서 자기 경로를 만드는 것으로 확장한다.

지역은 돌기둥 협곡, 목재 수관 마을, 옛 운반 유적이다. 중앙 산의 끊어진 길은 세 사람이 설계·준비·현장 연결을 맡아 복구한다. 개인의 기본 이동 능력을 운반 무게로 낮추지 않는다.

### 5.2 이동망과 목표

본부와 세 지역의 바깥길은 처음부터 순환한다. 탐험으로 얻은 길쭉한 부품·모서리 부품·넓은 발판 설계는 선택 지름길에 쓰고, 정상 관문의 기본 부품은 관문 주변에서 제공해 전체 지역 수집을 강제하지 않는다. 정상 필수 관문은 **공동 연결교** 1개, 이후 완만한 산길로 기본 정상에 도달한다. 유적 내부 공중 작업장은 추가 협력으로 여는 선택 주요 구역이다.

대표 기본 동선 약 180~240m 목표. 부품 찾기와 선택 길 연결은 별도로 측정한다. 첨탑 등반은 고정 지형으로 구성하고 자작 부품만으로 최고 지점에 닿아야 하는 조건은 두지 않는다.

### 5.3 교과 연결

| 지역 | 중심 개념·목표 | 실제 행동 |
|---|---|---|
| 돌기둥 협곡 | 수학: 길이·모양 조합. 같은 간격도 다른 조각 조합으로 연결할 수 있음을 설명 | 긴 판 한 개 또는 짧은 판과 모서리 조합으로 연결 |
| 수관 마을 | 과학: 관찰과 비교. 모양·크기를 비교해 용도에 맞는 부품을 고른 이유 설명 | 넓은 착지판·방향 전환판의 실제 크기를 보고 시험 |
| 운반 유적 | 국어: 절차·조건 전달. 누가 어느 조각을 어디에 두어야 하는지 설명 | 조사자와 연결자가 기준점·순서를 말로 공유 |

공통 개념은 **부분을 조합해 목적에 맞는 전체 만들기**다. 중앙 산에서도 여러 조합을 인정한다. 다리의 실제 구조 강도·하중을 계산한다고 표현하지 않고 연결 가능 위치가 정해진 게임 모형임을 밝힌다. 사회의 교역·옛 운반은 배경 소재로 두며 별도 성취 목표를 억지로 추가하지 않는다.

### 5.4 혼자·협력 장면

- 혼자: 협곡 옆 가지에서 모서리 부품 설계 발견 → 넓은 기존 우회길 또는 부품을 써서 옆 절벽 연결 선택 → 실제 연결면이 생김 → 새 시야의 유적 창문으로 진입. 설계는 소모하지 않아 잘못 배치해도 즉시 회수·회전 가능.
- 협력: 조사자가 절벽 끝 두 지점의 간격과 방향을 관찰 → 준비자가 맞는 조각 조합을 짧은 운반길로 보냄 → 연결자가 현장에서 조합을 놓아 보고 남는 틈·회전 방향을 전달 → 조사자가 다른 지지점을 확인하고 준비자가 조합을 수정 → 연결된 길을 시험하며 세 역할의 결과를 확정. 운반은 학생을 잡거나 친구 부품을 빼앗는 방식이 아님.
- 잘못 연결하면 부품은 안전 작업대에 남고 틈이 보인다. 수정은 자원 소실·추락 벌점 없이 가능하다. 세 역할의 실제 수행과 상호 피드백을 기록한 뒤 자격을 준다.

### 5.5 선택과 구간 변화

짧고 좁은 부품 조합은 적은 연결로 높은 발견에 닿지만 점프 부담이 있다. 넓고 굽은 조합은 연결 조각이 더 필요하고 이동이 길지만 쉽다. 초반 한 틈 연결, 중반 방향 전환·부품 재사용, 후반 선택 공중 작업장은 여러 연결의 착지 위치를 계획한다. 준비와 운반 왕복이 길어지면 작업대 위치를 조정하고 부품 수를 늘려 시간을 채우지 않는다.

### 5.6 장기 도전·복원

개인은 설계 발견과 자기가 만든 선택 연결을 저장한다. 반은 각 학생이 복구한 안내길·난간·관측대 조각을 누적해 원정 마을이 자란다. 공용 기반 도로를 철거하지 않아 나중 학생의 실험이 기존 통행을 끊지 않는다. 새 학생에게는 자기 연결 시공 공간이 남고 경험자는 다른 조합과 역할로 재도전한다.

### 5.7 실패·저장·합류

개인 선택 다리는 소유 학생의 가지 통로에만 충돌을 적용하고 다른 학생이 길을 타려면 같은 설계로 자기 통로를 연결한다. 협력 다리는 분리된 모둠 작업 자리에서 공유한다. 다른 학생 화면에서 허공에 서 있는 것처럼 보이는 문제가 남아 있으므로 통로 경계·상태 표식이 첫 시험 대상이다. 쉼터는 고정 땅이고 공중 부품 위 위치를 재접속 위치로 저장하지 않는다.

### 5.8 위험·첫 구현 조각

가장 큰 위험은 iPad에서 부품 배치가 어렵거나 준비자의 일이 왕복 심부름이 되는 것이다. 첫 조각은 **한 틈·조각 3종·넓은 우회로·3역할 작업대 1개**다. 자유 드래그 대신 충분히 큰 접점 선택·회전 1회 단위·되돌리기로 조작한다. 서로 다른 두 조합으로 실제 건너는지, 준비자가 결과를 보고 조합을 수정하는지, 배치보다 카메라 조작에 시간을 쓰는지 확인한다. 운반자의 판단이 없다면 역할 분담을 다시 설계한다.

도형 연구소의 보기 선택·자석 항구의 미리 정해진 레일보다 **어디를 어떻게 연결할지 학생이 직접 정함**이 차별점이다. 자율성이 크지만 편집 UI와 충돌 처리가 가장 어렵다. 신규 기능은 공통 기능 외에 접점 조립·부품 상태·연결 통로 표시다.

## 7. 첫 구현 순서와 검증 구분

안 선택 뒤 아래 순서로 제작한다. 이번 문서 작성에서는 어느 단계도 실행하지 않았다.

1. **공통 기술 조각:** 코드 발급·서버 확인·요약 복원·같은 코드 두 기기 제한·교사 세션 해제·실명 없는 저장·만료와 삭제를 최소 화면으로 확인. 기존 방 정리 이후에도 복원되는지 확인한다. 클라이언트만으로 안전한 구현이 불가능하면 공개 쓰기로 우회하지 말고 필요한 서버 범위를 보고한다.
2. **안별 행동 조각:** 3.8 / 4.8 / 5.8의 짧은 구간 중 선택한 것 하나. 실제 세 클라이언트의 이동과 역할 사건으로 완료·개인 자격을 확인한다. 1·2인 실패, 4~6인 기여, 경험자의 재참여, 교사 수동 예외, 다른 모둠·미참여자의 진입을 확인한다.
3. **성능 조각:** 20원격 아바타+전체 지역 외형을 실기 iPad에서 한 차시 길이로 관찰. 21대의 실제 동시 통신은 별도 확인. FPS·입력 반응·발열·역할 동기화가 나빠지면 장식·가시 범위부터 조정한다.
4. **전체 이동:** 봇이 직접 걸어 기본 정상·여러 방문 순서·오답 뒤 수정·쉼터 복귀·별 6개·선택 도전 우회를 확인. 설계 waypoint 길이와 실제 위치 누적 거리를 구분하며 선택 등반의 아래 착지·재등반도 기록한다.
5. **저장·네트워크:** 규칙 미게시, 통신 끊김·응답 재시도, 새로고침 덮어쓰기, 방 정리, 다른 기기 코드 복원, 같은 코드 동시 실행, 만료·일괄 삭제 후 재접속, 오래된 참여자와 중복 완료 사건을 다중 클라이언트 시험에 넣는다. 위치 주입 시험과 실제 서버 왕복 시험을 구분한다.
6. **회귀·문서:** 공통 파일 영향 범위 점검, 기존 두 앱과 새 규칙 권한 검증, `prototype`의 `npm test`. 안 선택·구현 뒤에만 정식 등록·두 README 갱신을 진행한다.

학생 관찰은 별도다. 자동 시험이 통과해도 **길을 발견해 스스로 다시 가는가, 다른 역할의 결과를 보고 자기 행동을 바꾸는가, 다음 차시에도 이어 하고 싶은가**를 봐야 한다. 한 명의 정답 지시·반복 왕복·도움 요청 방치·큰 추락 후 포기·터치 조작 때문에 관찰을 못 하는 장면이 반복되면 해당 구조를 수정한다. 근거 없는 임계 비율은 확정하지 않는다.

## 8. 비교와 추천

| 기준 | A 하늘 능선 | B 물길 계곡 | C 길 짓는 원정 |
|---|---|---|---|
| 이동의 중심 | 관찰점 찾기·수직 점프·경로 개척 | 환경을 바꾸며 순환 탐험 | 부품 발견·연결·직접 만든 길 이동 |
| 협력의 중심 | 다른 시야를 연결 | 상·중·하류 결과를 피드백 | 조사·준비·시공의 수정 순환 |
| 사용자 선호 적합성 추정 | 가장 높음: 점프 자체가 탐험 수단 | 중간: 장치 조작 비중이 커질 수 있음 | 높음: 개척 성취가 크지만 배치 부담 |
| 주된 기술 불확실성 | 카메라·관찰 단서·높이대 표현 | 화면별 수위·충돌 일관성 | 터치 편집·다른 학생에게 경로 표시 |
| 지루함 위험 | 정해진 점프길만 반복 | 물 조작 뒤 대기 | 부품 심부름·편집 작업화 |
| 가장 먼저 볼 학생 행동 | 높은 시야로 다음 길을 스스로 찾는가 | 물의 도착을 보고 분기를 고치는가 | 남는 틈을 보고 다른 조합을 만드는가 |

**추천: A안 하늘 능선 탐험대.** 학생이 자유롭게 점프하며 돌아다니기를 원한다는 인터뷰에 가장 직접적으로 맞고, 큰 추락의 긴장과 안전한 기본 정상의 구분도 쉽다. 기존 지형 탐험대와의 차별성은 넓이만 늘리는 데 있지 않고 관찰 높이가 다음 행동을 바꾸는 데 있다. 첫 조각에서 이 행동이 나오지 않으면 세계를 크게 만들기 전에 수정한다.

B는 환경 변화가 강점이고 C는 제작의 자유가 강점이다. 다만 세 안 모두 코드·장기 저장·3인 협력·모집 지도는 신규 기능이므로 A를 골라도 기술 기반 작업은 작지 않다. **세 안은 아직 재미·학습 효과와 실행 가능성을 확인한 결과가 아니다. 사용자 선택 전에는 코드·맵 등록을 진행하지 않는다.**

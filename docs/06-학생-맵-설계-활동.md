# 06. 학생 맵 설계 활동 (1단계: 종이 설계)

- 작성일: 2026-09-29
- 범위: **1단계만.** 학생은 종이에 설계하고, 설계지를 맵으로 만드는 일은 Claude가 한다. 게임 안 편집기(2단계)는 만들지 않는다.
- 인쇄 자료: [`activity/map-design-kit.html`](../activity/map-design-kit.html) (브라우저에서 열고 인쇄), [`activity/map-design-kit.pdf`](../activity/map-design-kit.pdf) (바로 인쇄)

## 1. 왜 하나

- 9/29 교실 시험에서 **점프맵을 자주 해 본 학생이 많았고**, 인터넷에 엔트리로 만든 점프맵이 많다는 이야기가 나왔다. 만들어 본 경험을 교과로 연결한다.
- 교과 원리로 장애물을 설계하려면 원리를 정확히 알아야 한다. **설계가 곧 깊은 이해**다 ([01](01-게임성-탐색.md) 2.4).
- 우리 맵의 설계 원칙("원리를 알아야 길을 고를 수 있게")을 학생이 직접 적용해 본다.

## 2. 인쇄 자료 구성 (A4 5쪽)

| 쪽 | 내용 | 몇 부 |
|---|---|---|
| 1 | 장애물 카드 8장: 예측 문, 색 발판, 직렬·병렬 스위치 문, 중력 구역, 바람 구역, 점프 구간, 도전 별·안내판 | 모둠마다 1장 (잘라서) |
| 2 | 좋은 장애물 기준 6가지 (원리를 알아야 지나감, 정확한 과학, 틀려도 배움, 찍기 어려움, 함께하기, 모두 완주) | 모둠마다 1장 또는 화면으로 |
| 3~4 | 설계지: 구간 3~4개(카드, 원리, 모르면 왜 못 지나가나, 질문·보기, 설명·힌트), 코스 그림, 모둠 점검표 | 모둠마다 1부 |
| 5 | 서로 검토지 (다른 모둠 2곳) | 학생마다 또는 모둠마다 |

카드는 **지금 게임에 있는 부품만** 넣었다. 학생이 설계한 것을 바로 맵으로 만들 수 있게 하기 위해서다.

## 3. 수업 흐름 (3차시, 모둠 기준)

| 차시 | 활동 | 자료 |
|---|---|---|
| 1 | **해 보고 분석하기**: 네 맵 중 두세 개를 경기한 뒤 "이 문은 왜 모르면 못 지나갈까?", "어디는 조작만 잘하면 지나갔나?" 이야기 → 2쪽 기준 함께 읽기 | 게임, 2쪽 |
| 2 | **모둠 설계**: 과학 주제 하나 고르기 → 카드 3~4장으로 구간 설계 → 설계지 작성 → 모둠 점검표 → 다른 모둠과 설계지 바꿔 읽고 검토지 작성 → 고치기 | 1·3·4·5쪽 |
| (수업 사이) | 선생님이 설계지 사진을 Claude에게 전달 → 맵으로 만들어 배포 (4장) | — |
| 3 | **서로의 맵 해 보기**: 교사 화면에서 모둠 맵을 차례로 골라 경기 → "예측 문 첫 시도 정답" 요약으로 질문이 너무 쉬웠나·어려웠나 이야기 → 검토지 → 설계한 모둠의 소감 | 게임, 교사 화면, 5쪽 |

- 개인 활동으로 할 때는 구간 수를 2~3개로 줄인다.
- 과학 주제는 자유롭게 고르되 **정확성은 교과서·실험 결과로 확인**하게 한다 (교육과정 단원명과 정확히 맞출 필요는 없음, 9/29 결정).

## 4. 설계지를 맵으로 만드는 방법 (선생님 → Claude)

1. 설계지(3~4쪽)를 모둠별로 사진 찍는다. 코스 그림이 잘 보이게.
2. Claude에게 사진과 함께 "모둠 ○○ 설계지로 맵 만들어 줘"라고 요청한다. 여러 모둠을 한 번에 줘도 된다.
3. Claude가 하는 일:
   - 과학 내용을 확인하고, 틀린 곳이 있으면 **고치기 전에 선생님께 먼저 알린다** (학생 설계를 존중).
   - 카드를 게임 부품으로 옮긴다 (아래 표). 게임에 없는 아이디어는 가장 비슷한 부품으로 바꾸고, 무엇을 바꿨는지 알린다.
   - 시뮬레이션으로 확인한다: 정답 길로 완주 가능, 오답은 떨어짐, 조작만으로 우회 불가, 점프 구간은 보통 점프나 점프 + 다이브로 닿음.
   - 맵 목록에 "○○ 모둠: 맵 이름"으로 추가하고, 선생님이 확인하신 뒤 배포한다.
4. 맵 이름·질문에는 **학생 이름을 넣지 않는다** (모둠 이름만).

### 카드 → 게임 부품

| 카드 | 코드 (`prototype/src/levels/`) | 참고 맵 |
|---|---|---|
| 예측 문 | `choiceGate({ name, question, hint, options, right, wrong })` (kit.js) | 태양계, 산과 염기, 전기 회로 |
| 색 발판 | `litmusField` 방식 (녹는 발판, 시드로 색 배치) | 산과 염기 (acid.js) |
| 직렬·병렬 스위치 문 | `switchDoor({ kind: 'series' | 'parallel', plates })` | 전기 회로 (circuit.js) |
| 중력 구역 | `gravityAt` + 구역 표 | 태양계 (solar.js) |
| 바람 구역 | `windAt` + 주기 | 태양계 화성, 점프 연구소 바람 다리 |
| 점프 구간 | `platform`, 움직이는 발판(`movers`), 도는 막대 | 점프 연구소 (level.js) |
| 도전 별 | `challengeStar(x, y, z)` — 섬 거리: 지구 7m, 토성 6.5m, 달 19.5m | 모든 맵 |
| 안내판 | `sign()` / `info()` | 모든 맵 |

- 색 발판과 스위치 문은 지금 각 맵 파일 안에 있다. 학생 맵에서 쓰게 되면 kit.js로 옮겨 공용으로 만든다.
- 맵 id는 영어 소문자만 (데이터베이스 규칙 `^[a-z]{1,16}$`), 예: `teama`.

## 5. 관찰할 것

- 학생이 "원리를 모르면 못 지나가는" 장애물을 설계하는지, 퀴즈 안내판처럼 설계하는지
- 헷갈리는 보기에 학생들의 오개념이 드러나는지 (다음 수업 자료)
- 다른 모둠 맵을 할 때 첫 시도 정답률, 설계한 모둠이 그 결과를 보고 무엇을 느끼는지

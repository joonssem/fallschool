  - 남은 한계: 색을 안 보고 점프만 하면 약 20%가 운으로 통과
- C 구현: 새 맵 "전기 회로 공장" (`circuit`) → [prototype README](../prototype/README.md)
  - 스위치 발판(회로 잇기 1개, 직렬 3개, 병렬 3개) + 예측 문 2개. 21명 방에서는 직렬 문을 혼자 못 열어 친구와 나눠 서야 한다
  - 발판 위 학생은 화면마다 모든 학생 위치로 계산 → 데이터베이스 규칙 변경 없음
  - 시뮬레이션 48/48. 시뮬레이션으로 찾아 고친 것: 문 앞에 다가가기만 해도 문이 뚫림, 직렬 문의 마지막 세 명이 문까지 못 옴(문을 4초에 걸쳐 천천히 닫기), 병렬 스위치 하나가 문 가는 길 위에 있어 모르고 밟음
- 카메라가 벽을 피하게 수정: 예측 문·스위치 문을 지난 직후 카메라가 벽 뒤에 남아 앞이 안 보였다 (A·B 맵에도 있던 문제)
- 난이도 폭: **도전 별**(맵마다 3개, 점프 + 다이브로만 닿는 섬, 개인 도전) + **도움 점프**(같은 곳에서 3번 떨어지면 다음 체크포인트까지 점프 1.15배)
  - 섬 거리는 중력별 점프 거리를 시뮬레이션으로 재서 정함. 별 12개 × 4가지 검사 48/48
  - 도움 점프는 예측 문·스위치 문을 넘지 못함(확인). 리트머스 구역에서는 끔 (판단 문제라서, 켜면 운 통과가 22% → 27%로 늘었다)
- 교사 화면 학습 기록: 경기 중 "예측 문 첫 시도 정답: 달 15/19 · 화성 12/18 …" 요약, 학생 줄마다 ★(도전 별 수)
  - 데이터베이스 규칙에 `stars`, `gates` 추가 → [04](04-데이터베이스-규칙.md) 3-1. **선생님이 Firebase 콘솔에 게시해야 보인다**
  - 새 칸은 따로 보내서, 규칙 게시 전에도 기존 기록(완주 등)은 영향 없음
- **토성 중력 점검 → 수정**: 게임 중력이 0.9배(지구보다 약함)라 실제 1.07배(지구보다 조금 셈)와 **방향이 반대**였다. 실제 값 1.07배로 바꿈
  - 확인한 사실: 표면 중력 10.44 m/s²(적도, 1기압 높이) ÷ 9.8 ≈ 1.07배, 평균 밀도 0.69 g/cm³(물보다 작음), 목성 다음으로 큼 → 예측 문 질문·보기·설명은 그대로 맞음
  - 고리 다리 난이도 차이 없음 (같은 봇으로 0.9배 18/40, 1.07배 18/40). 도전 별 섬 거리 8m → 6.5m (×1.07에서 보통 점프 5m, 점프 + 다이브 7.75m), 별 시뮬레이션 48/48
- 학생 맵 설계 활동 1단계: 장애물 카드 8장(게임에 있는 부품만), 좋은 장애물 기준 6가지, 설계지, 모둠 점검표, 서로 검토지 (A4 5쪽) + 3차시 수업 흐름 → [06](06-학생-맵-설계-활동.md)

### 확인된 것

- Firebase RTDB 무료 요금제 + 학교 와이파이로 학급 전체(교사 1 + 학생 21) 실시간 경기 가능
- 경기 도중 맵 바꾸기가 재참가 없이 모두에게 반영됨
- 학생 사이 조작 실력 차이가 큼: 점프맵 경험이 많은 학생에게는 두 맵 모두 쉽고, 경험이 적은 학생은 복합 조작(점프 + 다이브)에서 막힌다
- 원작을 아는 학생은 원작의 방해 행동(잡기·밀치기)을 기대한다. [01](01-게임성-탐색.md)에서 정한 "잡기는 물건·협동 운반에만, 교사가 켜고 끄기" 원칙을 유지하고, 활동 전에 이 게임의 규칙(방해 없음, 함께 완주)을 안내할 필요가 있다
- 맵에 중력 차이를 넣는 것만으로는 과학 내용이 떠오르지 않는다. 게임 안이나 수업에서 중력을 생각하게 만드는 장치가 따로 필요하다

### 참고: 작업 중 겪은 문제

- Claude Code의 자동 모드 안전 검사가 여러 번 응답하지 않아 명령 실행이 멈췄다. 자동 모드를 끄고(Shift+Tab) 진행하면 명령마다 허락을 묻는 대신 멈추지 않는다.
- 규칙을 채팅 화면에서 복사하면 긴 줄이 줄바꿈되어 "unterminated string literal" 오류가 났다. 규칙은 파일(메모장 또는 GitHub)에서 복사한다.

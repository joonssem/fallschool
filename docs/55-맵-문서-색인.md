# 55. 맵·문서 색인

- 작성일: 2026-10-06. 관리: Claude(기존 맵 수정·보완)와 Codex(새 맵 제작)가 맵을 만들거나 고친 **같은 커밋에서 해당 행을 갱신**한다(`AGENTS.md` '맵·문서 색인' 절).
- 용도: 맵마다 **현재 동작을 설명하는 기준 문서**, 상태, 검증 수준, 다음 보완 후보, 폴 가이즈 참고 연결을 한곳에서 찾는다. 이력과 상세 내용은 여기에 쓰지 않고 기준 문서 머리말에 둔다(중복 금지).
- 자동 검사: `prototype/tests/maps-meta.mjs`가 `index.js`에 등록된 모든 맵 id가 이 문서에 `` `id` `` 형태로 있고, 이 문서가 링크한 문서 파일이 실제로 있는지 확인한다. 내용이 최신인지는 검사하지 못한다.
- 작성 근거: 각 기록 문서(11~52)와 `npm test` 결과. 맵 코드는 새 맵 7개 중 일부만 이번에 직접 읽었다. 교사 보고·코드 기반 추정·실제 교실 검증은 구분해 적는다.

## 4. 기준 문서 머리말 형식

적용 현황(2026-10-06): 모든 맵의 기준 문서(11, 17, 20, 21, 23, 24, 27, 30, 31, 36, 38, 41, 42, 46, 47, 49, 52)에 머리말을 넣었다. 기존 맵의 머리말은 **기록 문서에서 정리한 것**이고 맵 코드를 새로 읽고 쓴 것이 아니다. 맵을 고칠 때 코드와 대조해 바로잡는다.

기준 문서는 맨 위에 다음을 둔다. 맵을 고칠 때 해당 문서만 갱신하고, 전체 문서를 한꺼번에 다시 쓰지 않는다.

```
## 현재 동작 요약 (YYYY-MM-DD 기준)
- 10줄 안팎: 핵심 행동, 선택과 대가, 결과가 쓰이는 다음 이동, 길이, 검증 수준

## 변경 이력
| 날짜 | 담당 | 내용 | 문서·커밋 |

## 발전 방향
| 후보 | 상태(제안/진행/완료/보류) | 근거 문서 |
```

## 5. 번호·이름 규칙

- 새 문서는 `ls docs | tail`로 최신 번호를 확인해 +1을 쓴다. 번호가 겹치면 나중에 커밋하는 쪽이 옮긴다([39](39-Codex-전달-문서번호.md)). 다음 새 번호는 **59**이다.
- 계획서에는 제작 기록 문서 번호를 미리 적는다([50](50-작업-정리-2026-10-05.md)).
- 링크는 파일 이름 기준이므로 문서 파일 이름은 바꾸지 않는다. 제목의 번호만 정정한다.

# 21. 산과 염기 리트머스 시험대 구현 결과

2026-10-01, Claude. 요청서: [15. 산염기 시험장치 구현 요청](15-산염기-시험장치-구현요청.md), 후보: [14. 기존 맵 수정 후보](14-기존맵-수정후보.md) 1번. 브랜치 `claude/acid-lab`(`8b746c3` 이후 커밋·푸시됨, **main에는 병합하지 않음**, Codex 검토 대기).

## 현재 동작 요약 (2026-10-06 기준, 기록 문서에서 정리)

- 지시약 문, 색을 판단해 밟는 리트머스 웅덩이 두 곳, 회전 장애물, 중화 문, 예측 문 3개. 타일 배치는 시드로 바뀐다.
- **리트머스 시험대**: 용액(식초·비눗물)과 종이(푸른·붉은)를 골라 넣기 전·후 색을 결과판에서 확인한다. 확정 버튼·정답·추락 오답 없음, 학생별 상태.
- 검증: 자동(`acid-lab.mjs`). 규칙이 드러난 뒤 경로 선택이 흥미로운지는 교실 관찰 전.

## 구현한 것 (`prototype/src/levels/acid.js`만 수정)

- 두 리트머스 구간 입구 발판 **옆 받침**(8×6, 입구 깊이 안)에 시험대 하나씩. 식초 입구는 안내판이 왼쪽이라 **오른쪽**, 비눗물 입구는 안내판이 오른쪽이라 **왼쪽**.
- 선택 발판 4개(식초·비눗물·푸른 종이·붉은 종이)와 결과판. 발판에 서면 선택되고 선택된 발판은 색이 켜지며 커진다. 선택 순서는 자유이고 선택을 바꾸면 결과판이 즉시 바뀐다. 한쪽만 고르면 결과를 채우지 않고 "이제 종이를/용액을 골라요"를 보여 준다.
- 결과판: 제목(`식초 + 푸른 종이`), **넣기 전 → 넣은 뒤** 색 도식과 색 이름, 설명 두 줄. 변하지 않는 경우도 결과로 표시한다(예: "붉은 종이는 그대로 붉어요"). 비눗물이 들어간 결과에는 "(이 실험의 비눗물은 염기성이에요)"를 덧붙인다. 설명에 "녹는다"는 표현이 없다.
- 결과 판정은 `litmusResult(solution, paper)` 한 곳(`export`)에서 계산하고 도식·설명이 같은 값을 쓴다.
- 확정 버튼·새 문·정답·사용 의무·추락 오답이 없다. 기존 타일·안전 색·녹음 공유·`noHelp`·예측 문 3개·체크포인트 7개·도전 별 3개는 그대로이고, 같은 시드의 타일 색 배치는 구현 전과 일치한다(시드 1·7·99).
- 상태는 학생별: 시험대는 **내 위치만** 본다. 친구의 위치·`triggerTile()`은 영향이 없다. `setSeed()`(새 경기)와 `resetProgress()`(처음부터)에서 선택·발판 점유가 초기화된다.
- `kit.js`, `main.js`, Firebase 필드·규칙은 건드리지 않았다.

## 검증 (자동 시험은 학습 효과 검증이 아니다)

`tests/acid-lab.mjs` 82건, 전체 `npm test` 13종 통과.

- 네 조합 판정표(변화 여부·결과 색·색 이름·설명)가 요청서와 일치, 알 수 없는 선택은 오류.
- 시험대 용액·종이 조합이 앞 웅덩이가 보여 주는 실험(식초에 푸른 종이 / 비눗물에 붉은 종이)과 같으면 결과판에 "앞 웅덩이와 같은 실험이에요"만 표시한다. 안전한 색은 알려 주지 않는다(`tests/acid-lab.mjs` 92건).
- 두 입구 × 네 조합 × 용액 먼저·종이 먼저(총 16가지)에서 결과 일치, 한쪽만 고르면 결과 없음, 선택 변경 즉시 반영, 선택 표시.
- 친구가 네 발판 모두에 서 있고 타일 20개가 녹아도 내 시험대는 그대로, 교사 화면(player 없음)에서 오류 없음.
- 새 경기·처음부터 초기화와 초기화 후 같은 발판 재선택.
- 같은 시드의 타일 지문, `noHelp` 두 체크포인트, 체크포인트·별·문 개수.
- 이동: 시드 3개에서 시험대를 쓰지 않고 안전 타일 길(너비 우선 탐색)로 두 구역 통과, 두 시험대 왕복. **우회 없음**: 시험대 앞 가장자리에서 달려 점프 + 다이브를 해도 발판 높이에서 최대 9.4m까지 가고(기존 입구 가운데에서도 9.8~11.0m), 건너편 입구 발판(약 14m)에 닿지 못한다.
- PC 화면: 비눗물 입구(왼쪽 시험대)에서 `비눗물 + 붉은 종이` 결과판·발판 선택 표시·라벨이 읽히고 도식 색과 이름이 함께 나오는 것을 확인했다.

## 확인하지 못한 것

- **식초 입구(오른쪽 시험대) 화면**: 캡처가 시간 제한에 걸려 얻지 못했다. 좌표만 거울 대칭이고 시험은 통과했으나 화면 겹침은 미확인.
- 시험대가 기본 카메라에서 타일 구간 시야를 가리는지(결과판이 입구 앞 약 4.4m에 떠 있고 PC 캡처에서는 길을 가리지 않았다)는 iPad에서 확인 필요.
- iPad 가독성·터치(발판에 정확히 서기), 결과판 글자 크기. 학생이 시험대를 실제로 쓰는지, 쓴 뒤 타일 선택이 바뀌는지, 시험대 때문에 기다리는 학생이 생기는지, 이유를 말하는지는 교실 관찰 대상이다.
- 우회 시험의 봇은 자동 점프만 쓴다. 숙련 학생의 다른 조작(연속 점프 등)은 시뮬레이션하지 않았다.
- 비눗물의 세기는 제품마다 다르므로 "이 실험의 비눗물은 염기성"으로만 표기했다.

## 통합 시 참고

- `acid.js`에 `export`가 추가됐다: `SOLUTIONS`, `PAPERS`, `litmusResult`. 맵 등록·`kit.js`는 변경 없음.
- `package.json`의 `npm test`에 `acid-lab.mjs`를 추가했다(Codex의 바람마을 시험 뒤).
- `prototype/README.md`의 산과 염기 절에는 아직 시험대 설명을 넣지 않았다. README의 다른 변경과 겹치지 않게 통합 때 한 번에 반영하길 권한다.
- 두 번째 적용 대상(거대 실험실 피스톤, 물의 순환)이 정해지면 `resultBoard()`·선택 발판 로직을 `kit.js` 공용 장치로 뽑을지 판단한다(요청서 방침). 지금은 `acid.js` 안에 있다.

## 게임성 점검표 ([19](19-게임성-반영-기준.md) 기준)

| 항목 | 기록 |
|---|---|
| 핵심 재미 | 색을 판단해 실제로 걸을 길을 고르는 기존 정체성을 유지. 시험대는 그 판단 전에 안전하게 해 보는 선택 활동 |
| 의미 있는 선택 | 용액(식초·비눗물) × 종이(푸른·붉은)를 골라 네 조합의 결과를 비교. 결과는 도식·색 이름·설명으로 즉시 바뀐다 |
| 즉시 결과 | 발판에 서자마자 넣기 전 → 넣은 뒤 색 도식이 바뀐다(설명을 읽기 전에 색으로 알아볼 수 있음). 변하지 않는 경우도 표시 |
| 다음 행동·성취 | 시험대는 앞 웅덩이와 같은 조합이면 "같은 실험"이라고만 알려 주고, 학생이 그 결과 색을 보고 기존 리트머스 타일 색을 고른다(웅덩이 안내판의 "변한 색 발판만 버텨요"와 연결). 안전한 색을 직접 알려 주지는 않는다 |
| 구간 변화 | 이번 변경은 구간 요구를 바꾸지 않는다(기존 타일·유리 막대·중화 문 유지). 새 관문·확정 버튼·왕복 의무 없음 |
| 재시도 부담 | 선택 변경은 발판 하나로 즉시. 시험대 왕복은 입구 옆 약 8m. 시험대에서 떨어지면 기존 `noHelp` 체크포인트로 돌아온다(도움 점프 없음 — 이 구간의 낙하는 판단 문제로 취급하던 기존 설정 유지) |
| 기본 완주·선택 도전 | 시험대를 한 번도 쓰지 않아도 완주한다(시험: 시드 3개에서 사용 없이 두 구역 통과). 선택이라고 안내하며 실제로 건너뛸 수 있다. 우회 경로도 만들지 않았다(점프+다이브로 건너편 도달 불가) |
| 친구와의 연결 | 상태는 학생별이라 친구의 선택이 내 결과에 영향이 없다. 친구와 결과를 말로 비교하는 장면은 교실 관찰 대상(코드로는 확인 불가) |
| 재체험 용도 | 시험대 자체는 고정이다. 재체험에서 달라지는 것은 기존 리트머스 타일 배치(시드)뿐이며, 이는 새로운 판단이 아니라 같은 규칙의 다른 배치다 |
| 근거·관찰 | 코드·시뮬레이션 확인과 교실 확인을 구분했다. 아래 "교실에서 볼 것" 참고 |

**교실에서 볼 것**: 시험대를 쓰는 학생 수와 시기(타일 전/후), 쓴 학생의 타일 오선택이 줄어드는지, 쓰지 않고 시행착오로 푸는 학생의 비율과 반응, 시험대를 쓴 뒤 "왜 그 색을 골랐나요?"에 결과를 근거로 답하는지, 결과판 글자·터치(iPad), 시험대와 타일 구간 사이 왕복·대기, 친구와 결과를 비교하는 대화. 규칙이 드러난 뒤에도 타일 길 선택이 흥미로운지도 함께 본다(docs/18).

# 08. 전원 참여 모드와 기존 맵 적용

- 작성일: 2026-10-01
- 목적: Fall Guys의 다양한 진행 방식을 검토하고, 탈락·학생 간 잡기·밀치기 없이 재미와 협동을 유지하는 수업 구조를 정한다.
- 상태: 원작 자료 및 저장소 코드 검토 완료. 아래 기능 제안은 아직 구현하지 않았고, 교실 효과는 관찰이 필요하다.
- 관련: [원작 사실 확인](07-원작-사실-확인.md), [작업 기록](05-작업-기록.md)

## 1. 원작 모드 검토

모드 선택 목록은 업데이트·기간 한정 운영에 따라 달라진다. 아래는 진행 방식의 비교이며, 조사 당일 모두 선택할 수 있다는 의미는 아니다. 2024년 공지의 인원·라운드 수는 당시 변경 사항으로 읽는다.

| 모드 | 진행 방식 | 수업에서 검토할 점 |
|---|---|---|
| Solos / Knockout | 개인 통과 여부에 따라 라운드를 진행하는 탈락전 | 탈락한 학생이 관전하게 되어 참여 시간이 줄어듦 |
| Ranked Knockout | 탈락전에 실력별 매칭·등급을 추가, 개인 참가만 가능 | 전원 참여보다 경쟁 성적에 초점 |
| Duos / Squads | 두 명·네 명 팀으로 경쟁. Squads는 일부가 미완주해도 팀 성과가 충분하면 진출 | 개인 실패를 보완하지만 팀 탈락은 남음. 팀원을 탓할 가능성은 교육적 검토 사항 |
| Explore | 제작자 맵을 계속 플레이. 완주 후 다음 맵으로 이동하거나 맵을 건너뜀 | 최종 한 명을 뽑는 쇼와 다른 구조. 그러나 학급이 각자 다음 맵으로 흩어질 수 있음 |
| Creative / Custom Games | 맵 제작·공유 / 코드로 비공개 방에 모여 선택한 맵 플레이 | 제작·참가 방식이며, 자동으로 탈락이나 잡기가 없어지는 규칙은 아님 |
| Sweet Thieves | 사탕을 가져오는 팀과 이를 막는 팀의 역할 대결. 잡힌 친구를 버튼으로 구출 | 이동·공동 목표·역할 분담을 참고할 수 있으나 잡기·감금 구조는 채택하지 않음 |

Solos Chill은 목표 달성 시 누구나 통과할 수 있는 기간 한정 모드로 커뮤니티 자료에 소개되어 있다. 공식 상세 규칙을 확보하지 못했으므로 보조 참고로만 사용한다. 조건 미달 학생도 다음 라운드에 참여시키는 우리 규칙과 동일하다고 보지 않는다.

Explore도 모든 개별 맵이 무탈락이라는 뜻은 아니다. 공식 소개에는 Course의 여유 있는 제한 시간이 설명되어 있으며, 이를 모든 맵의 재도전 규칙으로 일반화하지 않는다. 잡기·밀치기 허용 여부와 탈락·진출 여부도 별개의 설계 항목이다.

## 2. 우리 게임의 방향

Explore의 반복 도전과 팀 공동 목표를 참고하되, 학급 전체가 같은 맵에서 진행하는 전원 참여형 수업으로 만든다. 원작 모드를 그대로 복제하는 제안은 아니다.

- 학생 간 잡기·밀치기·충돌은 도입하지 않는다.
- 낙하는 체크포인트 재도전으로 처리한다. 미완주해도 다음 라운드에 참가한다.
- 교사가 고른 맵 세 개를 함께 진행하고, 라운드 사이 짧게 되돌아본다.
- 먼저 완주한 학생에게 선택 도전이나 도움 역할을 제공한다. 도움 역할을 의무로 만들지는 않는다.
- 완주·개념 판단·공동 과제를 구분해 본다. 첫 시도 정답률만으로 이해를 판정하지 않고 설명 질문을 함께 쓴다.
- 공동 목표는 추가 성취로 둔다. 전원 완주를 다음 라운드 입장 조건으로 삼지 않는다.
- 교사는 완주 인원·수업 시간을 보고 종료한다. 시간 부족과 개념 오해를 같은 실패로 처리하지 않는다.
- 긴장감은 움직이는 장애물, 선택의 결과, 도전 별, 개인 기록 개선, 공동 장치 완성에서 얻는다.

## 3. 코드에서 확인한 현재 상태

| 항목 | 확인한 동작 | 근거 |
|---|---|---|
| 낙하 후 복귀 | 학생은 낙하 후 체크포인트로 복귀, 탈락 참가자 목록 없음 | `prototype/src/main.js`의 `frame()`·복귀 처리 |
| 완주 후 조작 | 학생 완주는 기록·알림만 처리하며 입력을 끄지 않음. 완주 전용 활동·이동 버튼은 없음 | `main.js`의 `onFinish()`·`frame()` |
| 다음 경기 참가 | 새 경기에서 모든 학생의 진행 기록과 위치를 초기화. 이전 완주 여부로 제외하지 않음 | `main.js`의 `onStudentMeta()` |
| 교사 진행 | 출발·얼음·종료·대기실·맵 변경 가능. 맵 변경은 대기실로 전환 | `prototype/src/net/room.js`의 교사 명령 |
| 묶음 라운드 | 현재는 맵 하나씩 수동 선택. 세 맵 순서·라운드 번호·되돌아보기 상태는 없음 | `room.js`, `main.js` |
| 결과 표시 | 학생에게 학급 완주 수, 교사에게 완주 기록·별·예측 문 결과 | `main.js`, `prototype/README.md` |
| 협동 계산 | 다른 학생 위치를 각 화면에서 계산. 모둠별 목표·역할 기록은 없음 | `main.js`의 `level.getOthers`, 각 맵 코드 |

완주 후 입력이 가능하다고 해서 앞 구간에 안전하게 돌아가 도움을 줄 수 있다는 뜻은 아니다. 체크포인트·문·지형 때문에 접근이 어려울 수 있으므로 도움 이동과 완주 기록 보존은 별도 설계·시험이 필요하다.

## 4. 기존 일곱 맵에 적용

아래 추가 활동은 제안이다. 맵에 이미 있는 요소와 구현이 필요한 요소를 구분한다.

| 맵 | 현재 활용 가능한 요소 | 적용 제안 | 확인할 위험·되돌아보기 질문 |
|---|---|---|---|
| 점프 연구소 | 숨은 길의 실패가 공유됨, 여러 학생 위치로 기우는 시소 | 첫 라운드 조작 연습. 길 찾기·양쪽 균형을 공동 도전으로 안내 | 친구를 일부러 떨어뜨리는 행동 관찰. “왜 양쪽에 나눠 서니 덜 기울었나?” |
| 태양계 | 예측 문, 중력별 점프, 선택 도전 별 | 판단→체험→비교 라운드. 완주 후 중력 두 구역을 비교하는 선택 활동 | 친구를 따라 문을 고른 것과 이해를 구분. “같은 힘으로 뛰었는데 왜 달랐나?” 실제 값·게임 조정값 구분 |
| 산과 염기 | 지시약 문·리트머스 길, 공유되는 발판 변화 | 탐색자가 색 변화 관찰, 설명자가 근거 말하기. 역할은 수업 안내로 시작 가능 | 색 구별·가독성, 운 통과, 답만 알려주기 관찰. “시작 색과 넣은 뒤 색은?” |
| 전기 회로 | 세 발판을 함께 누르는 직렬 문, 하나로 열리는 병렬 문 | 우선 협동 시험 맵. 먼저 온 학생의 스위치 역할과 마지막 학생의 통과를 관찰 | 문은 다시 닫힘. 다수가 지나간 뒤 혼자 남은 학생이 막힐 수 있음. “왜 여기서는 모두, 저기서는 하나였나?” |
| 물의 순환 | 지표수·지하수 갈림길, 예측 문·이동 발판 | 모둠원들이 두 경로를 나눠 체험한 뒤 흐름 비교. 공동 경로 완료 표시는 추가 개발 | 어느 길도 다음 라운드 참가의 필수 조건으로 만들지 않음. “두 길의 물은 어디에서 다시 만나는가?” |
| 거대 실험실 | 피스톤·액체 발판·예측 문 | 한 학생이 주기를 관찰하고 다른 학생이 이동, 역할 교대. 완주 후 관찰 도전 추가 검토 | 조작 실패와 개념 판단 분리. 게임 피스톤의 주기를 실제 압력 법칙처럼 설명하지 않음. “같은 양의 공기가 차지하는 공간은?” |
| 인체 대탐험 | 두 발판 협동 판막, 산소·이산화탄소 흐름 | 공동 장치 작동 후 각자 완주. 도착 후 산소·이산화탄소 방향 비교 | 판막은 각 화면에서 한 번 활성화되면 유지됨. 늦게 온 화면도 같은 상태가 되는지 검증 필요. 실제 판막은 학생의 협동으로 열리는 장치가 아니라는 과장 구분 |

전기 회로의 전구 직렬·병렬 밝기 비교는 같은 전지·같은 전구 조건의 확장 도전으로 유지한다. 인체 판막의 영구 개방은 통과 편의를 위한 게임 규칙이며 실제 판막 운동 설명과 구분한다.

## 5. 다음에 할 일 — 세 가지 추천

### 1순위: 기존 맵으로 전원 참여 수업을 먼저 시험

점프 연구소 → 전기 회로 → 물의 순환을 현재 교사 버튼으로 수동 진행한다. 각 라운드 뒤 1분 정도 질문하고, 미완주 학생도 다음 라운드에 참여한다. 조작·협동·경로 비교라는 서로 다른 경험을 확인할 수 있다.

기록: 완주 후 대기 시간, 혼자 남아 문에서 막힌 학생, 자발적 역할 분담, 설명 질문에 대한 응답. 새 기능 없이 진행 구조의 효과를 먼저 확인한다. FPS·iPad 표시·Firebase 사용량 확인도 함께 수행한다.

### 2순위: 완주 후 선택 활동과 뒤처진 학생 지원

전기 회로를 첫 대상으로, 완주 기록을 보존하면서 도움 구역으로 이동하거나 선택 도전을 계속할 수 있는 흐름을 설계한다. 마지막 학생이 혼자 문 앞에 남는 상황의 교사 지원도 마련한다. 인체 판막은 입장·재접속·늦게 도착한 학생 화면의 개방 상태를 시험한다.

성공 기준: 완주자는 활동을 고를 수 있고, 도움 역할을 끝내도 기록이 바뀌지 않으며, 다른 학생은 도움자가 떠나거나 접속을 끊어도 수업을 계속할 수 있다. 도움 이동은 판단 문 정답을 자동 통과시키는 기능으로 만들지 않는다.

### 3순위: 세 라운드와 되돌아보기 진행 기능

교사가 맵 세 개를 고르면 라운드 번호·다음 맵·되돌아보기 질문이 보이게 한다. 다음 라운드는 교사가 시작하고, 모든 학생을 다시 참가시킨다. 맵 사이 기록은 덮어쓰기 전에 보존할 방법을 정한다.

현재 `meta`에는 묶음 라운드 상태가 없으므로 서버 데이터·Firebase 규칙·모의 백엔드와 결과 저장을 함께 검토해야 한다. 검증은 교사+학생 여러 탭으로 미완주·완주·연결 복구·다음 라운드 참가를 확인한다.

새 맵(분수 피자 공장)은 이 세 작업에서 확인한 공동 목표·완주 후 활동 구조를 적용해 제작하는 것을 추천한다.

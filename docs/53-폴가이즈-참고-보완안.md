## 1. 폴 가이즈에서 가져올 것과 버릴 것

폴 가이즈의 재미는 "예고가 보이는 움직이는 장애물을 읽고 몸으로 통과하는 것"이다. 이 부분이 우리 맵 중 `발판 → 결과판 → 문` 반복이 강한 곳에 부족하다. 반면 탈락·밀치기·운은 우리 규칙과 맞지 않는다.

| 가져올 것 | 우리 방식 |
|---|---|
| 회전 막대·원통·컨베이어·눈덩이처럼 읽고 피하는 움직임 | 움직임은 시간 `t`로만 정해 모든 화면이 같다. **실패해도 떨어지지 않고** 살짝 밀려 제자리로 돌아온다. 떨어지는 실패는 선택 별 도전에만 둔다 |
| 예고(코뿔소가 돌진 전에 빛남, 눈덩이 그림자) | 모든 장애물에 예고 신호를 둔다. 급발진·운으로 정해지는 장애물은 만들지 않는다 |
| 시각과 충돌 판정의 일치 | 폴 가이즈 레이저가 "보이는 것과 판정이 달라" 불만이 많았다. 보이는 모양과 충돌체를 같게 하고, 장식은 충돌 없는 자식 메시로 만든다 |
| 랜덤 변형(막대 1~3개, 블록 구조 변경) | 시드로 변형을 정한다(이미 맞바람·돌풍, 메아리가 사용). 난이도 변형은 `labeasy`처럼 맵 id로 나눈다 |
| 판정 관대함(코요테 타임, 느슨한 도착 판정) | 이미 있다(`player.js` 코요테 0.1초, 점프 버퍼 0.12초). 새 장치에서도 도착 판정을 넉넉하게 한다 |
| 시작 전 맵 훑어보기 | 구현 필요 여부는 화면 확인 뒤 판단(공용 `main.js` 변경이라 이번 보완 범위 밖) |

| 버릴 것 | 이유 |
|---|---|
| 탈락, 점액에 빠지면 실패 | 탈락 없음 원칙 |
| 상대를 잡아 밀기, 인원 밀집 충돌 | 학생 간 밀치기·잡기 없음 |
| 운이 승패를 정하는 장애물(코뿔소 급발진) | 안전한 재시도와 공정성. 학습 판단이 묻힘 |
| 제한 시간 압박, 카운트다운 | 급한 조작 부담 금지 |

## 2. 맵별 보완 후보

기준: 학습 판단은 그대로 두고 **이동의 재미**를 더한다. "선택이라고 안내한 활동은 건너뛸 수 있게" 하고, 별 도전은 맵당 10개 이하(`map-rules.mjs`)를 지킨다.

| 우선 | 맵 | 지금의 약점 | 폴 가이즈에서 빌린 이동 장치 | 학습·선택과의 연결 | 실패 시 |
|---|---|---|---|---|---|
| 1 | 도형 건축 연구소 | 3지선다형 조작([45]에서 범위 밖으로 남김) | **틈새 공략**: 천천히 다가오는 벽의 구멍 모양을 읽고 맞는 구멍으로 이동 | 구멍이 전개도·대칭 단서와 같은 도형 → 도형 판단이 곧 이동 선택 | 벽에 닿으면 앞으로 밀리지 않고 멈춰 구멍 앞에서 다시 선택 |
| 1 | 전기 회로 공장 | 협동 대기([30]) | **롤아웃/빙빙돌이**: 회전하는 기어·컨베이어 징검다리 지름길(선택) | 스위치를 기다리는 동안 해 볼 수 있는 선택 이동. 회로 상태가 켜진 기어를 돌림 | 기어에서 떨어져도 가까운 안전 발판. 별 도전만 낙하 |
| 1 | 명령 택배 로봇 도시 | 명령 입력 중심이라 이동 재미가 약함 | **컨베이어 배송 벨트**: 벨트 방향을 읽고 로봇·학생 이동 | 로봇 경로(명령)와 벨트 방향이 같은 좌표계 → 벨트를 이용한 명령 최적화 별 | 벨트에서 밀려도 길 밖으로 안 나가고 정류장으로 복귀 |
| 2 | 물의 순환 빙하길 | 미끄러운 얼음 외 변화 적음 | **눈덩이**: 미끄러져 내려오는 얼음덩이의 경로 예측(그림자로 예고) | 얼음덩이 경로를 읽고 비껴가면 빠른 길. 기온·빙하 개념과 연결 | 맞아도 살짝 밀려 얼음 위에 남음 |
| 2 | 점프 연구소 시험장 | 돌풍·시소만 있음 | **점프 클럽**: 회전 막대를 점프로 넘는 링(선택 별 도전) | 학습 없음(연습 맵). 막대 수 1~3개를 시드로 | 막대에 맞아도 링 안쪽으로 밀림, 낙하는 별 도전에만 |
| 2 | 분수 피자 공장 | 조각 고르기 후 문 열기 반복 | **컨베이어 조각 흐름**: 벨트로 흘러오는 조각을 읽고 고름 | 주문 분수와 같은 양이 되는 조합을 벨트 위에서 판단 | 놓친 조각은 다시 흘러옴 |
| 3 | 문장 구조 열차 | 철교 낱말 선택 후 이동 | **움직이는 열차 칸 건너기**: 낱말 칸이 열차와 함께 천천히 이동 | 어순에 맞는 칸으로 건너기. 다음 칸 단서가 예고로 보임 | 틀린 칸은 막히거나 흔들려 다시 선택(떨어지지 않음) |
| 3 | 색과 빛의 미술 공방 | 첫 체험 보존 결정([18][19]) | 변경하지 않음 | — | — |
| 3 | 태양계, 바람마을, 산과 염기, 거대 실험실, 인체, 그림자 극장 | 이미 이동 변화가 있거나 관찰이 먼저([45]) | 교실 관찰 뒤 판단 | — | — |

자석 항구·씨앗 구조대·문장 구조 열차는 최근 만든 맵이라 첫 교사 시험(화면·iPad) 뒤에 보완 범위를 정한다.

## 3. 추천 순서

1. **도형 건축 연구소 「구멍 벽」**: [45]에서 남긴 가장 큰 숙제(3지선다형)를 이동 판단으로 바꾼다. 도형 모양을 보고 맞는 구멍으로 가므로 학습이 이동 선택이 된다.
2. **전기 회로 공장 「기어 징검다리」**: 교실에서 문제로 확인된 협동 대기를 줄이는 방향이다. 필수 협동을 늘리지 않는다.
3. **로봇 도시 「배송 벨트」**: 명령 → 경로 → 이동의 연결을 강화한다.

## 4. 공통 구현 원칙 (모든 보완)

- 회전·이동은 시간 `t`로만 위치를 정한다(모든 화면이 같게). 새 장치는 파일 맨 위 상수에 속도·주기를 모은다.
- 예고(발광, 그림자, 신호 발판)를 장애물이 움직이기 전에 보이게 한다.
- 장애물과 부딪히면 **밀려나는 거리를 제한**하고 안전 바닥을 둔다. 밀려서 떨어지면 안 되는 구간은 가장자리에 낮은 벽을 둔다.
- 새 조작 발판은 "올라선 순간 한 번"(`onStand`는 매 프레임 불림), 체크포인트는 움직이는 장치와 겹치지 않게 한다(`map-rules.mjs` 자동 검사).
- 각 맵의 시험에 **봇이 걸어서** 기본 길 완주, 장애물을 맞아도 복귀, 별 도달을 넣는다. 자동 시험은 규칙·이동 검증일 뿐 재미의 증거가 아니다.
- 기록에는 docs/19 점검표, 교실에서 볼 장면(장애물을 읽고 기다리는지, 반복 실패해도 포기하지 않는지), 미확인 항목을 적는다.

## 5. 미확인

- 이 문서의 모든 "연결"과 "기대"는 설계 판단이다. 학생 반응, 화면(PC·iPad)에서의 가독성, 터치 조작은 확인하지 않았다.
- 회전 장치와 21명 동시 접속에서 화면 간 위치 일치는 구현 뒤 확인해야 한다.
- 폴 가이즈 자료는 사용자가 붙여 넣은 위키 설명이다. 라운드별 판정·수치는 확인하지 않았고 이동 아이디어 참고용으로만 썼다. 블로그 링크는 열어 보지 않았다.

# 43. 교실 관찰 요약표와 판단 기준 (2026-10-02 기준)

- 작성일: 2026-10-02, 담당: Claude. 근거: [33](33-작업-계획-2026-10-02.md) 4단계, [12](12-교실-시험-관찰지.md) 7·8절(활동별 상세 관찰 항목), [19](19-게임성-반영-기준.md).
- 목적: 오늘 추가한 선택 활동과 새 맵이 많아 한 번의 수업에서 전부 볼 수 없다. **먼저 볼 장면을 추리고**, 결과를 받았을 때 활동을 유지·수정·삭제할 기준을 정해 둔다.
- 이 문서의 기준은 **제안**이다. 임계값(비율·횟수)은 근거가 없는 시작점이므로 교사와 조정하고, 첫 관찰 뒤 바꾼다. 지금까지 모든 활동은 코드·시험(규칙·이동)까지만 확인했고 재미·난이도·학습 효과는 교실에서 확인한 적이 없다.

## 1. 먼저 볼 장면 6개

한 수업(약 40분)에서 한 반이 맵 한두 개를 한다고 가정하고, 맵에 상관없이 아래 장면을 먼저 본다. 세부 항목은 맵별로 [12](12-교실-시험-관찰지.md)에 있다.

| 순서 | 장면 | 무엇을 기록하나 | 볼 수 있는 곳 |
|---|---|---|---|
| ① | **선택 활동을 하는가, 건너뛰는가** | 선택 활동을 한 학생 수 / 전체, 안 한 이유("몰랐다", "어려워 보였다", "관심 없다") | 전 맵의 선택 활동 |
| ② | **어디서 막히고 몇 번 떨어지는가** | 구간별 낙하·막힘(교사 화면의 기존 기능), 포기하는 학생 | 점프 연구소 시험 구간, 태양계(달 탑·화성 협곡·목성 패드), 물의 순환(빙하·눈 구름), 컨베이어 |
| ③ | **선택이 결과로 이어지는 것을 말로 설명하는가** | "~했더니 ~가 됐다"처럼 선택→결과를 자기 말로 말한 학생 수, 틀린 설명(오개념) | 공기 실험대, 물에 띄워 보기, 밝기 실험대, 햇빛·그늘 상승기, 산소 배달, 메아리·얼음 택배·로봇 도시 |
| ④ | **진짜 고민하는가, 아무 데나 고르는가** | 고르기 전에 비교·멈춤이 있는지, 항상 같은 선택만 하는지(지배 전략 여부), 시도하다 포기하는지 | 얼음 택배(포장·길), 메아리(스캔 뒤 통로), 로봇 도시(명령 순서), 화성 협곡(폭풍 타이밍) |
| ⑤ | **터치(iPad)·조작 부담** | 의도하지 않게 밟은 발판 횟수, 점프 간격·미끄러움이 터치로 어려운지, 글자 크기 | 발판 선택이 있는 모든 맵, 달 탑·징검다리·얼음 |
| ⑥ | **친구와의 연결** | 먼저 끝난 학생이 정답만 알려 주는지 경로·이유를 설명하는지, 같이 도전하는지 | 전 맵 |

기록할 때 **교사 보고, 학생 반응(관찰), 코드 기반 추정**을 구분한다. 한 학생의 한 번의 반응을 전체로 일반화하지 않는다.

| 목적 | 추천 맵 | 이유 |

## 4. 결과 해석과 판단 기준 (제안)

관찰 결과로 활동을 **유지 / 수정 / 보류 / 삭제**한다. 임계값은 첫 관찰 전의 시작점이다.

### 4.1 활동별 판단표

| 관찰 | 해석(가설) | 조치 |
|---|---|---|
| 선택 활동을 한 학생이 **거의 없다**(예: 20% 미만)이고 이유가 "몰랐다" | 안내가 약하다 | 안내판 위치·문구, 보상을 눈에 띄게. 활동은 유지 |
| 한 학생이 한 구간에서 **여러 번(예: 5회 이상) 떨어지고 포기**한다 | 난이도가 높거나 조작이 어렵다 | 해당 구간 값을 완화(`DIFFICULTY`, 틈·폭·속도), 체크포인트를 가깝게 |
| 대부분이 **한 번에 통과하고 지루하다**는 반응 | 너무 쉽다 | 시험 맵은 단계를 올린다. 일반 맵은 선택 결과를 늘리지 말고 유지 |
| 선택을 했지만 **결과를 설명하지 못한다** | 즉시 결과가 약하다 | 결과 표시를 눈에 띄게(애니메이션·소리·문구), 설명 문장을 짧게 |
| 학생이 **항상 같은 선택**(예: 항상 그늘 길)을 한다 | 지배 전략이거나 정답이 알려졌다 | 숫자 조정, 선택 비용·이득을 다시 설계 |
| **"해도 그만"** 이라는 반응이 많다(산소 배달 등) | 선택이 다음 행동으로 이어지지 않는다 | 보상·다음 행동과 연결(별·문·장면). 연결이 어려우면 보류 |
| **터치 오입력**이 잦다 | 발판 간격·크기 문제 | 발판 간격 확대, 안내 문구, 턱 추가 |
| 틀린 설명(**오개념**)이 반복된다 | 안내문·모형 표시 문제 | 해당 문구 수정(`docs/22` 방식), 즉시 수정 |
| 먼저 끝난 학생이 **정답만 알려 준다** | 선택 활동이 하나의 정답에 가깝다 | 정답이 여러 개인 구조로, 설명을 요구하는 질문 추가 |

### 4.2 결정 규칙

- **삭제**는 두 번 이상의 관찰(다른 반)에서 같은 문제가 확인되고, 수정으로도 해결되지 않을 때만 한다. 한 번의 관찰로 삭제하지 않는다.
- **수정**은 값·문구·표시처럼 작은 변경부터 한다. 구조 변경은 Codex와 조율한다(`kit.js` 공용화는 관찰 뒤에도 근거가 쌓일 때).
- **보류**는 관찰이 엇갈릴 때. 다음 반에서 같은 장면을 본다.
- 교사 보고는 조치의 출발점이지만 **학생 관찰과 구분**한다. 예: 바람마을 학습 내용은 교사 보고(충실함), 게임성은 아직 학생 관찰 없음.
- 자동 시험(통과 비율 포함)은 판단 근거로 쓰지 않는다. 봇 통과 비율은 규칙·이동이 막히지 않는지 보는 용도다.

### 4.3 `docs/14` 후속 후보와의 연결

- 도움 요청 표시(`docs/14` 7번): ②에서 "누가 막혔는지 교사가 못 찾는다"가 반복될 때만 검토한다.
- 공용 실험 장치 추출(`docs/14` 4번): 비슷한 구조(선택 발판→즉시 결과)가 다섯 곳 이상에서 유지될 때 검토한다. 이번 관찰에서 일부는 삭제·수정될 수 있으므로 그 전에는 하지 않는다.

## 5. 기록 틀 (수업 한 번당)

교사나 보조자가 장면마다 한 줄로 적을 수 있는 형식이다.

| 항목 | 적을 것 |
|---|---|
| 반·날짜·맵·단계 | 예: 5-2, 10/○, 점프 연구소(기본) |
| 학생 수·기기 | PC/iPad, 접속 인원 |
| 장면 번호(①~⑥) | |
| 관찰(사실) | 보고 들은 것만. 예: "달 탑에서 3명이 5회 이상 떨어지고 2명 포기" |
| 학생 말(그대로) | 설명이나 불만의 원문 |
| 근거 구분 | 교사 보고 / 학생 관찰 / 코드 추정 |
| 해석(가설) | 위 4.1 표의 해석. 단정하지 않는다 |
| 조치 후보 | 4.1 표의 조치. 실제 변경은 기록 뒤에 결정 |

수업 뒤 질문(맵당 1~2개, [12](12-교실-시험-관찰지.md) 3절)과 "다시 하고 싶은 구간과 이유", "재미가 줄었던 순간"을 함께 묻는다. 첫 체험과 재체험을 구분해 적는다.

## 6. 아직 확인하지 못한 것

- 모든 활동의 화면(PC·iPad) 가독성, 터치 조작, 실제 교실 반응, 학습 효과.
- 교사가 시험 맵 단계를 실제로 고르는 흐름(맵 선택 화면에서 단계가 구분되어 보이는지).
- 위 임계값(20%·5회 등)의 적절함. 관찰 뒤 조정한다.

# 20. 스테이션 맵 게임성 보강 (연결 코스 + 매 판 다른 문제)

2026-10-01, Claude. 브랜치 `claude/gameplay`(`7a737af` 이후 커밋·푸시됨, **main에는 병합하지 않음**, Codex 검토 대기). 대상: 분수 피자, 색과 빛의 미술 공방, 도형 건축 연구소. 기준: [18. 전체 맵 게임성 분석](18-전체맵-게임성-분석.md), [19. 게임성 반영 기준](19-게임성-반영-기준.md). 이 문서의 이전 번호는 17이었으나 그림자 극장 기록이 사용해 20으로 옮겼다.

## 왜

새 맵은 "발판에 서기"만 하는 스테이션(방)을 이어 붙인 구조였다. 코드에서 확인한 사실: 세 맵이 같은 틀(24칸 방 + 선택 발판 + 문 열림)이고, 방 사이는 이어진 바닥이라 달리기·점프·타이밍이 쓰이지 않았으며, 정답이 매 판 같았다. 교사는 미술 공방이 좋은 반응이었다고 보고했고 같은 반이 다시 하면 지루할 것 같다고 예상했다(재진행 결과는 아님). 이번 변경은 퍼즐은 그대로 두고 (1) 방 사이를 움직임 구간으로 채우고 (2) 판마다 문제를 바꾼다. 재미와 학습 효과는 교실에서만 판단할 수 있다.

## 1. 방 사이 연결 코스 (`src/levels/course.js`, 신규)

- 방과 방 사이 27m를 채운다(`CONNECTOR_LENGTH = 26`, 방 간격 `ROOM_STEP = 59`). 세 종류:
  - **회전 막대**: 넓은 판 위에서 맞아도 밀릴 뿐, 뛰어넘거나 때를 기다린다. 가운데 기둥이 있어 가운데 선으로는 못 간다.
  - **움직이는 발판**: 폭 5m, 좌우 ±2.6m로 오가고 틈은 1.5~2.5m. 떨어질 수 있다.
  - **가로 범퍼**: 사이로 지나가거나 뛰어넘는다. 맞아도 밀릴 뿐이다.
- 연결 코스 입구에 **체크포인트**를 두고 **도움 점프를 허용**한다(`noHelp` 없음). 퍼즐 방 체크포인트는 그대로 `noHelp`(개념 오답 보호). 떨어지면 방 뒤쪽이 아니라 연결 코스 입구로 돌아온다.
- 모든 움직임은 시간 `t`(방에서는 서버 시계)로 계산해 화면 간에 같다.
- 맵별 배치: 분수 피자 막대 → 움직이는 발판, 미술 공방 움직이는 발판 → 범퍼 → 막대, 도형 건축 범퍼 → 움직이는 발판 → 막대. HUD 구간 이름은 "연결 코스".
- 각 맵은 `level.course = { rooms, connectors, tail, goalZ }`를 내보내 시험이 경로를 만든다.

## 2. 매 판 다른 문제 (`src/levels/variants.js`, 신규)

문제는 **시드**로 정한다. 시드는 방의 모든 학생이 같고 새 경기마다 바뀐다.

| 맵 | 바뀌는 것 | 후보 | 조합 수 |
|---|---|---|---|
| 분수 피자 | 주문량 | 주문 1: 1/4·1/2, 주문 2: 1/2·3/4, 주문 3: 3/4·한 판 | 8 |
| 미술 공방 | 목표 색 | 물감 두 방은 서로 다른 두 색 섞기(파랑·초록·빨강 중), 빛 첫 무대는 두 색(노랑·자홍·청록 중), 마지막 빛은 흰색 고정 | 18 |
| 도형 건축 | 전개도 보기·대칭 문제 | 전개도: 정육면체가 되는 5개와 되지 않는 6개 풀에서 방마다 정답 1·오답 2, 두 방이 다른 전개도, 자리 섞임. 대칭: 출발점·기준선 반사, 오답 둘(한 칸 어긋난 점, 두 기준선을 거친 점 등) | 매우 많음 |

- 제목·목표 견본·HUD 구간 이름이 문제에 맞게 바뀐다(`dynamicSign`). 도형 건축은 전개도 모델을 새 경기마다 다시 만들고 이전 모델을 치운다(장면이 불어나지 않음을 시험).
- 과학·수학 정확성: 전개도의 유효 여부는 기존 `analyzeCubeNet`이 판정하며 35개 헥소미노 중 11개가 정육면체 전개도라는 독립 기준과 맞는다(기존 시험). 새 후보도 모두 시험으로 유효·무효를 확인했다. 분수 주문량은 8분의 몇 판이며 조각(1/2·1/4·1/8)으로 모두 만들 수 있다. 미술 공방의 색 혼합은 기존과 같은 가상 모형이다.

### "매 판 반드시 다른 문제"는 보장하지 않는다

- 시드가 정하는 것은 **후보 안의 선택**이다. 후보가 적은 분수 피자(8가지)와 미술 공방(18가지)에서는 **다음 판에도 같은 문제가 나올 수 있다**(우연히 같은 시드 결과). 도형 건축은 조합이 많아 같은 문제가 나올 확률이 낮지만 0은 아니다.
- 이전 판 문제를 피하는 장치는 만들지 않았다. 화면마다 이전 판을 기억하는 정도가 달라(재접속 등) 같은 방의 학생들이 서로 다른 문제를 보게 될 위험이 있기 때문이다.
- 보기 위치(전개도·대칭 보기 순서)가 바뀌는 것은 새로운 판단으로 계산하지 않는다. 문제가 실제로 달라지는 것(다른 전개도, 다른 출발점·기준선, 다른 주문량·목표 색)만 변형으로 본다.
- 같은 방의 답 공유는 허용한다(같은 판의 문제가 같음). 학생마다 다른 문제는 만들지 않았다.

## 게임성 점검표 ([19](19-게임성-반영-기준.md) 기준)

| 항목 | 기록 |
|---|---|
| 핵심 재미 | 퍼즐 방의 선택·결과 확인은 그대로 두고, 방 사이를 달리기·점프·타이밍 구간으로 바꿔 퍼즐과 움직임이 번갈아 나온다 |
| 의미 있는 선택 | 연결 코스에는 개념 선택이 없다(휴식·움직임 구간). 퍼즐 방의 선택은 기존 그대로다. 연결 코스에서의 선택은 타이밍·통과 방식뿐이다 |
| 즉시 결과 | 장애물에 맞으면 밀리고, 움직이는 발판에서 떨어지면 연결 코스 입구로 돌아온다(몸으로 바로 알 수 있음). 문제 변형에서는 제목·목표 견본·주문량 그림이 즉시 바뀐다 |
| 다음 행동·성취 | 연결 코스의 결과(통과)는 다음 퍼즐 방에 도착하는 것이다. **퍼즐 결과가 다음 활동에 쓰이는 방향(docs/18 개선 방향)은 이번 범위가 아니며 구현하지 않았다** |
| 구간 변화 | 방 사이 장애물이 맵마다 다른 순서로 바뀐다. 퍼즐 요구는 시드마다 달라진다(단, 구조는 같음) |
| 재시도 부담 | 연결 코스 입구 체크포인트 + 도움 점프(3번 떨어지면). 장애물 맞음은 밀림뿐. 퍼즐 방 왕복·대기는 이번에 바꾸지 않았다. 연결 코스 때문에 퍼즐 방 도착까지 거리가 늘었다(방 3개 맵 2구간, 방 4개 맵 3구간, 구간당 27m) |
| 기본 완주·선택 도전 | **연결 코스는 기본 완주 경로에 있다.** 정밀 조작을 기본 조건으로 늘리지 않으려 했으나 이동 조건이 추가된 것은 사실이다. 완화: 도움 점프, 입구 체크포인트, 막대·범퍼는 밀릴 뿐, 움직이는 발판 틈 1.5~2.5m. 점프+다이브 연속 조작은 요구하지 않는다. 그래도 점프 경험이 적은 학생에게는 막힐 수 있다 `[추론]`. 안전 선택 경로(장애물을 피해 가는 길)는 만들지 않았고 후속 후보다 |
| 친구와의 연결 | 연결 코스의 타이밍을 먼저 지난 학생이 말로 알려 줄 수 있다 `[추정, 교실 관찰 필요]`. 필수 협동·동시 조작은 없다 |
| 재체험 용도 | 문제 변형은 후보 안의 선택이며 같은 문제가 다시 나올 수 있다(위). 첫 체험용 구조는 유지한다 |
| 근거·관찰 | 아래 시험은 규칙·이동 확인이며 재미·학습 효과의 증거가 아니다. 교사 보고는 미술 공방 원본 구조에 대한 것이지 이번 변경에 대한 것이 아니다 |

## 확인하지 못한 것과 교실에서 볼 것

- **재미와 난이도**: 연결 코스가 퍼즐 사이의 **리듬**을 만드는지 초보자에게 **이동 부담만** 추가하는지는 구분해서 관찰해야 한다. 시험의 봇은 단순하다(회전 막대는 가운데를 비껴 걷고, 움직이는 발판은 일부 시각에서 한 번 떨어진다).
- **기본 경로의 반복 낙하·대기**: 연결 코스 입구 체크포인트에서 학생별 낙하 횟수, 도움 점프가 켜지는 비율, 3번 이상 떨어진 학생이 포기하거나 기다리는지, 연결 코스 때문에 퍼즐 방에 도착하는 시간이 얼마나 늘었는지.
- **퍼즐 흐름**: 연결 코스가 퍼즐 사이의 집중을 끊는지, 먼저 통과한 학생이 코스 앞에서 기다리거나 돕는지. 연결 코스를 쉬운 구간으로 느끼는 학생과 막히는 학생의 차이.
- **문제 변형**: 같은 반이 다시 했을 때 같은 문제가 나왔는지, 다른 문제가 새로운 판단을 요구했는지(보기 순서만 다른 경우는 제외).
- 아직 확인하지 못한 것: iPad 가독성·터치·FPS, 실제 Firebase 21명에서 움직임 동기화(`t`는 서버 시계 기준이며 실제 연결에서는 미확인).
- **개념 접근**: 연결 코스는 개념을 담지 않는다. 퍼즐 결과가 다음 이동·성취로 이어지는 변경(docs/18, 문서 14의 방향)은 이번 범위가 아니다.

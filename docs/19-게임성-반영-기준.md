# 19. 맵 수정·차기 제작의 게임성 반영 기준

2026-10-01. 사용자가 [18. 전체 맵 게임성 분석](18-전체맵-게임성-분석.md)을 기존 맵 수정과 차기 맵 제작에 꼭 반영하도록 요청했다. 아래 기준은 이후 작업의 설계·검토 항목으로 적용한다. 이 문서에서 기존 맵의 기능을 일괄 수정한 것은 아니다.

## 적용 절차

1. 작업 전에 해당 맵의 18번 분석을 읽고 유지할 재미와 고칠 약점을 정한다.
2. 설계 기록에 아래 점검표를 작성한다. 새 맵은 기존 맵과 실제 행동이 어떻게 다른지도 쓴다.
3. 구현 뒤 규칙·이동 시험과 화면 확인을 한다. 설계와 구현의 차이, 미확인 사항을 기록한다.
4. 교실에서 관찰할 장면을 정해 [12. 관찰지](12-교실-시험-관찰지.md)에 따라 확인한다. 재미는 자동 시험 통과로 판정하지 않는다.

분석 → 설계 반영 → 구현 확인 → 교실 관찰로 연결한다. 모든 맵을 같은 장치 구조로 만드는 공용화는 피하고 상태·초기화 등 공통 부분의 재사용과 맵 고유의 플레이를 구분한다.

## 제작·수정 기록에 넣을 점검표

| 항목 | 기록할 내용 |
|---|---|
| 핵심 재미 | 학생이 즐길 행동을 한 문장으로 쓴다. 이동·탐험 중심 맵도 인정한다. |
| 의미 있는 선택 | 무엇을 보고 무엇을 고르는지, 선택별 결과가 어떻게 다른지 쓴다. |
| 즉시 결과 | 설명을 읽기 전에 화면·이동·물체에서 알아볼 수 있는 변화를 쓴다. |
| 다음 행동·성취 | 만든 결과가 다음 이동·배송·공연·탐험 등에 어떻게 쓰이는지 쓴다. 단순 통과 문이면 이유를 쓴다. |
| 구간 변화 | 뒤 구간에서 새로 요구하는 행동·원리 조합을 쓴다. 같은 입력의 횟수 증가만으로 대신하지 않는다. |
| 재시도 부담 | 오답·조작 실패 뒤 복귀, 불필요한 왕복·대기, 터치 오입력 가능성을 점검한다. |
| 기본 완주·선택 도전 | 추가 활동을 안 해도 완주되는지 확인한다. 정밀 조작과 동시 협동을 기본 조건으로 늘리지 않는다. |
| 친구와의 연결 | 설명·자발적 도움·함께 성공의 기회와 기다리는 학생의 행동을 쓴다. |
| 재체험 용도 | 첫 체험용인지, 반복 시 무엇이 달라지는지 쓴다. 보기 위치 변경을 새로운 판단으로 계산하지 않는다. |
| 근거·관찰 | 코드 확인, 교사 보고, 예상 반응을 구분하고 다음 교실에서 볼 장면을 쓴다. |

문서상 반영 여부와 기능 구현 여부를 분리한다. 아직 구현하지 않은 개선을 완료로 표시하지 않는다.

## 기존 맵 수정에 적용

기존 맵 수정 담당은 Claude를 유지한다. [14. 수정 후보](14-기존맵-수정후보.md)와 [15. 산·염기 요청서](15-산염기-시험장치-구현요청.md)를 아래 게임성 기준과 함께 사용한다.

| 맵 | 유지할 재미 | 수정 시 반영할 방향 | 상태 |
|---|---|---|---|
| 점프 연구소 | 다양한 장애물·숙련·숨은 길 | 반복 낙하와 시소 혼잡을 관찰하고 안전 선택 경로·짧은 구간 도전 검토 | 게임성 시험 맵으로 확장·난이도 상향([31](31-점프연구소-시험코스.md)). 시소 안전 길(외길) 구현([32](32-시소안전길-달높이뛰기.md)) |
| 태양계 | 환경에 따라 달라지는 점프 | 중력을 이용하는 경로 선택을 살리고 문에서 흐름이 끊기는지 확인 | 달 높이뛰기 탑 구현(선택, [32](32-시소안전길-달높이뛰기.md)). 목성·화성 활용은 후속 |
| 산과 염기 | 색을 판단해 실제 길 고르기 | 안전 실험 → 결과 확인 → 기존 길 선택. 새 실험을 필수 관문으로 만들지 않기 | 다음 기존 맵 구현 대상 |
| 전기 회로 | 친구와 회로를 잇고 전구 켜기 | 대기·역할 교대 관찰. 후반의 `확장 도전` 안내와 필수 통과 조건 불일치 해소 후보 | 확장 도전 선택화·밝기 실험대 구현([30](30-전기회로-확장도전-정리.md)). 대기·역할 교대는 관찰 후 |
| 물의 순환 | 구름·동굴 여행 | 환경 조건을 선택하면 이동 결과가 달라지는 한 구간 검토 | 증발 상승기 구현(선택 지름길, [24](24-물의순환-증발상승기.md)). 갈림길 선택은 후속 |
| 거대 실험실 | 큰 기구 사이 이동 | 힘 조절 결과로 피스톤 높이를 만들고 이동에 활용 | 공기 실험대 구현(선택 도전, [23](23-거대실험실-공기실험대.md)). 부력 구간은 후속 |
| 인체 | 몸속 탐험 | 전달 대상 선택 → 세포·근육 반응으로 작은 임무 만들기 | 산소 배달 구현(선택, [27](27-인체-산소배달.md)). 보상 연결은 후속 |
| 분수 피자 | 같은 양의 여러 조합 | 완료 뒤 다른 조합을 시험하는 선택 활동·포장 보상 검토 | 재체험 수요 확인 후 |
| 미술 공방 | 자유 조합·즉시 변화·서로 설명 | 첫 체험 보존. 작품 요청·자유 제작은 재체험이 필요할 때 검토 | 다른 반 관찰 우선 |
| 도형 연구소 | 실제 접기·길 생성 | 면 수정·점 직접 배치 등 선택 도전 검토 | 후속 후보 |
| 바람마을 | 몸으로 느끼는 바람·경로 선택 | 순풍이 새로운 경로·이동 이득을 만드는지 관찰. 해안 왕복의 보상 상쇄 검토 | 순풍 도약 구현([26](26-바람마을-순풍도약.md)). 해안 정리는 교실 관찰 후 |
| 그림자 극장 | 조작 → 실루엣 변화 → 수정 | 마지막 그림자가 공연 장면에 쓰이도록 완성 보상 강화 | Codex 후속 조정 후보 |

모든 후보의 동시 구현을 요구하지 않는다. 이번에 확정한 것은 게임성 기준의 적용이며, 기존 우선순위와 담당을 유지한다.

## 차기 맵 제작에 적용

새 맵 담당은 Codex다. 제작 순서는 그림자 극장 첫 버전 완료 → 명령 택배 로봇 도시 → 열을 지키는 얼음 택배다.

### 명령 택배 로봇 도시

- 핵심 재미: 내가 만든 명령을 로봇이 실제로 수행하며 도시를 돌아다니고 배송한다.
- 명령 입력 후 현재 명령·로봇 방향·지나온 길을 함께 보여 준다. 잘못 움직인 지점이 수정할 단서가 된다.
- 첫 구간은 짧은 배송, 다음은 회전, 이후 반복·복수 경로로 요구를 바꾼다. 입력 발판 왕복만 늘리지 않는다.
- 배송 성공이 소포 도착·도시의 변화·다음 이동로 작동으로 이어진다. 정답 확인 문만 열고 끝내지 않는다.
- 기본 배송에는 여러 성공 경로를 인정하고 최단 명령은 선택 도전으로 둔다. 오류는 로봇 경로를 되돌려 빠르게 수정하며 학생을 떨어뜨리지 않는다.
- 관찰: 학생이 실행 장면을 보고 명령을 고치는지, 긴 명령으로도 성취하는지, 배송 뒤 다른 경로를 시도하는지.

### 열을 지키는 얼음 택배

- 핵심 재미: 포장·경로 선택에 따라 달라지는 화물 상태를 보며 배달 계획을 세운다.
- 고정 시간의 안전 시험으로 재료 차이를 먼저 비교한다. 실제 배송은 화물 상태와 도착 장면을 보여 준다.
- 경로에는 그늘·햇빛·거리 등 판단할 차이를 둔다. 자동으로 녹는 것을 오래 기다리는 활동으로 만들지 않는다.
- 조작 속도만으로 성패를 정하지 않는다. 기본 완주가 가능하도록 복구 지점을 두고 추가 보존 목표는 선택으로 둔다.
- 첫 버전의 시간·재료 변화는 게임 모형으로 표시한다. 과학 조건과 게임 과장을 구분한다.
- 관찰: 포장 시험을 근거로 경로를 고르는지, 화물 상태를 보고 계획을 수정하는지, 재시도가 부담이 되는지.

## Claude 인수인계에 포함할 문구

> 기존 맵 수정 시 docs/18의 맵별 게임성 분석과 docs/19의 점검표를 함께 적용해 주세요. 산·염기는 안전한 실험 결과를 실제 길 선택에 활용하는 흐름을 우선합니다. 맵별 이동·탐험·회로 조작의 정체성을 보존하고, 공용 실험판과 문 열기 구조를 모든 맵에 반복하지 않습니다. 인수인계에는 유지한 재미, 선택 결과와 다음 행동, 왕복·대기·재시도 부담, 선택 도전의 실제 우회 가능성, 교실에서 확인할 항목을 기록해 주세요. 자동 시험과 실제 재미 검증은 구분합니다.

이 문구는 저장한 인수인계 기준이며 외부 메시지 도구로 전송하지 않았다.

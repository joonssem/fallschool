# 37. 점프 연구소 시험장: 난이도 단계 (쉬움·기본·어려움)

- 작성일: 2026-10-02, 담당: Claude (기존 맵 수정). 근거: [33](33-작업-계획-2026-10-02.md) 3단계, [31](31-점프연구소-시험코스.md)
- 상태: **코드 구현·규칙 시험 완료. 단계별 난이도가 실제로 적절한지는 미확인(교실 관찰 전).**

## 범위 확인 결과 (database.rules 변경 없음)

- 방 설정은 `rooms/{code}/meta`(`mapId`, `seed`, `phase` 등)이고 `database.rules.json`이 `meta`의 허용 필드를 고정한다(`"$other": { ".validate": false }`). 새 필드(예: `difficulty`)를 `meta`에 쓰려면 **규칙을 바꾸고 Firebase에 배포**해야 하고, 규칙이 배포되기 전에는 쓰기가 거절되어 교사가 단계를 못 고른다. 기존 방과 호환 영향도 생긴다.
- 그래서 **맵 id로 단계를 고르는 방식**을 택했다. `mapId`는 `^[a-z]{1,16}$`만 허용하므로 `labeasy`, `labhard`가 그대로 통과한다. 규칙·Firebase 데이터 구조·교사 화면 코드를 바꾸지 않는다. 맵 선택 화면이 맵 목록을 보여 주므로 교사는 "점프 연구소 시험장 (쉬움/어려움)"을 기존 맵처럼 고르면 되고, 방의 모든 학생이 같은 단계를 받는다(`meta.mapId`가 모두에게 전달됨).
- 단점: 맵 목록에 연습 분류 항목이 3개가 된다. 단계 변경은 맵을 다시 고르는 것이라 경기 중간에 단계를 바꾸려면 새 경기를 시작해야 한다. 학생별 단계는 지원하지 않는다.

## 바뀐 것

- `src/level.js`: `buildLevel(parent, world, { seed, difficulty })`에 `difficulty`('easy'|'normal'|'hard', 기본 'normal')를 추가하고 단계별 값을 한 곳(`DIFFICULTY`)에 모았다. 기본 단계는 이전과 같은 값이다.
- `src/levels/index.js`: `labeasy`(쉬움), `labhard`(어려움) 항목을 추가했다. 기존 `lab`은 기본이다.
- `tests/lab.mjs`: 같은 시험을 세 단계에서 각각 돈다. 인자 없이 실행하면 기본을 돌고 이어서 쉬움·어려움을 자식 프로세스로 돈다(환경 변수 `LAB_DIFFICULTY`).
- 공통 파일 변경: `index.js`에 맵 항목 2개 추가(기존 맵 id·계약 변경 없음). `tests/robotcity.mjs`, `icetaxi.mjs`, `echodetective.mjs`의 `MAPS.length === N` 조건을 제거했다(맵 개수를 고정하면 항목을 더할 때마다 시험이 깨진다. 맵 등록 여부는 `mapById(...)`로 확인한다). `icetaxi.mjs`·`echodetective.mjs`는 Codex의 미커밋 파일이라 작업 트리에서만 바꾸었고 커밋하지 않았다.

## 시험 결과 (규칙·이동, 봇)

- 세 단계 모두 `tests/lab.mjs`(각 33건) 통과: 구간별 통과 가능성, 사라지는 발판은 어느 출발 시각에도 지나갈 경로가 있음(가능성 검사), 맞바람은 벽 뒤에서 쉬었다 달리면 지나감, 컨베이어는 단계별 속도로 밂.
- 봇의 출발 시각별 통과 비율(참고용): 해머 복도 쉬움 12/12, 기본 9/12, 어려움 8/12. 사라지는 발판(직진 봇) 쉬움 7/12, 기본 3/12, 어려움 3/12. 회전 막대(1부) 쉬움 9/12, 기본 8/12, 어려움 10/12(어려움이 더 높은 것은 봇의 출발 시각과 속도가 우연히 맞았기 때문이다 `[추정]`). **이 숫자는 단계의 난이도가 적절하다는 증거가 아니다.** 봇은 사람의 반응·터치 조작을 흉내 내지 못한다.
- 시험 중 발견: 어려움의 맞바람은 잔잔한 시간이 1.2초라 "1.3초 동안 잔잔한 때에만 달린다"는 봇 조건이 만족되지 않아 지나갈 수 없었다. 봇이 기다리는 길이를 잔잔한 시간보다 짧게 맞췄다. 사람은 짧은 틈에도 달릴 수 있다고 가정했으나 확인하지 않았다.

## 한계와 후속

- 단계를 학생별로 고르거나 경기 도중 바꾸는 것은 불가능하다. 필요하면 방 설정에 `difficulty`를 넣는 방식(규칙 변경·배포 필요)을 검토한다. 그때는 호환 영향과 규칙 시험(`firebase` 규칙 테스트가 있다면)을 먼저 확인한다.
- 단계 이름이 맵 이름에 들어가 교사 화면의 구간·낙하 기록에서 단계가 구분되지 않을 수 있다(맵 이름으로 구분). 교사 보고서에서 단계를 기록해야 한다.
- 어려움의 징검다리 마지막 틈(4.7m)은 달리기 점프의 한계에 가깝다(봇은 통과하지만 사람의 터치 조작은 미확인).

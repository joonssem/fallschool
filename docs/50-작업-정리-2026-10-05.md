## 3. 이날 정한 설계 원칙 (교사 의견 + 작업에서 확인한 것)

1. **맞게 판단하면 가장 쉽고 빠른 길이 열린다.** 틀리면 길이 막히지는 않지만 손해를 본다(교사 결정: 씨앗 구조대는 되돌아가기). "쉬운 길로 직진"과 "개념을 알고 고르기"가 같아야 게임성과 학습을 함께 잡는다.
2. **선택마다 이득과 대가를 둘 다 둔다.** 한 선택이 늘 유리하면 판단이 사라진다(얼음 택배 포장 C).
3. **결과를 다음 이동에 쓴다.** 결과판·문 열기로 끝내지 않는다(싹이 다리가 되고, 자석이 화물을 옮겨 길이 된다).
4. **숫자 정답을 보여 주지 않는다.** 숫자를 보여 주면 개념 없이 숫자 비교로 푼다. 말 단서와 방향 피드백("적어요/지나쳐요")을 쓴다.
5. **판단을 조건을 바꿔 여러 번 한다.** 한 정거장에서는 한 조건만 다르게 하고 나머지는 같게 둔다(변인 통제).
6. **시드로 배치를 바꿔 외워서 풀 수 없게 한다.** 보기 위치만 바뀌는 것은 새로운 판단으로 치지 않는다.
7. **다른 맵에서 검증된 장치를 빌려 온다.** 교사 의견(2026-10-05): "새로운 것만 넣기 어렵다면 다른 맵의 어울리는 게임성을 붙여 넣는 것도 좋다." 이날 빌려 쓴 장치는 흔들리는 발판, 막다른 굴, 무너지는/가라앉는 발판, 조건을 채우면 나타나는 별, 탄성 발판이다.
8. **맵 길이는 약 150~250m.** 교사 보고: 자석 항구·문장 구조 열차 첫 버전(약 80m)은 짧았다.
9. **조작 부담을 판단보다 크게 만들지 않는다.** 틀린 판단은 떨어뜨리지 않고, 떨어지는 실패는 선택 별 도전에만 둔다. 점프 틈은 전속력으로 뛰어도 다음 발판에 내려앉는 간격으로 정한다.

## 4. Codex–Claude 협업에서 확인한 것

- **분담**: 선생님 요청 → Claude가 계획서 작성(문서 48) → Codex가 기본 맵 제작 → Claude가 걸어서 확인하고 보완·재설계. 기존 맵 수정은 Claude, 새 맵 제작은 Codex라는 `AGENTS.md` 기본 분담과 같다.
- **"시험은 통과했는데 걸어서는 막힌다"**: 씨앗 구조대 첫 버전은 시험 25건을 통과했지만 걸어서는 완주할 수 없었다. 시험이 심기·물 조절 함수를 직접 불러서 확인했기 때문이다. **새 맵 시험은 봇이 실제로 걸어서 발판을 밟게 한다.**
- **자주 생긴 코드 문제**:
  - 발판의 `onStand`는 서 있는 동안 **매 프레임** 불린다. 조작 발판은 "올라선 순간 한 번"으로 만들고, 일정 거리 벗어나야 다시 반응하게 한다.
  - 발판이 다른 블록 안에 묻히거나(심기 발판), 체크포인트가 탄성 발판과 겹치면 걸어서는 문제가 드러난다.
  - 0.35m 높이의 턱도 뛰지 않으면 넘지 못한다. 걸어서 올라서는 곳은 0.15m 정도로 둔다.
  - 메시 크기(scale)를 바꾸면 충돌 상자도 함께 바뀐다. 모양 단서는 장식용 자식 메시로 만든다.
- **문서 번호**: Codex가 계획서와 같은 48번으로 기록을 써서 49번으로 옮겼다. 계획서에 기록 문서 번호를 미리 적어 두면 겹치지 않는다.
- **토큰 절약(작업 중 관찰, 측정 아님)**: 기존 코드를 읽는 비용보다 시험 실패 뒤 원인을 찾는 반복이 컸다. 구간마다 어떤 장치를 붙일지 구체적으로 요청하고, 검증된 장치를 재사용하고, 한 요청에 맵 하나씩 맡기면 반복이 줄어든다.

## 7. 맵 시험 규칙 자동화 (2026-10-05 사용자 요청: "맵 테스트 할 때 해당 내용이 실행되도록")

- 새 시험 `prototype/tests/map-rules.mjs`를 `npm test`에 넣었다. `index.js`에 등록된 **모든 맵**을 자동으로 검사한다(새 맵도 등록만 하면 검사됨). 약 12초 걸린다.
  1. 작은 발판(4.5m 이하) 위에 1.5초 서 있을 때 안내가 4번 이하인가 — 발판이 매 프레임 반응하는 문제(씨앗 구조대 첫 버전)
  2. 모든 체크포인트 부활 위치에 2초 서 있을 때 1.2m 넘게 튕기거나 1.5m 넘게 떨어지지 않는가
  3. 도전 별 10개 이하(데이터베이스 규칙)
  4. 맵 파일마다 그 파일을 불러와 봇이 `run(...)`으로 걷는 시험이 있는가
- 처음 돌렸을 때 기존 맵에서 **실제 문제 두 개**를 찾아 고쳤다.
  - 인체 '동맥' 체크포인트: 이날 넣은 적혈구가 부활 자리(z -66)를 지나가 부활하자마자 튕겨 떨어졌다. 혈류·적혈구를 z -70부터 시작하게 하고, 짧아진 만큼 미는 힘을 3.2 → 3.8로 올렸다(봇: 피하며 가운데 4.6초, 옆 5.4초, 곧장 6.5초 — 맞교환 유지).
  - 태양계 '화성 폭풍 앞' 체크포인트: 부활한 뒤 가만히 있으면 모래 폭풍에 밀려 떨어졌다. 첫 폭풍 구역을 z -129.5부터로 줄여 부활 자리 둘레는 바람이 닿지 않게 했다(화성 협곡 별 시험 결과는 그대로 3/6).
- `AGENTS.md`에 '맵 시험 규칙' 절을 추가했다: 위 자동 검사, 맵별 시험은 봇이 걸어서 확인(기본 완주·선택별 결과·틀린 선택 뒤 복귀·별 도달), 사람이 점검표에 적을 설계 확인 항목(맞게 판단하면 쉬운 길, 이득과 대가, 결과의 다음 이동 사용, 숫자 정답 비표시, 시드 변화, 길이 150~250m), 턱 높이·메시 크기 주의.
- 이 자동 검사는 **조작·안전 규칙만** 확인한다. "맞게 판단하면 쉬운 길인가" 같은 설계 판단은 맵마다 달라 자동으로 검사하지 않고, 맵별 시험과 점검표로 확인한다.

# 11. 바람마을 첫 버전

2026-10-01. 학생 아이디어 **아이엠가든 · 버블리**를 출발지 표지에 표시했다. Claude의 `wind.js` 계산 모듈을 사용해 Codex가 맵을 제작했다. 행성 맵을 좋아했다는 관찰은 사용자 제공 배경이며 이번 제작에서 학습 효과를 확인한 것은 아니다.

## 현재 동작 요약 (2026-10-06 기준, 기록 문서에서 정리)

- 학생 아이디어(아이엠가든·버블리)로 만든 바람 맵. 풍향계 입구 → 고기압·저기압 갈림길(순풍/역풍 길) → 상승·하강 기류 → 해풍·육풍 다리.
- 순풍 길에는 **바람 도약대**(별), 역풍 길에는 **연 발판**(별)이 있어 길마다 보상이 다르다. 역풍 길도 완주 가능.
- 바람은 `wind.js` 계산에서 나오며 화면의 바람 입자·깃발과 같은 값을 쓴다. 낮밤 반전은 서버 시계(`sharedTime`)에 맞춘다.
- 검증: 자동(`wind.mjs`, `windvillage.mjs`), 교사 확인 2026-10-02. 화면·iPad·21명 동시 접속의 낮밤 일치는 미확인.

## 구성

| 구간 | 체험과 판단 | 지원 |
|---|---|---|
| 풍향계 입구 | 빨간 풍향계 끝은 불어오는 쪽, 초록 화살표·깃발은 가는 쪽 | 넓은 길, 약한 바람 |
| 고기압·저기압 갈림길 | H/L 배치를 보고 순풍 길 선택. 두 길의 바람 방향이 반대 | 역풍 길도 같은 출구로 완주 가능 |
| 상승·하강 기류 | 저기압 쪽 상승·고기압 쪽 하강을 점과 움직이는 발판으로 표현 | 가운데 안전 계단, 상승 발판의 별은 선택 |
| 해풍·육풍 다리 | 바다와 육지를 두 번 가로질러 낮밤에 반전하는 바람 체험 | 넓은 통로·가장자리 난간, 역풍에도 걸어서 통과 |

- 낮밤 한 주기는 게임에서 32초. 반전 시 바람이 부드럽게 약해진다. 실제 하루 길이나 실제 날씨를 재현하는 값은 아니다.
- 바람 속도는 갈림길 최대 2.5m/s, 해안 최대 2.2m/s의 게임 이동값. 사람을 미는 힘은 과장이라고 안내한다.
- 네 체크포인트, 선택 도전 별 두 개, 탈락 없음. 다른 학생의 선택·접속 여부 때문에 길이 닫히는 장치가 없다. 풍차·필수 협동·태풍은 이번 범위에서 제외했다.
- 퀴즈 오답 낙하가 없어 `conceptFall`을 설정하지 않는다. 바람에 밀린 낙하도 도움 점프 계산에 포함한다. 도움 점프를 켜도 개념 문을 우회하는 문제가 없으며, 낙하 기록은 기존 방식이다.

## 계산과 과학 표현

- 수평 바람·화살표·풍향계·깃발·입자는 구간별 동일한 압력 원본과 `makeWindAt()`을 사용한다. `pressureAt()`으로 해안 H/L 관계와 낮밤 안내를 확인한다.
- 바람이 가는 쪽과 풍향(불어오는 쪽)을 반대로 표시한다. 고기압에서 저기압으로 향하는 수평 흐름은 지표 부근의 단순 모델이라고 설명한다.
- 상승·하강 발판과 수직 입자는 **별도 시각 장치**이다. 수평 `wind.js`가 수직 운동까지 계산한 것으로 표현하지 않는다. 발판이 되돌아오는 것은 운행 주기이며 공기의 실제 운동을 그대로 모사하지 않는다.
- "H/L이 가까울수록 바람이 세다"는 설명을 쓰지 않았다. 압력이 가파르게 변하는 곳에서 더 세다고 안내한다.
- 낮 해풍은 바다→육지, 밤 육풍은 육지→바다. 실제 바람은 더 큰 규모의 날씨·마찰·지구 자전 등의 영향도 받는다. 게임의 곧은 바람은 단순화이며 예보 계산이 아니다.
- 바람 입자는 공기 흐름을 보여 주는 표시다. 입자 위치는 각 화면의 프레임에 따라 다를 수 있지만, 현재 위치에서의 바람 방향과 낮밤 상태는 공유 시간 `t`에서 계산한다. 실제 21명 연결의 시계·위치 지연은 아직 확인하지 않았다.

표현 근거: [NWS 해풍 용어](https://marine.weather.gov/glossary.php?word=sea+breeze), [NWS 지표 고·저기압과 수직 운동](https://www.weather.gov/source/zhu/ZHU_Training_Page/winds/pressure_winds/Pressure.htm), [NWS 어린이 날씨 설명의 육풍](https://www.weather.gov/hfo/kids).

## 검증

- `tests/windvillage.mjs`: **52개 통과**. 두 갈림길의 방향, 낮밤 반전·전환 시 약풍, 구역 제한, 풍향계·깃발 표시 방향, 도움 점프 허용, 전체 경로(시드 3개 × 시작 시각 4개 × 길 2개)를 확인했다.
- 기존 시험을 포함해 `npm test`: **890개 통과**. 맵 목록은 11개, 메타데이터 시험은 36개이다.
- `tests/windvillage-visual.html`: 같은 맵을 입구·갈림길·기류·해안 시야와 고정 낮밤 시간으로 확인하는 개발 화면. PC에서 학생 닉네임·H/L·안전 계단·육풍 안내를 확인했고, 해안 안내판 위치를 조정했다.
- 미확인: iPad 글꼴·FPS·터치 조작, 실제 Firebase 21명 낮밤 동기화·재접속, 재미·학습 효과. PC 브라우저의 자동화 화면 FPS를 학생 기기의 성능 측정으로 사용하지 않는다.

## 교실에서 볼 것

1. "어느 길이 등을 밀어 줬나요? H와 L의 위치로 설명해 보세요." — 길 선택 이유를 말하는가.
2. "낮에 바다에서 육지로 갈 때와 밤에 갈 때 무엇이 달랐나요?" — 해풍·육풍 방향을 연결하는가.
3. 풍향계 빨간 끝과 화살표를 같은 방향으로 오해하는가, 반전을 기다리느라 멈추는 시간이 긴가.
4. 역풍·바람다리에서 떨어짐과 도움 점프 빈도, 안전 계단·도전 별 선택, 마지막 학생도 완주 가능한가.

학생 H/L 지도 그리기는 후속 활동 후보이며 활동지·수업 적용은 아직 제작하지 않았다.

## Claude 검토 인수인계 (2026-10-01)

동적 안내판 `board()`에 Apple SD Gothic Neo 글꼴을 추가하고 720px 폭을 넘으면 최소 22px까지 줄이도록 수정했다. Windows 안내판 549줄 실측에서 잘리는 줄이 없다는 결과는 Claude의 보고이며 Codex가 다시 실측한 것은 아니다. iPad 가독성은 여전히 실기 확인이 필요하다.

| Claude 봇 측정 구간 | 도움이 되는 바람 | 방해가 되는 바람 |
|---|---|---|
| 갈림길 33m | 3.9초 | 6.1초 |
| 해안 다리 한 번 횡단 17m | 2.0초 | 3.5초 |

보고된 최고 속도 봇의 해안 왕복 경로는 낮·밤 모두 12.14초였다. 한 번 횡단에서 느끼는 차이가 전체 경로에서는 상쇄될 수 있어, 기다리면 완주가 빨라진다는 보상은 확인되지 않았다. 학생의 조작·출발 시각·관찰 행동에 따라 결과가 달라질 수 있으므로 모든 플레이의 시간이 같다고 일반화하지 않는다.

이번에는 길·바람 세기를 유지한다. 첫 교실 시험에서 H/L을 근거로 길을 고르는지, 한 번 횡단의 순풍·역풍을 구별하는지, 친구에게 이유를 설명하는지를 본다. 한 방향 횡단이나 기다림 보상 추가는 교실 결과를 본 뒤 결정한다. 추가 관찰 항목은 [12. 교실 시험 관찰지](12-교실-시험-관찰지.md)에 있다.

# 점프 연구소 시험장 (조작·맵 시제품)

교과 연결 없이 **게임성과 캐릭터 조작감**만 확인하기 위한 1인용 시제품이다. Three.js 기반이고 빌드 과정이 없다.

## 실행

**배포 주소 (GitHub Pages)**: https://joonssem.github.io/fallschool/prototype/
`main` 브랜치에 푸시하면 1~2분 뒤 자동으로 갱신된다.

PC에서 수정하며 시험할 때:

```bash
# prototype 폴더에서
python -m http.server 8000 --bind 0.0.0.0
```

- PC: `http://localhost:8000`
- iPad: 같은 와이파이에서 `http://<PC의 IP 주소>:8000` (Windows에서 `ipconfig`로 IPv4 주소 확인)
  - 처음 실행 시 Windows 방화벽 허용 창이 뜨면 "개인 네트워크" 허용
- Three.js는 `cdn.jsdelivr.net`에서 불러오므로 인터넷 연결이 필요하다.

## 멀티플레이 (교실 모드)

시작 화면에서 세 가지 중 하나를 고른다.

| 선택 | 누가 | 하는 일 |
|---|---|---|
| **참가하기** | 학생 | 방 번호 4자리 + 이름 + 색깔로 입장 |
| **선생님: 방 만들기** | 교사 | 선생님 코드 입력 → 방 번호·QR 코드가 있는 교사 화면 |
| **혼자 연습하기** | 누구나 | 네트워크 없이 1인 플레이 |

### 수업 흐름

1. 교사가 방을 만들고 전자칠판에 교사 화면(방 번호·QR)을 띄운다.
2. 학생이 QR로 접속하면 방 번호가 채워져 있다. 이름만 쓰고 참가한다.
3. **대기실**: 학생들은 코스를 자유롭게 연습한다 (기록 없음).
4. **출발!** → 모두 출발선으로 돌아가고 카운트다운 후 경기가 시작된다. 숨은 발판의 진짜 길은 경기마다 새로 정해진다.
5. 경기 중 교사 화면에서 학생별 위치(구간)·떨어진 횟수·완주 기록을 본다. 이름을 누르면 그 학생을 따라가며 본다.
6. **얼음!** → 모든 학생 조작이 멈추고 "선생님 말씀을 들어요" 화면이 뜬다.
7. **경기 끝** → 학생 화면에 "우리 반 완주 n / 전체" 결과가 뜬다. **대기실로** → 다시 자유 연습.

학생 화면에는 개인 순위를 보여 주지 않고 **학급 완주 인원**만 보여 준다. 완주 기록 순 목록은 교사 화면에만 있다.

### 함께 하는 요소

- 다른 학생 캐릭터와 이름표가 보인다 (서로 부딪히지는 않음).
- **숨은 발판은 모두에게 함께 무너진다.** 누군가 가짜 발판을 밟으면 모든 화면에서 그 발판이 떨어져, 친구의 실패를 보고 길을 찾을 수 있다.
- 움직이는 장애물(회전 막대, 발판, 바람)은 서버 시계에 맞춰 모든 화면에서 같은 순간에 같은 위치에 있다.
- 시소 기울기는 각자 화면에서 따로 계산한다 (다른 학생이 시소 위에 있을 때 조금 어긋나 보일 수 있음).

### 데이터 구조 (Firebase Realtime Database)

교실 대소동(`eraser-6bb35`)과 같은 프로젝트를 쓰되, 모든 데이터는 `fallschool/` 아래에만 쓴다.

```
fallschool/rooms/{방번호}
  meta              [저빈도] 교사만 씀: phase(LOBBY|RACE|RESULT), race, seed, startAt, frozen, epoch
  players/{uid}     [중빈도] 학생 자기 것만: name, color, race, cp, falls, finish(ms)
  pos/{uid}         [고빈도] "x,y,z,방향,상태" 문자열, 초당 최대 10회, 거의 안 움직이면 생략
  presence/{uid}    접속 표시, 연결이 끊기면 서버가 자동 삭제(onDisconnect)
  tiles/{race}/{i}  숨은 발판이 무너진 시각
```

- 전송량 추정: 21명이 **계속 움직이는 최악의 경우** 방 전체 다운로드가 시간당 약 1GB 수준 (계산값, 실측 필요)
- 학교망에서 웹소켓이 막히면 주소 끝에 `&lp`를 붙여 강제 롱폴링으로 접속한다.

### 시험용 모의 백엔드

주소에 `?net=local`을 붙이면 Firebase 대신 **같은 브라우저의 탭끼리** 통신하는 모의 백엔드를 쓴다. PC 한 대에서 교사 탭 1개 + 학생 탭 여러 개로 흐름을 시험할 수 있다.

- 예: `http://localhost:8000/?net=local` (교사) / `http://localhost:8000/?net=local&room=1234` (학생)
- 한계: 탭을 닫아도 접속 목록에서 바로 빠지지 않을 수 있다 (Firebase에서는 서버가 처리). 백그라운드 탭은 화면 갱신이 멈춘다.

## 맵

시작 화면에서 맵을 고른다 (혼자 연습·방 만들기). 교사는 대기실·결과 화면에서 맵을 바꿀 수 있고, 모든 학생 화면이 따라 바뀐다. 경기 중에는 바꿀 수 없다. 시험용 주소 `?map=solar`.

| id | 이름 | 특징 |
|---|---|---|
| `lab` | 점프 연구소 시험장 | 아래 표의 장애물 코스 |
| `solar` | 태양계 중력 달리기 | 구역마다 중력이 다르다 (아래) |
| `acid` | 산과 염기 실험실 | 지시약 색 변화를 알아야 길을 고른다 (아래) |
| `circuit` | 전기 회로 공장 | 스위치 발판으로 회로를 잇는 협동 코스 (아래) |

### 태양계 중력 달리기 (`src/levels/solar.js`)

| 구역 | 게임 중력 (실제) | 점프 높이 | 메커닉 |
|---|---|---|---|
| 지구 발사대 | ×1 | 1.8m | 계단, 로켓 패드로 달까지 발사 |
| 달 크레이터 | ×0.33 (약 1/6) | 5.6m | 약 16m를 날아가는 점프, 지구에서는 못 넘는 3.5m 벽 |
| 화성 모래 폭풍 | ×0.45 (0.38) | 4.1m | 4초 주기 모래바람, 바위 옆에서 버티기 |
| 소행성대 | ×0.5 | 3.7m | 가운데 바위 딛고 건너기, 아래에 궤도를 도는 안전망 발판, 굴러다니는 소행성 |
| 목성 소용돌이 | ×1.6 (약 2.5) | 1.1m | 도는 정팔각형 판, 낮은 점프로 겨우 오르는 붙은 계단 |
| 토성 고리 | ×0.9 (1.07) | 2.0m | 다리를 건너며 도는 고리 조각을 뛰어넘거나 틈으로 지나기 |
| 우주 정거장 | ×1 | — | 골인 |

- 실제 중력을 그대로 쓰면 달에서는 조작이 어렵고 목성에서는 거의 뛸 수 없어 게임용으로 조정했다. 구역 안내판에 실제 값과 게임 값을 함께 적었다. 행성 크기·거리도 과장되어 있다.
- **예측 문** (달·화성·목성·토성 입구): 벽에 커튼 문 3개와 질문("달에서 점프하면 어떻게 될까?")이 있다. 맞는 보기의 문 뒤에만 바닥이 있고, 틀린 문으로 들어가면 떨어져 체크포인트에서 다시 고른다. 문을 지나면 화면에 정답 설명이나 다시 생각할 힌트가 뜬다.
  - 조작 실력이 아니라 **중력에 대한 판단**으로 통과하게 하려는 장치다 (9/29 교실 시험에서 대다수가 중력 차이를 조작 실력으로만 넘었다).
  - 정답 문 위치는 경기마다 섞인다 (같은 방은 모두 같은 배치). 벽이 높고 넓으며 통로에 지붕이 있어 달 중력 점프로도 돌아갈 수 없다.
  - 실제 중력 안내판은 문 뒤에 있다: 예측 → 몸으로 확인 → 실제 값 확인.
  - 토성 문은 "크면 중력도 세다"는 생각을 뒤집는 문제다 (토성은 목성 다음으로 크지만 밀도가 물보다 낮아 중력이 지구와 비슷하다).
- 지구 발사대의 둘째 틈을 6m → 3m로 줄였다 (보통 점프로 넘는다. 예전에는 점프 + 다이브가 필요해 처음 하는 학생이 막혔다).
- 예측 문은 맵 공용 도구 `choiceGate()`(`src/levels/kit.js`)로 만든다. 다른 맵에서도 같은 방식으로 쓴다.
- 시뮬레이션 통과율: 로켓→달 3/3, 달 점프 4/4·4/5·벽 4/4, 화성 8/8, 소행성대 12/12·출구 8/12, 목성 18/18, 토성→골인 20/20

### 산과 염기 실험실 (`src/levels/acid.js`)

조작은 쉽게 두고, **용액의 성질(지시약 색 변화)을 알아야** 길을 고를 수 있게 한 코스. 약 140m.

| 구간 | 방식 | 알아야 하는 것 |
|---|---|---|
| 실험실 입구 | 2m 틈 세 번 (보통 점프) | — |
| 페놀프탈레인 문 | 예측 문: 붉게 변한 비커 → 비눗물 / 식초 / 레몬즙 | 페놀프탈레인 용액은 염기성에서 붉게 변한다 |
| 식초 웅덩이 | 빨강·파랑 리트머스 발판 5줄. "식초에 넣은 리트머스 종이와 같은 색"만 버틴다 → 빨강 | 산성 용액에서 리트머스 종이는 붉은색 |
| 비눗물 웅덩이 | 같은 발판, 이번엔 파랑 | 염기성 용액에서 리트머스 종이는 푸른색 |
| 붉은 양배추 문 | 예측 문: 노랗게 변한 비커 → 염기성 / 산성 / 알 수 없어요 | 붉은 양배추 지시약: 산성 붉은 계열, 염기성 푸른·노란 계열 |
| 유리 막대 젓기 | 도는 막대 뛰어넘기 (쉬어 가는 조작 구간) | — |
| 섞으면? 문 | 예측 문: 묽은 염산에 묽은 수산화 나트륨 용액을 계속 넣으면 산성은? | 산성 용액에 염기성 용액을 넣을수록 산성이 약해진다 |

- **틀린 색 발판은 밟는 순간 녹는다**: 점프도 다이브도 못 하고 떨어진다. 짧게 흔들리다 무너지는 숨은 발판과 달리, 빨리 달리거나 연속 점프로 건너뛸 수 없다. 다섯 줄(13.5m)은 점프 + 다이브로 한 번에 넘지 못한다.
- 처음 틀리면 "식초는 산성 용액이에요…" 힌트가 한 번 뜬다.
- 누가 녹인 발판은 모두의 화면에서 같이 녹는다 (친구의 실패가 단서). 2.5초 뒤 제자리로 돌아온다.
- 발판 색 배치와 문 정답 위치는 경기마다 섞인다 (같은 방은 모두 같은 배치). 앞·옆으로만(대각선 없이) 이어지는 안전한 길이 늘 있다: 대각선으로 가면 이웃한 틀린 칸 모서리를 밟을 수 있다.
- 알려진 한계: 색을 보지 않고 가운데 줄로 점프만 계속하면 약 20%는 운으로 건넌다 (한 번 뛰면 두 줄씩 넘어가 두 칸 정도만 밟으므로). 조작 실력이 아니라 운이고, 나머지는 떨어지며 힌트를 본다.
- 시뮬레이션 71/72: 입구 점프, 문 3개 × 시드 5 × 문 3, 안전한 길 따라 건너기(시드 5 × 2구역), 틀린 칸 낙하·힌트, 점프 + 다이브로 한 번에 넘기 막힘, 유리 막대 광장 9/12, 결승 도착. 실패 1개는 위의 운 통과 비율(비눗물 9/40)
- 발판 번호는 0~49라 기존 데이터베이스 규칙(`tiles/{race}/{0~99}`)을 그대로 쓴다.
- 교과 내용: 초등 과학 산과 염기 (지시약, 산성·염기성 용액, 섞을 때의 변화).

### 전기 회로 공장 (`src/levels/circuit.js`)

스위치 발판에 서면 회로가 이어져 전구가 켜지고 문이 열린다. **직렬 문은 친구와 나눠 서야** 열리는 협동 코스. 약 120m.

| 구간 | 방식 | 알게 되는 것 |
|---|---|---|
| 회로 잇기 | 스위치 1개 → 전구가 켜지고 문이 열림 | 회로가 끊기지 않고 이어져야 전구가 켜진다 |
| 직렬 스위치 문 | 스위치 3개가 한 줄로 이어짐 (바닥 전선이 하나로 이어진 모양) → **셋 다** 눌러야 열림 | 직렬: 하나라도 끊기면 전구가 꺼진다 |
| 병렬 스위치 문 | 스위치 3개가 갈래로 따로 이어짐 (전선이 부채꼴) → **하나만** 눌러도 열림 | 병렬: 갈래 하나만 이어져도 전구가 켜진다 |
| 예측 문 1 | 전구 두 개를 더 밝게 켜려면? → 병렬 | 병렬 연결한 전구가 직렬보다 밝다 |
| 예측 문 2 | 하나를 빼도 켜져 있는 연결은? → 병렬 | 병렬은 갈래가 따로다 |

- 발판 위에 누가 있는지는 **각 화면이 모든 학생의 위치로 계산**한다. 데이터베이스에 새로 쓰는 값이 없어 규칙을 바꿀 필요가 없다.
- 스위치는 발에서 떨어진 뒤에도 잠시 이어져 있다: 방에 3명 이상이면 1.5초 (혼자서는 직렬 문을 못 연다 → 협동), 혼자·둘이면 7초 (혼자 연습도 가능).
- 문은 빨리 열리고 **4초에 걸쳐 천천히 닫힌다**. 전구는 회로가 끊기면 바로 꺼지지만, 스위치를 누르고 있던 마지막 학생들도 문까지 올 수 있게 한 것이다 (가장 먼 스위치에서 약 19m).
- 문을 지나가면 그 연결의 원리를 한 번 알려 준다.
- 교과 내용: 초등 과학 전기 회로 (회로 잇기, 직렬·병렬 연결, 전구 밝기).
- 시뮬레이션 48/48: 혼자 직렬 문 통과(7초 안에 세 스위치), 21명 방에서 혼자는 못 엶, 친구 둘 + 나, 스위치 하나 비면 닫힘, 마지막 세 명 통과, 병렬 문 하나로 통과·아무도 없으면 닫힘, 벽 옆으로 돌기 막힘, 예측 문, 결승

### 카메라

카메라와 캐릭터 사이를 벽이 가리면 카메라를 벽 앞으로 당긴다 (움직이지 않는 충돌체만 검사). 예측 문·스위치 문을 지난 직후 높은 벽 때문에 앞이 안 보이던 문제를 막는다.

## 코스 구성: 점프 연구소 시험장 (약 250m, 체크포인트 5곳)

| 구간 | 원작 메커닉 패턴 | 확인할 점 |
|---|---|---|
| 몸풀기 계단 + 점프 패드 | 기본 점프 | 점프 높이·거리 감각 |
| 숨은 발판 (5×8 타일) | P1 숨은 규칙 찾기 | 가짜 발판은 흔들린 뒤 떨어지고, 돌아올 때 약간 어두워진다 (기억 단서) |
| 회전 막대 광장 | 타이밍·회피 | 낮은 막대는 점프로 넘고, 높은 막대 아래에서는 점프하지 않기 |
| 움직이는 발판 | P2 주기·타이밍 | 좌우 발판·오르내리는 피스톤에 실려 가는 느낌 |
| 바람 다리 | P4 환경 힘 이용 | 선풍기 회전 예고 → 강풍 → 멈춤 4초 주기, 난간 옆에서 버티기 |
| 시소 다리 | P3 균형·무게 | 한쪽으로 가면 기울고 미끄러진다 |
| 골인 언덕 | 타이밍 | 좌우로 움직이는 범퍼 피하기 |

탈락은 없다. 떨어지면 마지막 체크포인트로 돌아가고 "떨어짐" 횟수만 기록된다.

## 시험용 주소 옵션

| 주소 | 기능 |
|---|---|
| `?cp=2` | 해당 체크포인트에서 시작 (0 출발, 1 숨은 발판, 2 회전 막대, 3 움직이는 발판, 4 시소 다리) |
| `?reveal` | 숨은 발판의 진짜 길을 노란색으로 표시 |

## 조작감 조정

`src/player.js`의 `TUNING` 값을 바꾸면 된다.

| 값 | 현재 | 의미 |
|---|---|---|
| `maxSpeed` | 7 | 달리기 속도 (m/s) |
| `jumpSpeed` / `gravity` | 9.8 / 26 | 점프 높이 약 1.8m, 체공 약 0.75초 |
| `diveSpeed` | 10 | 다이브 전진 속도 |
| `knockSpeed` / `tumbleTime` | 7 / 0.8 | 장애물에 맞았을 때 밀려나는 속도, 조작 불능 시간 |
| `coyoteTime` / `jumpBufferTime` | 0.1 / 0.12 | 가장자리 늦은 점프·이른 점프 허용 시간 (초보자 배려) |

## iPad 시험 체크리스트

1차 시험 (2026-09-28, 교사 1인, iPad Pro Safari):

- [x] 프레임: 약 78fps (화질 "보통", iPad Pro 120Hz 화면 기준)
- [ ] 학생용 iPad 10세대에서 프레임 측정
- [x] 화면 확대·스크롤 등 Safari 기본 동작이 끼어들지 않음
- [x] 좌절스러운 구간 없음
- [x] 목표 완주 시간 3~5분 적절
- [ ] 조이스틱과 점프 버튼 동시 입력 (PC 헤드리스 브라우저에서만 확인)
- [ ] 카메라 드래그 감도
- [ ] 멀미 여부
- [ ] 학생 시험: 조작 적응 시간, 구간별 낙하 횟수, 재미 반응

## 파일 구조

```
prototype/
├─ index.html      화면 구성, HUD, 시작·완주 화면
├─ style.css
└─ src/
   ├─ main.js      렌더러, 게임 루프(120Hz 고정 스텝), 카메라, HUD
   ├─ player.js    캐릭터 모델·애니메이션·이동·충돌 응답
   ├─ physics.js   회전 박스(OBB) 충돌, 움직이는 발판 운반
   ├─ level.js     코스 전체와 움직이는 장애물
   ├─ input.js     터치 조이스틱·카메라·버튼, 키보드·마우스
   ├─ sfx.js       WebAudio 효과음
   ├─ remote.js    다른 학생 캐릭터 보간·이름표
   └─ net/
      ├─ config.js           Firebase 설정, 선생님 코드
      ├─ room.js             방 상태, 위치 전송, 교사 명령
      ├─ backend-firebase.js Firebase RTDB 연결
      └─ backend-local.js    시험용 모의 백엔드 (?net=local)
```
